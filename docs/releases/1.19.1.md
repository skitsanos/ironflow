# IronFlow 1.19.1

Security maintenance release after v1.19.0. Upgrade existing binaries and
rebuild/redeploy containers; updating source or a moving tag does not repair
an already-running deployment.

## TLS trust stores

- Address the eMudhra intermediate-key compromise with rustls-webpki 0.103.16,
  webpki-roots 1.0.11, webpki-root-certs 1.0.11, and rustls 0.23.46 (IF-151).
- Require Debian bookworm ca-certificates >= 20250419~deb12u2 in both container
  stages and Bun >= 1.4.4 for pinned CI jobs. Existing custom CA files remain
  operator-managed; never disable certificate verification as a workaround.
- Add opt-in CLI acceptance that requires valid HTTPS to succeed and all four
  disclosed compromised-chain probes to fail with certificate errors.
- The previously published v1.19.0 image accepted a compromised chain in an
  actual HTTP workflow reproduction. This establishes exposure, not evidence
  of historical interception. See [security guidance](../SECURITY.md).

## Dependency security and compatibility

- Refresh the AWS SDK and Smithy cohort together, plus Ammonia, noyalib,
  ctutils, and archive dependencies. Use ZIP 9.0.5 and Calamine 0.37.0 to remove
  vulnerable transitive ZIP versions (IF-152).
- Disable optional SigV4a signing to remove the affected crypto-bigint 0.5
  dependency. **S3 Multi-Region Access Points are no longer supported.** Use
  regional buckets or regional access points instead. Regional S3, compatible
  regional endpoints, presigned URLs, S3 Vectors, and the regional S3 artifact
  backend remain available. Regression tests cover regional GET/PUT/HEAD/DELETE
  signing and rejection of unsupported multi-region signing.
- Keep dependency auditing fail-closed with warnings denied and no advisory
  ignores. Refresh compatible Tokio, mlua, rmcp, UUID, libc, Comrak, and JSON
  Schema dependencies.

## Tooling and reliability

- Align local, CI, release, and digest-pinned container builder inputs on Rust
  1.99.1. Keep cargo-chef dependency cooking separate from application builds.
- Allow sufficient hosted-runner time for the lease-reaper regression's
  synchronization watchdog without changing production lease behavior
  (IF-153).
- Correct IF-149's historical implementation commit reference.

## Upgrade checks

- Replace binaries or pull a new image and restart explicitly. Pin a verified
  immutable container digest for deployments; images target linux/amd64.
- Update host trust stores and review administrator-provided CA bundles.
  PostgreSQL sslmode=require encrypts without verifying server identity;
  use verify-full with the appropriate CA for identity protection.
- Check workflows that use S3 Multi-Region Access Points before upgrading.
- Default archives exclude optional PostgreSQL/Redis backends; `-full`
  archives and Docker include both. Neither includes database servers or
  native Pdfium.
- Run the public TLS acceptance from the deployment environment. Local or
  hosted checks do not prove that old binaries, images, or every deployment
  have been replaced, and cannot establish absence of past exploitation.
