# IronFlow 1.23.0

This release fixes six advisories in the SMTP library behind `send_email`
and one in the bundled SQLite, closes the findings of the November 19 code
review, finishes moving IronFlow's own time handling off the unmaintained
`chrono`, and improves Word, PowerPoint and Excel extraction on files saved
by Office for the web. Release publication and deployed-version acceptance
are separate from these source-level release notes.

Several fixes make a node refuse input it used to accept silently, or change
the shape of its output. Read the upgrade notes before deploying over an
existing installation.

## Upgrade Notes

- **HTTP response headers** (IF-250, IF-258). In `{output_key}_headers` of
  `http_request` and its wrappers, a header received several times is now an
  array in receipt order; only one value was kept. A header received once is
  a string as before. A flow that read a repeated header such as
  `set-cookie` as a string must index the array. A value the HTTP client
  cannot read as text, which includes any non-ASCII byte, is
  `{"base64": "..."}` where it was an empty string.
- **`db_query` fails on duplicate column labels** (IF-249). Two result
  columns with the same label, such as `SELECT *` over a join or two
  unaliased expressions, fail the step; the later one used to replace the
  earlier one. Alias the columns. The check runs per row, so such a query
  still returns `[]` while it matches nothing.
- **`date_format` is stricter** (IF-238, IF-257). An `input_format` with an
  incomplete clock (`%F %H`, `%F %p`), or fields that disagree with a `%s`
  timestamp, fails the step instead of returning midnight; a date with no
  time fields is still midnight. The output `timezone` must be a sign, two
  hour digits, a colon and two minute digits (00 to 59): `+5:30`, `+02:0` and
  `+002:00` now fail, and `+01:75` is no longer normalized to another offset.
  `UTC`, `Z` and named zones are unchanged. Dates are held for the years
  -9999 to 9999.
- **`csv_stringify`** fails when formula escaping makes two header cells
  equal, for example the keys `=a` and `'=a` (IF-243).
- **`list_directory`** fails on a name that is not UTF-8, without a partial
  list; it used to list it with replacement characters, and a recursive
  listing then read another directory (IF-242).
- **`mcp_client` `list_tools`** returns one page per call and accepts
  `cursor` (IF-251). An empty `cursor` fails the step before anything is
  sent (IF-261): guard the next-page step with
  `step_if("ctx.<key>_result.nextCursor exists", ...)`. The action timeout
  now includes waiting for the session (IF-252).
- **`html_to_markdown` and `extract_html` Markdown** changes with `htmd` 0.6
  (IF-237). Plain text, limits and refusals do not. `&`, `$` and `~` are
  escaped (`R\&D`), also inside link destinations (`/r?a=1\&b=2`); a flow
  that reads URLs from raw Markdown with a pattern must drop the backslash.
  A link around block content is one line (`[Card Body text](/card)`), a `|`
  in a table cell is `\|`, and a table with no header cells gets an empty
  header row.
- **`extract_word`** lists footnotes and endnotes after the body by default,
  marked `[^1]` and `[^e1]` at their references (IF-225). `notes = false`
  restores the previous text.
- **`extract_xlsx`** returns elapsed-time cells (`[h]:mm:ss`) as ISO-8601
  durations such as `PT37H30M`, where they were dates that dropped whole days
  (IF-227); with `has_header`, such a header cell becomes the key `PT37H30M`
  without literal quotes (IF-244). A date or duration cell no calendar holds,
  such as `-1e300`, is `null` instead of failing the step (IF-233).
- **Markdown documents** (`markdown_to_pdf`, `markdown_to_docx`): `comrak` 1.0
  lets reference links expand to the larger of the input size and 100 KB,
  where 0.59 used the smaller. A document that repeats a reference link with
  a long target can come out longer; the 256 KB input, 20,000 node and
  32 MiB output limits still apply.
- **Schedules in `America/Havana`** fire one hour earlier in UTC, at the same
  wall-clock time, between 1 November 2026 and 14 March 2027: the bundled
  IANA data moves from 2025b to 2026f (IF-231). Every other compared zone,
  and every fire instant and claim key, is unchanged.
- **`ironflow validate`** reports child-flow recursion once, as an error when
  any route through the cycle is unconditional, whatever the declaration
  order (IF-246, IF-260). A flow that passed only because of step order may
  now fail validation.

## Security

- `lettre` 0.11.24 fixes RUSTSEC-2026-0560 to RUSTSEC-2026-0565 in the SMTP
  client and message builder: STARTTLS reply injection, SMTP command
  injection through a bare line break, mail for a quoted local part sent to
  another address, and three denial-of-service cases (IF-235). `send_email`
  with the SMTP provider used that code; the Resend provider did not.
- `sqlx` 0.9.1 bundles SQLite 3.54.1, which fixes RUSTSEC-2026-0459
  (uninitialized page-cache memory through a crafted `-wal` file). The audit
  exception carried since 1.21.0 is retired. With 1.22.0 and earlier, do not
  point `db_query` or `db_exec` at SQLite files an untrusted party can write.
- An artifact already in the store is no longer unlinked when its
  verification cannot finish (a read error, a cancellation, a file that
  changes while it is hashed); only a size or digest mismatch is repaired
  (IF-253).
- A protected value echoed in a response header that is not text is
  redacted when IronFlow records or returns a run (IF-262).
- `chrono` is used only by the adapter that hands wall-clock values to
  `cron`; `chrono-tz` is removed with its audit exception. `chrono` stays in
  the graph through `cron` and `rmcp`, with one reviewed exception
  (RUSTSEC-2026-0543, unmaintained, no vulnerability) to be reviewed again by
  2026-12-17 (IF-231).

## Added

- `extract_word`: footnotes, endnotes, and with `headers_footers = true` the
  header and footer parts, in all three formats; a custom footnote mark is
  reported as `mark` in JSON (IF-225).
- `extract_pptx` reads PowerPoint modern comments with their replies, author,
  date and `status`; when a slide has both formats only the modern part is
  read (IF-226).

## Fixed

- **Office extraction** (IF-225, IF-230). The core properties, main
  document and parts are found through package relationships, so files saved
  by Office for the web return their metadata; core-property fields are
  matched by namespace. `extract_word` Markdown emphasis survives Word's run
  splits.
- **Runs and the API.** Replaying a completed keyed request no longer returns
  409 when `IRONFLOW_MAX_TASK_OUTPUT_BYTES` is small (IF-245). On the SQL
  stores, `ironflow inspect` and `GET /runs/{id}` read a run's header and
  tasks from one snapshot (IF-254).
- **Scheduler.** A restart during the repeated hour of a fall-back day
  recovers an occurrence still inside its grace period (IF-255).
- **Metrics.** `ironflow_task_attempts_total` counts the steps of child
  workflows (IF-256).
- **`llm` on Azure** names the routed deployment in the request body and
  `llm_model` when `model` is not set (IF-248).
- **Validation.** `--strict` accepts `self` inside `function obj:method()`
  (IF-247).
- **`date_format`** writes `%C` before the year 0000 as a number (IF-234).
- **Storage.** `prune_before` compares whole microseconds in every store
  (IF-232).
- **Packaging.** Archives and the container image include IronFlow's own
  `LICENSE`, and a change to a shipped license or notices file publishes a
  new image (IF-240, IF-241).

## Time handling

IronFlow's scheduler, stores, API and `date_format` now use `jiff` instead of
`chrono` (IF-231). Every stored and published timestamp keeps its exact text
and ordering keys, checked by golden tests on all four stores, so replicas on
1.22.0 and 1.23.0 can share a store during a rolling upgrade. Zone data is
compiled in and never read from the host. A hand-edited timestamp outside the
years -9999 to 9999, or with surrounding spaces or a one-digit hour, is
reported as corrupt; SQL rows dated before the year 0000, which earlier
versions wrote but could not read, now load.

Library API: the scheduler and store types (`ScheduleConfig::timezone()`,
`Scheduler::new`, `Scheduler::evaluate`, `DueInstant`, `RunInfo`,
`RunSummary`, `TaskState`, `RunEvent`, `RunCursor`, `RunLease`,
`StateStore::prune_before` and `reconcile_expired_run_leases`) take or return
`jiff` types. `ironflow::util::timestamp` holds the stored forms.

## Dependencies

`lettre` 0.11.24, `sqlx` 0.9.1, `htmd` 0.6.0 with `html5ever` and
`markup5ever_rcdom` 0.40 (one `html5ever` in the graph, seven crates fewer),
`comrak` 1.0, `jiff` 1.0.1 added, `chrono-tz` removed, `zip` 9.8.1 (each
version's archive-reader re-read recorded in IF-218), `rmcp` 3.11.0, `noyalib`
0.0.62, `clap` 4.6.8, `uuid` 1.29.3 and the AWS SDK crates.

With `rmcp` 3.11 a JSON error body from an MCP server is read within the
16 MiB response cap, where 3.10 stopped at 64 KiB; at most 64 KiB of its text
is kept (IF-236).

## Downloads And Compatibility

- Four platforms, each with default and `-full` archives: Linux x86-64
  (static musl), macOS Apple Silicon, macOS Intel and Windows x86-64.
- Default archives use the SQLite store by default and keep JSON selectable;
  `-full` adds PostgreSQL and Redis backends and the embedded CJK font. The
  container image includes all of them. No database servers are bundled.
- Every archive includes IronFlow's `LICENSE` and `THIRD_PARTY_LICENSES.md`;
  `-full` archives and the container image include the fonts' OFL license.
  Verify downloads against the accompanying `checksums-sha256.txt` manifest.
