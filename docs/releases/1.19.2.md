# IronFlow 1.19.2

Maintenance release after v1.19.1, focused on SQLite startup reliability,
Markdown rendering and dependency updates. No new workflow options,
configuration defaults or database schema changes are introduced.

## SQLite startup reliability

- Fix intermittent rejection of the managed SQLite event-sequence index
  during fresh startup. Verify index metadata on one refreshed pooled
  connection instead of combining stale metadata from different connections
  (IF-155).
- Preserve checks for the index's table, uniqueness, partial predicate,
  origin and ordered columns. PostgreSQL verification, pool sizes, timeouts
  and retry policy are unchanged.
- Retain bounded, credential-redacted startup diagnostics and reap failed
  test children. Deterministic stale-schema and invalid-index regressions
  accompany the fix; native Linux stress qualification passed 1,500 complete
  ten-test CLI suites without retries.

## Dependencies and rendering

- Update Comrak to 0.58.0, including its quadratic table-cell rendering fix.
  Cover wide aligned tables with autocompleted cells through IronFlow's
  Markdown node. Comrak default features remain disabled.
- Update ZIP to 9.1.1, including LZMA 0.23.0 and typed-path 0.13.0 from the
  preceding ZIP update. Archive admission, path and cancellation limits
  remain unchanged; unrelated lockfile resolutions are preserved.
- Refresh serde_json to 1.0.154, SHA-2 to 0.11.1, tree-sitter to 0.27.1
  (tree-sitter-language 0.1.9), Redis to 1.8.0, JSON Schema to 0.60.1 and
  lopdf to 0.46.0. Retain the selected PDF features and disabled defaults.
- Keep dependency auditing fail-closed with warnings denied and no advisory
  ignores. Rust remains pinned to 1.99.1 across local, CI, release and
  container builder inputs.

## Regression coverage

- Replace a fragile 50 ms XLSX timing assertion with a corrupt-payload
  negative control proving declared limits are checked before decompression
  (IF-154). Production extraction limits are unchanged.
- Cover order-independent object const/enum and uniqueItems validation,
  including inline and context schemas.
- Check dependency feature policy structurally rather than freezing PDF or
  Markdown dependency version strings in policy assertions.

## Upgrade checks

- Replace binaries or pull the new image and restart explicitly. Pin a
  verified immutable image digest for deployments; images target linux/amd64.
- Retain the v1.19.1 TLS trust-store fixes and review operator-managed CA
  bundles. PostgreSQL sslmode=require encrypts without verifying server
  identity; use verify-full with the appropriate CA for identity protection.
- SigV4a remains disabled: S3 Multi-Region Access Points are unsupported.
  Regional S3, compatible regional endpoints and S3 Vectors remain available.
- Default archives exclude optional PostgreSQL/Redis backends; `-full`
  archives and Docker include both. Neither includes database servers or
  native Pdfium.
- Local and hosted acceptance do not prove that an existing deployment has
  been replaced. See the [security guidance](../SECURITY.md) and
  [v1.19.1 upgrade notes](1.19.1.md).
