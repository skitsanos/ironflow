# IF-207 — Follow-ups recorded while fixing IF-173 to IF-206

## Evidence and boundary

Recorded on 2026-11-12 while fixing IF-173 to IF-206, and items (n) to (q)
while fixing IF-178, IF-181 and IF-185. Each item says how it was
established. None was re-verified for this page.

Measured by the fixing session:

- (a) HTML parsing is quadratic in nesting depth: about 16 s for 100,000
  nested `<div>` in an optimized build. The Markdown paths now stop early
  (IF-174); `extract_html` with `format = "text"` is uncapped and still slow,
  though it observes cancellation.
- (b) `html_to_markdown` output is not charged against an output limit. At
  the 128-level cap, wide content in nested block quotes grew about 63 times
  (323 KB in, 20 MB out).
- (c) `topological_phases` in `src/engine/recovery.rs` is quadratic: a
  10,000-step dependency chain took 10 s to validate, unoptimized (IF-175).
- (d) Scrubbing a diagnostic twice over-redacts. A `key: value` ends at a
  line break, the scrubber turns the break into a space, and the second pass
  (node, then engine) takes the following lines as the value. On one line, a
  `Header: value` credential also removes ordinary words up to the next
  comma. Over-redaction only (IF-177).
- (e) Named weekday ranges across the week boundary (`Sat-Sun`, `Fri-Mon`)
  are rejected at startup while `6-7` is accepted (IF-180, documented).
- (f) A cron value outside its field (`61 * * * *`), a backwards range and a
  bad step are rejected without naming the field (IF-206, message only).
- (n) `zip_create` stores every archive entry with mode `0600`, whatever the
  source file's mode (IF-185).
- (o) Parent directories that file nodes create get `0755` masked by the
  umask, not `0777` masked by it (IF-185).

Decision needed:

- (g) A sender who controls a forwarded header can still blank a string of
  eight or more bytes that a later step outputs (IF-176, IF-011). Closing it
  means choosing record-only scrubbing or failing the step.
- (h) `mcp_client` relies on `rmcp`'s fixed 16 MiB and 64 KiB response caps.
  There is no IronFlow limit, and a reply of up to 16 MiB enters workflow
  context (IF-173).
- (i) The `calamine` 0.38 style-table growth found in IF-173 has not been
  reported upstream.
- (p) `lopdf` caps its ToUnicode reverse map on `main` but, by reading, still
  walks a range whose destination is a short array; not reported upstream
  (IF-178).

By reading only:

- (j) Single-page `pdf_split` saves each page with a plain create: it follows
  a symlinked leaf and truncates in place
  (`src/nodes/image/pdf_merge_split/split.rs`, documented as the legacy mode).
- (k) The `cache` file backend writes entries with `std::fs::write`
  (`src/nodes/utility/cache.rs`), so a concurrent reader can see a partial
  entry.
- (l) The diagnostic scrubber does not match a Lua bracket key
  (`["password"] = "x"`) or `key => value`.
- (m) The portable (non-Unix) rooted writer, including the
  `RootedDir::existing` added for IF-179, is not compiled in local validation.
- (q) A run record that cannot be decoded is skipped by reconciliation and
  can be deleted, but `inspect` still fails on it, the unbounded
  `StateStore::list_runs` fails on one, and a damaged lease file or Redis
  index key still fails a reconciliation pass (IF-181).

Boundary: the `0600` output mode that IF-179 extended to the image and
`transcribe` nodes was resolved in IF-185, the SQLite audit exception carries
its own exit criterion in `.cargo/audit.toml`, and the Renovate and notices
conflict was resolved in IF-208.
