# IF-133 — `extract_html` markdown mode leaks head, style and script content

## Required outcome and acceptance

- `format = "markdown"` drops `<head>` content (`<title>`, `<style>`, `<script>`,
  `<noscript>`) and non-content elements before converting, matching what
  `format = "text"` already removes.
- Headings, emphasis, lists and tables keep their Markdown rendering; the
  document's own text is not escaped (`#` in prose must not become `\#`).
- Test with a page whose head carries a title, a style block and a script, plus
  body content with a heading, a list and a table: neither mode contains the CSS
  or the JavaScript, and markdown mode contains the heading markers.

## Evidence and cause

Found on 2026-09-14 while building the document-ingestion flows of the HARMOny
`ironflow-hooks` service (IronFlow 1.18.1-dev.4).

[Source: extract/html.rs:66](../../src/nodes/extract/html.rs).

`"markdown"` hands the raw document to `html2md::parse_html`, while `"text"`
first runs `ammonia::clean` and strips. For

```html
<html><head><title>T</title><style>body{color:red}</style><script>var x=1;</script></head>
<body><h1>Heading One</h1><p>First paragraph with <b>bold</b>.</p>…</body></html>
```

markdown mode returns `Tbody{color:red}var x=1;\n\nHeading One\n==========\n…` —
the title, the CSS and the script concatenated ahead of the content. A page
saved by macOS `textutil` (a `<style>` block with `p.p1 {margin: …}` rules)
came back with 165 characters of CSS as its first paragraph. Text mode returns
`T\n\nHeading One\n==========\n…` (title still present, CSS and script gone) but
escapes literal `#` in the source text as `\#`.

Consumers indexing web pages for retrieval get style sheets embedded, so the
ingestion flows use `format = "text"` and accept the escaping.
