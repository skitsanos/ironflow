# IF-133 — `extract_html` markdown mode leaks head, style and script content

## Required outcome and acceptance

- `format = "markdown"` drops `<head>` content (`<title>`, `<style>`, `<script>`,
  `<noscript>`) and non-content elements before converting, matching what
  `format = "text"` already removes.
- Headings, emphasis, lists and tables keep their Markdown rendering; the
  document's own text is not escaped (`#` in prose must not become `\#`).
- Test with a page whose head carries a title, a style block and a script, plus
  body content with a heading, a list and a table: neither mode contains the CSS
  or the JavaScript, and markdown mode contains the heading markers.

## Evidence and cause

Found on 2026-09-14 while building the document-ingestion flows of the HARMOny
`ironflow-hooks` service (IronFlow 1.18.1-dev.4).

[Source: extract/html.rs:66](../../src/nodes/extract/html.rs).

`"markdown"` hands the raw document to `html2md::parse_html`, while `"text"`
first runs `ammonia::clean` and strips. For

```html
<html><head><title>T</title><style>body{color:red}</style><script>var x=1;</script></head>
<body><h1>Heading One</h1><p>First paragraph with <b>bold</b>.</p>…</body></html>
```

markdown mode returns `Tbody{color:red}var x=1;\n\nHeading One\n==========\n…` —
the title, the CSS and the script concatenated ahead of the content. A page
saved by macOS `textutil` (a `<style>` block with `p.p1 {margin: …}` rules)
came back with 165 characters of CSS as its first paragraph. Text mode returns
`T\n\nHeading One\n==========\n…` (title still present, CSS and script gone) but
escapes literal `#` in the source text as `\#`.

Consumers indexing web pages for retrieval get style sheets embedded, so the
ingestion flows use `format = "text"` and accept the escaping.

## Outcome and validation

- HTML content extraction now uses the existing `html2md` HTML parser and its
  public DOM/custom-handler API. A root handler removes `head`, `title`,
  `script`, `style`, `noscript`, and inert `template` subtrees before any
  conversion, including descendants of tables and preformatted blocks. No new
  dependency or regular-expression tag removal is used.
- Markdown conversion keeps headings, emphasis, lists, tables, links, and code.
  Required escapes are retained: a literal paragraph beginning with `#` must not
  become a Markdown heading. Ordinary prose such as `issue #133` remains
  unescaped. The implementation does not blindly remove backslashes.
- Plain-text mode reads decoded text directly from the filtered tree, preserving
  literal punctuation without Markdown markers. Blocks/line breaks and table
  cell boundaries remain separated; preformatted internal whitespace remains.
  This intentionally replaces the older text mode's converter-produced markers.
- Original-input metadata extraction remains separate, including the title.
  The tracked blocking worker, structural/input/output budgets, and cancellation
  checkpoints remain in use. Filtering and text traversal add cooperative
  checkpoints; third-party parsing/conversion still has non-interruptible spans.
- Focused regressions cover both modes, mixed-case and malformed HTML fragments,
  tag-like attributes and entity-encoded text, nested table/pre content, empty
  input, literal syntax, rendered Markdown semantics, and the runnable Lua example.
  See `tests/test_extract_html_content.rs` and
  `examples/08-extraction/extract_html.lua`.

## Validation

Post-fix checks on 2026-09-14 with Rust 1.98.1:

- `test_extract_html_content`: all 7 tests passed in default and combined-feature
  builds, including strict CLI validation and execution of the HTML example.
- Combined-feature `test_extract_nodes` (23), `test_extract_text_limits` (1),
  `test_extract_execution` (2), `test_extract_config` (1), and
  `test_artifact_nodes` (4) passed, preserving other extractors, limits,
  cancellation/admission lifetime, and verified artifact handling.
- Default and full-feature Clippy, formatting, module-size policy, dependency
  audit, and example-catalog/fixture checks passed for the batch.

The initial implementation test exposed a DOM ownership error causing empty
plain text. Retaining the owning document, not just its `<html>` child, fixed
it; the new nested/sibling lifetime regression now passes. This was an
implementation-stage regression, not evidence about published extraction.

## Follow-up (2026-09-15)

Code review of commit `874b28f` found that the plain-text renderer introduced
here pushed a newline on block entry, block exit, and `<br>` only when the
output did not already end with `\n`, so `</p><p>` and `<br><br>` collapsed to
one newline. The previous converter-based text mode had separated paragraphs
with a blank line. Tracked and resolved as [IF-143](./IF-143.md): paragraph-level
blocks now ensure a blank line on entry and exit, line-level blocks a single
newline, and `<br>` one newline that never widens an existing blank line. The
exact-output assertions in `tests/test_extract_html_content.rs` were updated
accordingly; the filtering, escaping, and metadata contracts above are unchanged.
