# IF-101 — Artifact storage has no remote multi-host lifecycle backend

## Required outcome and acceptance

Artifact descriptors keep large binaries out of workflow context and local
reads verify the opened content, but artifact bytes remain in a local directory
with operator-owned retention. Multi-host replicas therefore require a durable
shared mount, ephemeral-platform restarts can lose retained artifacts, and
unreferenced publications have no bounded garbage-collection path.

Required outcome:

- introduce a narrow artifact-store abstraction that preserves the existing
  content-addressed descriptor contract and keeps the local backend available;
- add an S3-compatible backend whose publication and consumption stream through
  explicit byte ceilings, cancellation checkpoints, SHA-256 verification, and
  atomic visibility rules without materializing Base64 in workflow context;
- define authentication, namespace isolation, retry/idempotency, partial-upload
  cleanup, and read-after-write expectations;
- provide a bounded retention or garbage-collection contract that cannot delete
  artifacts still retained by workflow state, and document the operator-owned
  alternative when automatic collection is disabled;
- cover local/remote parity, corruption, cancellation, retry, concurrent
  publication, replica handoff, and interrupted cleanup; and
- extend the replica acceptance path with an artifact-producing and
  artifact-consuming workflow across separate instances.

This goal does not turn IronFlow into a general object-storage service. A
network filesystem remains supported when operators deliberately provide the
documented durability and process-isolation boundary.

## Outcome and validation

**Resolved on 2026-08-05.** `ArtifactStore` now preserves the canonical
`artifact://sha256/<digest>` descriptor while selecting either the existing
local content-addressed backend or an S3-compatible backend at runtime. The
S3 path streams verified local handles into a single-object PUT with a strict
byte ceiling, cooperative cancellation, three bounded idempotent attempts, and
a post-write HEAD check covering SHA-256 metadata, declared size metadata, and
object length. It returns no descriptor after a failed or cancelled publish.

Remote consumers stream a cache miss into a private local staging file, enforce
descriptor, response, and configured byte ceilings, and verify SHA-256 before
atomically publishing and reopening the consumer handle. A valid remote object
can repair a corrupt regular cache entry, while links and non-regular entries
still fail closed. Bucket, prefix, endpoint, region, path-style addressing, and
the standard AWS credential/workload-identity chain remain deployment
configuration and never enter workflow state.

`ironflow artifacts prune --before <RFC3339> --confirm-offline` provides the
retention boundary. It admits at most 100 old candidates, pages run summaries
100 at a time, loads one retained run at a time, recursively audits context and
task input/output, and deletes only unreferenced digests. The explicit offline
assertion prevents reference-creation races. Each local/S3 deletion is
idempotent, so an interrupted candidate batch can be rerun; cleanup is not a
cross-object transaction and automatic online eviction remains intentionally
disabled.

The Docker replica acceptance gate now provisions disposable MinIO alongside
PostgreSQL. A flow executing on replica A publishes an artifact, replica B
reads its descriptor from shared state, restores through its separate cache,
and writes byte-identical content. The gate retains its restricted arbitrary
UID, read-only root, routing, idempotency, scheduler, SIGTERM, and real SIGKILL
lease-reconciliation checks, and removes its containers and disposable volumes
after completion.

Focused validation passed 15 artifact unit tests; 4 artifact-node tests; 4
write-file safety tests; 3 offline-retention CLI tests; 16 CLI-precedence tests;
3 example-catalog tests; 3 example-contract tests; and the three affected Lua
flow validations. The production two-replica Docker/MinIO/PostgreSQL acceptance
gate passed the cross-cache artifact handoff and all existing lifecycle phases.
`cargo check --all-targets`, Rust formatting, the 464-module size policy, exact
all-target Clippy with warnings denied, `cargo audit --deny warnings`, the Bun
issue/repository policy tests, issue-registry validation, and `git diff --check`
also passed. No live external AWS account, Railway deployment, or OpenShift
deployment was used; MinIO supplies the reproducible S3-compatible runtime
evidence for this issue.
