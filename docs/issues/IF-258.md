# IF-258 — A non-text response header is silently reported as an empty value

## Evidence and boundary

At `ae1f686`, response metadata substituted `""` for values the HTTP client could not read as text. A loopback HTTP 200 response sent `X-Label` with bytes `63 61 66 e9`; `http_get` returned `x-label: ""`, indistinguishable from a genuinely empty field. This affected single fields independently of [IF-250](IF-250.md).

## Required outcome and acceptance

Define a loss-aware policy for non-text fields (for example, a documented byte representation or an explicit diagnostic). Test a single non-text field against an actual empty field and a normal ASCII string. Preserve the ordinary string shape and do not emit potentially sensitive header contents in errors.

## Outcome and validation

Non-text values are returned as objects containing the original bytes in standard Base64, without logging the value. The loopback regression checks that both inline and artifact responses distinguish `{"base64":"Y2Fm6Q=="}`, the literal string `"Y2Fm6Q=="`, and `""`. Repeated fields preserve these types and their receipt order.
