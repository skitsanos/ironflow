# IF-258 — A non-text response header is silently reported as an empty value

## Evidence and boundary

Reviewed 2026-11-19 on local `develop` at `ae1f686`.

`src/nodes/http/request/response.rs:49` calls `value.to_str().unwrap_or("")` when serializing response metadata. The HTTP library can retain bytes that this conversion rejects. A loopback HTTP 200 fixture sent `X-Label` with bytes `63 61 66 e9`; `http_get` reported success with `x-label: ""`. Downstream steps cannot distinguish this from an actual empty header. This occurs with a single field, independently of IF-250.

## Required outcome and acceptance

Define a loss-aware policy for non-text fields (for example, a documented byte representation or an explicit diagnostic). Test a single non-text field against an actual empty field and a normal ASCII string. Preserve the ordinary string shape and do not emit potentially sensitive header contents in errors.
