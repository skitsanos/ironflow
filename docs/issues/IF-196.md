# IF-196 — xml_stringify writes keys as markup; CSV type inference and data_filter equality lose values

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12, reproduced with a local
optimized build.

1. `xml_stringify`. Input `{ ["first name"] = "x",
   ["a/><admin>true</admin><b"] = "v", qty = { ["@unit"] = 5, ["#text"] = 3 },
   ok = { ["@unit"] = "kg", ["#text"] = "3" } }` produces

   ```xml
   <root><a/><admin>true</admin><b>v</a/><admin>true</admin><b><first name>x</first name><ok unit="kg">3</ok><qty/></root>
   ```

   - Keys are written as tag and attribute names without validation
     (`src/nodes/transform/xml/stringify.rs:29-32, 72-96`), so a key from
     untrusted JSON injects elements, and a key with a space yields an
     ill-formed tag. `xml_parse` rejects this node's own output.
   - `@unit = 5` and `#text = 3` are dropped silently: attribute and text
     values are emitted only when they are strings (`:116-128, 157-164`).
2. `csv_parse` with `infer_types = true`. The row
   `NAN,02134,+15551234567,12345678901234567890,inf` becomes `null`, `2134`,
   `15551234567`, `1.2345678901234567e19`, `null`
   (`src/nodes/transform/csv/value.rs:24-45`). Identifiers lose leading
   zeros and signs, large integers lose precision, and the words `nan` and
   `inf` become null.
3. `data_filter`. With items `{qty = 5}`, `{qty = 7}` and `value = 10 / 2`
   (a Lua float, `5.0`), `op = "eq"` returns nothing while `op = "gte"`
   returns both. `eq` and `neq` compare `serde_json::Value` directly, where
   integer 5 and float 5.0 differ (`data_filter.rs:81-82`).

Boundary: all three return success with wrong data. By reading,
`xml_stringify` also emits zero or several root elements for a top-level
array. `docs/nodes/csv_parse.md` describes inference as converting numeric
and boolean fields; it does not warn about identifiers.

## Required outcome and acceptance

- Validate XML names and fail the step on an invalid key; stringify scalar
  attribute and text values; reject array roots or wrap them explicitly.
- Keep CSV fields as strings when they have a leading zero or sign, more
  than 15 significant digits, or a non-finite spelling.
- Compare numbers numerically in `eq` and `neq`.
- Regressions for each input above, including an `xml_stringify` to
  `xml_parse` round trip.
- Update the three node documents.

## Outcome and validation

All three items were reproduced with `ironflow run` on the unfixed tree
(debug build), with the outputs quoted above. The array root was run too:
`{"a", "b"}` gave `<root>a</root><root>b</root>`, which `xml_parse` accepted
and returned as `{"root": "b"}`.

**`xml_stringify`.** `root_tag`, `item_tag`, element keys and attribute keys
must be an XML 1.0 `Name` that is also a `QName`: one name, or
`prefix:local`. `xmlns` and `xmlns:*` are attribute names only and
`xmlns:xmlns` is refused; the `xml:` prefix is accepted. Unprefixed names
that only start with `xml` are accepted, because parsers accept them and
`xml_data` is the default `xml_parse` output key. Prefix declarations are not
checked. An invalid key fails the step with the key escaped and cut to 48
characters. Numbers and booleans in `@attribute` and `#text` are written as
text; `null` there means absent; an object or array fails the step. An array
source fails unless the new `item_tag` wraps each item under the root.

**`csv_parse`.** A field converts only when it is
`[-]digits[.digits][e[+-]digits]` (digits optional on one side of the point)
with at most 15 significant digits and a finite value. `-` is a sign that
still converts; `+` is not.

**`data_filter`.** `eq` and `neq` compare numbers by value, recursively in
arrays and objects; two integers compare exactly. Types stay strict (`"5"`
is not `5`), unlike IF-187 guards, because here both sides are typed JSON
values and not condition text. An item without the field still matches
neither operator.

Results that change:

| Input | Before | After |
|---|---|---|
| key that is not a name | written as markup | step fails |
| `@unit = 5`, `#text = 3`, booleans | dropped | written as text |
| object or array in `@attr` or `#text` | dropped | step fails |
| array source, including one item | 0 to n roots | step fails without `item_tag` |
| control character in a value | written raw | step fails |
| tab, newline in an attribute; CR in text | written raw | character reference |
| CSV `02134`, `+1`, `-0`, 16 or more digits | number | string |
| CSV `nan`, `inf`, `infinity`, `1e999` | `null` | string |
| `eq`/`neq`, integer against equal float | unequal | equal |

Unchanged and covered by tests: the supported mapping (exact output), plain
integers, floats, exponents, `.5`, `5.`, booleans, trimming, empty fields,
string, boolean and large-integer equality.

Same class in sibling transforms, each reproduced with a probe flow and
fixed here: `xml_parse` returned the last of several root elements and now
fails; `data_filter` returned an empty result for an unknown `op` and now
fails; `deduplicate` kept `5` and `5.0` as distinct keys and now treats them
as one. Reproduced and left for separate findings: `yaml_parse` turns `.nan`
and `.inf` into `null` and integers above the 64-bit signed range into
rounded floats; `csv_stringify` writes cells that start with `=`, `+`, `-` or
`@` unchanged, which spreadsheets read as formulas. Checked and sound:
`yaml_stringify` and `csv_stringify` quoting round-trips keys and values with
syntax characters; `json_stringify`, `data_transform`, `select_fields` and
`rename_fields` copy values without reinterpreting them (by reading).

Validation on the fixed tree: `tests/test_transform_fidelity.rs` holds 16
tests; 11 of the first 15 failed before the fix (the other four pin
unchanged behaviour) and all 16 pass after. The original flows now fail the
`xml_stringify` step, return the five CSV fields as strings, and report
`eq=1 neq=1 gte=2`. Default-feature debug runs: library tests 745 passed (1 ignored), `nodes`
296, `engine` 304, `examples` 11, `serial` 191 with one test thread, no
failures; the three changed examples validate and run; formatting, the
module-size check and Clippy with `-D warnings` pass. Not run: the full integration gate,
feature-enabled builds and live services.
