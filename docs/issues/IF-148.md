# IF-148 — Scheduler startup regressions depend on wall-clock margins

## Evidence and boundary

On 2026-09-28, PR #196 at `9948e9b019e3769ed1a3d57d56381dc1e447870c`
failed hosted CI run `36370034014`, job `108764233002`, in
`a_long_running_schedule_does_not_block_the_next_evaluation`.
Startup took 2.30728131 seconds against a 1.5-second assertion while the
workflow used a three-second delay. Twelve other tests in that binary passed.
The PR changes only rmcp and lockfile resolution; this failure does not establish
an MCP regression or prove that startup waited for workflow completion.

The adjacent admission regression uses the same 1.5-second startup assertion
against a two-second task and shares the same timing vulnerability. Its failure
was not observed in that hosted run.

## Required outcome and acceptance

- Use a fixture-local controlled node to signal task entry and hold completion
  until the test explicitly releases it.
- Prove startup returns while the task remains active and the admission permit
  remains held; then release the task and verify successful terminal state and
  restored capacity.
- Keep timeouts only as generous deadlock watchdogs; preserve production runtime
  behavior and public contracts.
- Pass focused default and feature-enabled scheduler regressions, formatting,
  module-size policy, exact all-target Clippy, and the integration gate before
  integration. Record hosted evidence separately from local results.

## Outcome and validation

The candidate overrides only its fixture registry's `delay` node with a
notification-controlled implementation. Both tests wait for actual task entry,
assert lifecycle behavior before release, and then verify successful completion.
Startup/task-entry and permit-drain watchdogs allow 30 seconds.

Local candidate validation on 2026-09-28:

- `cargo test --locked --test test_scheduler_e2e --test test_scheduler_admission`:
  14 passed, including both controlled-task regressions.
- `cargo audit --deny warnings`: passed with all six incoming dependency updates.
- Formatting, the 536-module size policy, issue registry, and all 18 focused
  repository-policy/registry tests passed. One initial policy run timed out at
  five seconds during cold compilation; isolated and normal-timeout reruns passed
  without changing that test.

`scripts/integration_gate.sh` passed on the final local candidate containing
PRs #193–#198 and the IF-148/IF-149 test fixes. It passed formatting, module-size,
repository/issue/skill/hook/workflow policies, exact all-target Clippy, 1,770
default/doc tests, 1,895 feature-enabled tests, the dependency audit, a release
build, all 153 Lua examples, and required disposable PostgreSQL 18.6 / Redis
8.10.2 tests plus TLS-only persistence and certificate/bypass rejection.
Each Rust configuration retained four repository-declared ignored tests.
Both scheduler regression targets passed in default and feature-enabled runs.
The initial full gate stopped at the separate IF-149 regression; the final full
gate passed after that test-only fix. Gate containers and IronFlow artifacts
were cleaned. No production Rust, public workflow contract, node document, or
Lua example changed. This is local validation, not hosted CI for the eventual
integrated commit or deployed evidence.
