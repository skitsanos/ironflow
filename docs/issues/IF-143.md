# IF-143 — `extract_html` text mode collapsed paragraph separation to one newline

## Required outcome and acceptance

- `format = "text"` separates paragraph-level blocks (paragraphs, headings,
  preformatted blocks, block quotes, rules, tables, lists, figures, forms, and
  sectioning elements) with one blank line, as the pre-IF-133 converter-based
  text mode did.
- List items, table rows, `dt`/`dd`, and `div` layout blocks are separated by a
  single newline. `<br>` is one newline and never widens an existing blank line,
  so `<br><br>` yields exactly one blank line and `</p><br><p>` does not produce
  three newlines.
- Test with `<p>a<br><br>b</p><p>c</p>\n<br>\n<p>d</p>`: the text output is
  `a\n\nb\n\nc\n\nd`. `<ul><li>x</li><li>y</li></ul>` yields `x\ny` and
  `<h1>T</h1><p>a</p>` yields `T\n\na`.

## Evidence and cause

Found on 2026-09-15 during code review of commit `874b28f` (the IF-133 batch),
before any release carried it.

[Source: extract/html/content.rs](../../src/nodes/extract/html/content.rs).

The IF-133 plain-text renderer pushed a newline on block entry, block exit, and
`<br>` only when the output did not already end with `\n`, so consecutive
separators collapsed. For

```html
<p>a<br><br>b</p><p>c</p>
<br>
<p>d</p>
```

the previous html2md-based text mode returned `a\n\nb\n\nc\n\nd`; commit
`874b28f` returned `a\nb\nc\nd`. Paragraph boundaries became indistinguishable
from soft line breaks, which degrades chunking and readability for consumers
indexing extracted text. The `plain_text_preserves_literal_punctuation` and
nested/sibling assertions in `tests/test_extract_html_content.rs` had encoded
the collapsed output, so the existing suite did not catch it.

## Outcome and validation

- The renderer distinguishes two block classes. Paragraph-level blocks ensure
  the output ends with a blank line on both entry and exit; line-level blocks
  (`li`, `tr`, `dt`, `dd`, `div`) ensure a single trailing newline; `<br>`
  pushes one newline unless the output already ends with a blank line.
  Separators never apply to empty output; leading and trailing newlines are
  still trimmed.
- Preformatted whitespace, table-cell spacing, image alternative text,
  cooperative checkpoints, and output admission are unchanged. Exit frames are
  now pushed only for block, `td`, and `th` nodes, and the redundant per-node
  output admission was removed; the text and image-alt branches admit before
  growing the output. Because the document root no longer has an exit frame,
  the walk holds its own handle to the root for its whole duration: RcDom's
  node destructor clears descendant child lists, and the first attempt of this
  change returned empty text until the new unit tests exposed that.
- Regressions: `nodes::extract::html::content::tests` (paragraph/double-break
  blank lines, list-item newlines, heading/paragraph blank line, single
  break/rule/table-row spacing) plus the updated exact-output assertions in
  `tests/test_extract_html_content.rs`.
- `docs/nodes/extract_html.md` states the separation rules; [IF-133](./IF-133.md)
  records the follow-up. The runnable example is unchanged; its CLI regression
  checks content, not exact spacing.

## Validation

Post-fix checks on 2026-09-15 (focused, default features):

- `cargo test --lib extract::html`: the four new content unit tests passed.
- `cargo test --test test_extract_html_content`: all 7 tests passed, including
  strict validation and execution of `examples/08-extraction/extract_html.lua`
  through the CLI.
- `cargo fmt --all`, `python3 -B scripts/check_module_size.py`, and
  `cargo check` passed.

This is a pre-release regression of the IF-133 rewrite; no published release
carried the collapsed output. No live-service or deployed validation is claimed.
