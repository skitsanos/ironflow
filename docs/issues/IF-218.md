# IF-218 — File output and archive follow-ups

## Evidence and boundary

Recorded on 2026-11-13 from the fixes for IF-179, IF-185 and IF-190.

- (a) By reading: single-page `pdf_split` saves each page with a plain
  create; it follows a symlinked leaf and truncates in place
  (`src/nodes/image/pdf_merge_split/split.rs`, documented as the legacy mode).
- (b) By reading: the `cache` file backend writes entries with
  `std::fs::write`, so a concurrent reader can see a partial entry.
- (c) Measured: `zip_create` stores every archive entry with mode `0600`,
  whatever the source file's mode.
- (d) Measured: parent directories that file nodes create get `0755` masked
  by the umask, not `0777` masked by it.
- (e) Not compiled locally: the portable (non-Unix) rooted writer, including
  `RootedDir::existing`.
- (f) By reading: `calamine`'s own archive open is not confirmed against the
  admitted ZIP directory; it reads the same handle with the same `zip`
  version as the confirmed opens.
- (g) By reading: the `zip` reader allocates the ZIP64 extensible data sector
  in one buffer sized from the record. The preflight's metadata budget bounds
  it today.

## Required outcome and acceptance

- (a), (b) Use the staged writer. (c) Preserve the source mode, masked.
  (d) Decide the directory mode and document it.
- (e) Add a non-Unix compile check to CI, or a documented manual one.
- (f), (g) Re-read the reader's selection and allocation code on every `zip`
  or `calamine` upgrade; add that to the dependency update checklist.
- Each code fix gets a regression.
