# IF-247 — Strict Lua validation rejects the implicit self parameter of colon methods

## Evidence and boundary

Reviewed 2026-11-19 on local `develop` at `ae1f686`.

`src/lua/analysis/scope.rs:87` opens the function scope and declares the explicit parameter list, but not the implicit receiver of a Lua colon-method declaration. A valid `function t:get() return self.x end` can thus emit `undefined_global` and fail strict validation. Source inspection.

CLI confirmation: strict validation returned exit 1 with `undefined_global` on `self`; executing the unchanged flow returned `result=1`. The control reading the surrounding local table instead of `self` validated successfully.

## Required outcome and acceptance

Verify a locally declared table with a colon method that reads `self` validates without warnings through strict validation. The corresponding dot function without an explicit receiver must still warn, and the implicit receiver must not leak outside the method.

## Outcome and validation

The Lua analyzer declares `self` in the local scope of a colon method. Nested closures can read it. A dot declaration does not introduce a receiver, and leaving the method restores the enclosing scope.

Both `function item:get()` and `function item.get(self)` pass strict validation and return the same value when called as `item:get()`. Reading an otherwise undefined `self` in `function item.get()` or after the method still reports `undefined_global`.
