# IF-107 — Provider redirects can replay credentials and private payloads to another origin

## Required outcome and acceptance

- Constrain redirects in credential-bearing provider clients and suppress sensitive Referer values; a redirect must not replay private payloads or custom credentials to another origin.
- Cover LLM and notification clients and inventory related provider entry points sharing this trust boundary.
- Test same-origin and cross-origin 301/302/307/308 with synthetic credentials and payloads, including a normal successful request. Document redirect behavior.

## Evidence and cause

Fresh review on 2026-09-12, finding R02. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: ai/llm.rs:137](../../src/nodes/ai/llm.rs), [notify/slack.rs:76](../../src/nodes/notify/slack.rs).

The clients use default redirects. A controlled cross-origin 307 replayed an LLM prompt and custom `x-api-key` header to a second loopback server. A separate Slack probe replayed the notification body and included the original token-bearing webhook path in Referer. A redirecting or compromised provider/proxy is sufficient; an untrusted workflow is not required. This does not claim that reqwest forwards standard Authorization headers cross-origin.

Fix and coverage: explicitly constrain redirects for credential-bearing provider clients and disable sensitive referrers. Include same-origin/cross-origin 301/302/307/308 tests. Evidence: the AI evidence bundle and API probe log listed below.

## Outcome and validation

Resolved locally on 2026-09-12. A shared provider client builder now allows at
most ten redirects within the original scheme, host, and effective port, and
disables automatic Referer headers. LLM, embeddings, semantic chunking, Slack,
Resend, and ArangoDB use it; transcription retains its existing policy through
the shared builder. The generic HTTP node's explicit redirect policy, SMTP,
and AWS SDK behavior are unchanged. The seven affected node documents record
the redirect contract and migration to an explicit final provider URL.

The new cross-origin and Referer regressions failed before the change. The
permanent regression matrix now passes for nine provider/auth configurations
across 301/302/307/308: cross-origin destinations receive no requests, while
same-origin redirects preserve the expected method/body semantics and custom
authentication without Referer. Normal success and the ten-hop boundary pass.
Unit coverage checks scheme, host, and effective-port comparisons; the two
existing transcription redirect tests also pass.

Validation: four tests in `test_provider_redirect_security` passed, along with
the shared-policy unit test and both `test_transcribe_redirect_security` tests.
The combined default `cargo test --all-targets` run passed 1,423 tests with
zero failures and two existing manual tests ignored. Formatting, module-size
policy, `cargo clippy --all-targets -- -D warnings`, and
`cargo audit --deny warnings` passed; 34 affected Lua examples validated.
Runtime evidence uses bounded loopback providers with synthetic credentials,
not external provider services or a live deployment.
