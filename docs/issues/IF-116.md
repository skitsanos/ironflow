# IF-116 — Persistence truncation corrupts live child-workflow results

## Required outcome and acceptance

- Separate live child-result transport from inspection-only persisted snapshot truncation.
- Preserve values across subworkflow, repeat, and parallel composition within execution-context budgets even when history snapshots truncate.
- Add a large-string regression comparing inline and child execution, carried repeat state, and persisted inspection output; retain cancellation and ownership semantics.

## Evidence and cause

Fresh review on 2026-09-12, finding R11. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: finalizer.rs:34](../../src/engine/executor/finalizer.rs), [consumer: subworkflow.rs:154](../../src/nodes/composition/subworkflow.rs).

Composition reads finalized, truncated child context. A 3 MiB string became a marker table in the parent and the next repeat iteration while success remained true; an equivalent inline workflow preserved all bytes. The documented inspection-only cap changes execution semantics. Separate live result transport from persisted snapshots. Cover subworkflow, repeat, and parallel variants. Evidence: engine probe bundle.

## Outcome and validation

Resolved on 2026-09-13. Waiting subworkflow, static/dynamic parallel fan-out,
repeat, and tool-dispatch nodes now consume an internal live completion result
instead of reconstructing execution values from bounded `RunInfo.ctx` history.

- Completion carries the full redacted context, flow name, and final status
  only after execution, cooperative worker drain, finalization, and heartbeat
  cleanup. Stalled execution and finalization errors do not deliver a valid
  child result. Business failures retain their existing per-node error policy.
- Child capture is opt-in. Ordinary public run handles keep their run-ID-only
  wait/cancel API and detach-on-drop behavior without retaining a full live
  payload. Internal child waiters retain cancellation-on-parent-drop behavior.
- Final snapshot preparation moves the owned live values, applies the existing
  execution-overlay redaction, and clones only values admitted to inspection.
  Oversized values remain live but become the same truncation markers in
  persisted task output and final context. Persistence caps were not raised.
- Updated all four node documents, architecture, CLI reference, and Lua guide.
  Added a catalogued offline parent/helper pair that checks a full 3 MiB child
  string before the final CLI context displays its inspection marker.

Pre-fix evidence: all four initial `test_child_result_fidelity` regressions
failed against the prior implementation. Subworkflow, parallel, and tool
results returned markers instead of strings; repeat failed when its second
iteration received a marker as carried state. Those regressions now pass.

Post-fix validation on Rust 1.98.1:

- `cargo test --lib engine::executor`: 27 tests passed, including live-result
  ownership, ordinary-handle non-retention, finalization timeout, and redacted
  full results alongside bounded history on Null, JSON, and SQLite stores.
- `cargo test --test test_child_result_fidelity --test test_child_result_cli`:
  six fidelity regressions and two CLI tests passed. Coverage includes inline
  equivalence, flattened/namespaced output, static/dynamic fan-out ordering,
  repeated state, tool result/message/by-ID fidelity, and ignored failures.
  CLI runs verified full parent values at default and 128-byte inspection caps
  and failure under a 1 MiB Lua memory limit.
- Existing `test_subworkflow_node`, `test_parallel_subworkflows_node`,
  `test_repeat_subworkflow_node`, `test_tool_dispatch_node`, and
  `test_nested_workflow_cancellation`: 42 tests passed, including physical
  child-process cleanup and the parent repeat deadline.
- `test_engine`, `test_engine_terminalization`,
  `test_parallel_context_determinism`, `test_webhook_composition`,
  `test_webhook_persistence_boundaries`, `test_api`, `test_api_sse`, and
  `test_api_errors`: 73 tests passed, preserving phase publication, terminal
  state, public detach/cancel behavior, HTTP contracts, and secret boundaries.
- `test_example_catalog` and `test_examples`: four tests passed, including
  loading and validating all 141 Lua examples and catalog/node coverage.
- `cargo fmt --all -- --check`, `python3 -B scripts/check_module_size.py`,
  `cargo clippy --all-targets -- -D warnings`, and `cargo audit --deny warnings`
  passed. Existing module-size exceptions were unchanged. `cargo test --doc`
  passed with no executable doctests.

Boundary: the result is invocation-local, not durable child recovery or a new
global context-memory cap. Existing Lua memory/conversion limits and execution
timeouts still apply; large live values consume memory and may need artifact
references. Public persisted inspection remains intentionally lossy. IF-118's
parallel metadata collisions and IF-119's dynamic literal-input mapping are
separate open issues. Live PostgreSQL/Redis, deployed serve processes, the full
integration gate, and publication were not part of this focused local fix.
