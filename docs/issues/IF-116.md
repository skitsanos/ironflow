# IF-116 — Persistence truncation corrupts live child-workflow results

## Required outcome and acceptance

- Separate live child-result transport from inspection-only persisted snapshot truncation.
- Preserve values across subworkflow, repeat, and parallel composition within execution-context budgets even when history snapshots truncate.
- Add a large-string regression comparing inline and child execution, carried repeat state, and persisted inspection output; retain cancellation and ownership semantics.

## Evidence and cause

Fresh review on 2026-09-12, finding R11. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: finalizer.rs:34](../../src/engine/executor/finalizer.rs), [consumer: subworkflow.rs:154](../../src/nodes/composition/subworkflow.rs).

Composition reads finalized, truncated child context. A 3 MiB string became a marker table in the parent and the next repeat iteration while success remained true; an equivalent inline workflow preserved all bytes. The documented inspection-only cap changes execution semantics. Separate live result transport from persisted snapshots. Cover subworkflow, repeat, and parallel variants. Evidence: engine probe bundle.

## Progress

Open. Implementation and regression validation are pending.
