# IF-170 — Documentation and repository hygiene drift

## Evidence and boundary

Audit of `develop` at 1.20.1-dev.6 on 2026-10-28.

- `docs/LUA_FLOW_GUIDE.md` says "103 built-in nodes" while `README.md`,
  `docs/ARCHITECTURE.md`, `docs/NODE_REFERENCE.md`,
  `docs/IMPLEMENTATION_PLAN.md` and `ironflow nodes` give 105. IF-024 resolved
  earlier drift but no test guards the count.
- `docs/.DS_Store` is tracked although `.gitignore` lists `.DS_Store`.
- `Taskfile.yaml` is tracked and also matched by `.gitignore`. Its
  `docker-build-multi` and `docker-publish` tasks push
  `skitsanos/ironflow:latest` and a version tag from a local build, which can
  overwrite the provenance- and SBOM-attested images published by
  `container.yml` and `container-release.yml`.
- 30 comments in `src/` reference `IF-NNN` identifiers in place of stating the
  invariant they protect.
- `docs/ARCHITECTURE.md` (73 KB) and `docs/CLI_REFERENCE.md` (74 KB) repeat
  storage and limit contracts that also live in node documents; this
  duplication is where count drift comes from.

Boundary: none of these affect runtime behavior. They are maintenance and
trust signals for a repository that otherwise documents contracts carefully.

## Required outcome and acceptance

- Correct the count and add a parity test (or extend
  `tests/test_example_catalog.rs`) that compares every documented node count
  with `NodeRegistry::with_builtins().list().len()`.
- Remove `docs/.DS_Store` from the index. Decide the Taskfile's status (track
  and un-ignore, or remove it) and make its publish tasks refuse `latest` and
  version tags, or document them as local-only.
- Replace `IF-NNN` comment references with the invariant text, keeping the ID
  only where the issue page adds evidence the comment cannot.
- Resolution evidence: parity test green and `git ls-files` free of ignored
  paths.

## Outcome and validation

Resolved on 2026-10-28 on branch `fix/if-170-hygiene` at 1.20.1-dev.8.

Outcome:

- `tests/test_example_catalog.rs::documented_node_counts_match_the_registry`
  reads `README.md`, `docs/ARCHITECTURE.md`, `docs/NODE_REFERENCE.md`,
  `docs/IMPLEMENTATION_PLAN.md` and `docs/LUA_FLOW_GUIDE.md`, takes the integer
  before every "built-in nodes" phrase and compares it with
  `NodeRegistry::with_builtins().list().len()`, the default-feature registry
  the documents describe; it also requires at least five mentions so a reworded
  document cannot silently drop out. `docs/LUA_FLOW_GUIDE.md` now says 105.
- `docs/.DS_Store` is removed from the index; `.gitignore` already listed it.
- The Taskfile is not tracked: `git ls-files -ci --exclude-standard` lists only
  `docs/.DS_Store`, so the evidence above misread an ignored local file as a
  tracked one. Its publish tasks therefore cannot overwrite the attested images
  from the repository; the item is closed as a corrected finding.
- The 29 production comments that cite an `IF-NNN` identifier each state the
  invariant they protect beside the identifier (for example "Only bytecode this
  process compiled verifies (IF-035)"), and the identifier points at the page
  that holds the evidence, which is the acceptance's own exception. They stay
  as they are; no comment cites an identifier alone.
- Documentation duplication between `docs/ARCHITECTURE.md`,
  `docs/CLI_REFERENCE.md` and the node documents remains as noted in the
  evidence; the parity test guards the number that drifted.

Contract boundary: documentation only, plus one test. The node count is the
default-feature registry; a build without `pdf-render` has 103 nodes and is
documented as such on the node pages ([IF-164](IF-164.md)).

Validation on 2026-10-28: with the stale `103` restored the new test fails
naming `docs/LUA_FLOW_GUIDE.md:411`; with the fix it passes, and the
`examples` binary passes all 11 tests. `git ls-files -ci --exclude-standard`
is empty after the removal. `cargo fmt --all -- --check` and the issue
registry check pass.
