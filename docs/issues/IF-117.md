# IF-117 — Missing nested tool-input paths fall back to the entire root object

## Required outcome and acceptance

- Resolve the complete requested nested path without falling back to its root object.
- Specify and document missing-path behavior as an error or explicit missing value, never a wider data selection.
- Test present/missing nested fields, literal values, and a private sibling field that must not enter tool messages.

## Evidence and cause

Fresh review on 2026-09-12, finding R12. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: tool_dispatch/call_context.rs:85](../../src/nodes/composition/tool_dispatch/call_context.rs).

Mapping `ctx.user.id` when `id` is absent returns the full `user` object. A synthetic unrelated private field then appeared in tool-result messages. Missing paths should fail or have an explicit missing-value contract, never broaden selection silently. Evidence: engine tool-context probe.

## Outcome and validation

Resolved on 2026-09-13. The context selector now distinguishes an explicit root
reference from a nested path. An explicit `ctx.user` reference may return the
complete `user` value; `ctx.user.id` must resolve the entire path or return JSON null. Missing
fields, incorrect intermediate types, and out-of-range array indices no longer
fall back to the root. Empty roots and path segments, including a trailing dot,
also resolve to null for `ctx.*`, `arguments.*`, and `call.*` selectors.

The change is confined to the existing shared tool-input resolver. Recursively
mapped arrays/objects, literal values, zero-based dotted array indices, and
explicit whole-object or legacy bare-key references retain their behavior.
Values selected from context are copied as-is, not interpreted a second time.

### Contract boundary

- Missing selectors produce JSON null, represented by `json_null` in Lua. They
  do not automatically fail dispatch. Handlers can reject required missing values;
  the existing `fail_fast` and `ignore` policies still apply to handler failures.
- Parent context is not implicitly copied to the child, but intentionally
  selected objects are not redacted. The default child metadata and dispatch
  result entries still include tool arguments. This is a selection-correctness
  fix, not an authorization mechanism or general secret filter.
- Parent context/history is unchanged. The child-context result fallback removes
  only top-level underscore-prefixed keys, not nested private fields. Tests cover
  both explicit results and this fallback without claiming wider redaction.
- `docs/nodes/tool_dispatch.md` documents these boundaries. The new offline
  `tool_dispatch_input_projection.lua` and its child handler demonstrate nested
  selection and assert that a synthetic private sibling never enters tool output.
  Both examples are listed in the README and execution catalog.

### Regression evidence

Before the fix, the new real-subworkflow regression failed: an absent `user.id`,
absent deeper field, or traversal through a scalar selected the complete `user`
object. The synthetic `private-sibling-sentinel` appeared in result entries,
serialized message content, and the call-ID lookup while dispatch reported success.
The same regression passes after the fix.
