# IF-200 — artifacts prune cannot get past a first page of still-referenced digests

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12, by reading. Not executed.

- `local_candidates` (`src/artifacts/retention.rs:46-79`) walks the digest
  directory and returns the first `limit` files older than the cutoff, in
  directory order, then stops. The remote variant
  (`src/artifacts/remote_retention.rs:11-67`) does the same in key order.
- The CLI (`src/cli/commands/artifacts.rs:27-46`) computes which candidates
  retained runs still reference, skips those, deletes the rest, prints
  `inspected N, retained N, deleted N`, and exits. `--limit` is capped at
  100.
- There is no cursor and no "skip retained and keep scanning". Retained
  candidates do not leave the listing, so they are returned first on the
  next invocation as well.

Trigger: a store where at least `limit` old artifacts are still referenced
by retained runs, with unreferenced old artifacts later in listing order.
Every invocation then reports `inspected 100, retained 100, deleted 0`, and
the orphans behind them are never reached. Old artifacts referenced by
long-retained runs are the normal case for an active deployment, so storage
grows without bound while pruning appears to run.

Secondary, by reading: `collect_references`
(`src/cli/commands/artifacts.rs:105-106`) aborts the whole prune if any
retained run holds a string that starts with `artifact://` but is not a
canonical URI.

Boundary: the existing resume test
(`tests/test_artifact_retention.rs`) covers orphans only, which leave the
listing when deleted. Directory order was assumed stable for an unchanged
directory; S3 key order is deterministic. Pruning is offline-only by
contract (IF-101), so no race is claimed here.

## Required outcome and acceptance

- Keep scanning until `limit` unreferenced candidates are found or the
  listing ends, or accept and print a continuation marker so repeated
  invocations make progress.
- Skip and report non-canonical `artifact://` strings instead of aborting.
- Regressions for local and remote backends: more than `limit` retained old
  digests followed by orphans, asserting the orphans are deleted within a
  bounded number of invocations.
- Document the progress guarantee in the `artifacts prune` section of
  `docs/CLI_REFERENCE.md`.
