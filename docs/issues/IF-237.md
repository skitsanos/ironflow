# IF-237 — htmd 0.6 no longer accepts IronFlow's depth-capped HTML tree

## Evidence and boundary

Found on 2026-11-18 while integrating a Renovate update of `htmd` from 0.5.6
to 0.6.0. Reproduced: with `htmd` 0.6.0, `html5ever` 0.40 and
`markup5ever_rcdom` 0.40 the crate does not compile. The errors are in
`src/nodes/extract/html/markdown.rs` and `content.rs`:
`HtmlToMarkdown::tree_to_markdown` is private, and element handlers take
`&Element` and a different return type.

Why it matters: since IF-174 IronFlow parses HTML itself with `html5ever`
into an `rcdom` tree, so nesting is capped while parsing, and hands that tree
to `htmd` through `tree_to_markdown`. The handlers for block quotes, list
items, ordered lists, tables and cells also meter Markdown output against
`IRONFLOW_MAX_EXTRACT_OUTPUT_BYTES`. By reading the 0.6.0 source: `htmd` now
builds its own tree type (`html_to_tree`) and no longer depends on
`markup5ever_rcdom`; whether a caller can still supply a pre-built, bounded
tree was not established.

`htmd`, `html5ever` and `markup5ever_rcdom` stay on the 0.5.6 and 0.38 line,
which the manifest keeps together on purpose, and `renovate.json` excludes
exactly `htmd` 0.6.0. `ammonia` already resolves `html5ever` 0.40, so two
`html5ever` versions remain in the graph until this is done.

## Required outcome and acceptance

- Move `html_to_markdown` and `extract_html` to `htmd` 0.6 and one
  `html5ever` release line without losing the bounds: nesting capped during
  parsing (`IRONFLOW_MAX_HTML_TEXT_DEPTH` and the IF-174 tests), the Markdown
  output meter, and cancellation.
- If `htmd` 0.6 cannot take a bounded tree, either bound the input before
  `htmd` parses it, with regressions that show the same inputs are refused,
  or replace the conversion.
- Markdown output for the existing fixtures stays the same, or each
  difference is listed.
- Remove the Renovate exclusion.

## Outcome and validation

Design (a) of the three considered: IronFlow keeps its own depth-capped
parse and `htmd` 0.6 converts that tree. Read in the 0.6.0 source: the
`rcdom` feature implements `ConvertInput` for `&Rc<markup5ever_rcdom::Node>`,
so `HtmlToMarkdown::convert` takes the tree `tree.rs` builds and `htmd` never
parses. `htmd` has no depth or size option. The manifest enables `rcdom` and
turns the default `ego-tree` backend off. A bounded pre-pass and an in-tree
renderer were therefore not needed.

- Bounds: `tree.rs` is unchanged apart from a test, so the nesting cap, the
  4 KiB chunks and the cancellation checks are the same code. Handlers take
  `&Element`; the meter reads parents and children through `htmd`'s node type
  and identifies a table row by that node's hash. Its constants follow 0.6: a
  cell `|` grows by one byte, an empty column is one byte wide, and a table
  may gain an empty header row.
- One `html5ever` (0.40.1) and `markup5ever_rcdom` 0.40.1; `cargo tree -d`
  lists neither. Seven crates left the lockfile. The Renovate exclusion and
  its policy test are removed.
- `tests/golden/html_conversion.txt` was recorded with 0.5.6 before the
  update: two fixtures and 93 inputs, each through `html_to_markdown` and
  both `extract_html` formats. Plain text and every refusal are identical,
  including the parser-recovery shapes at the cap, so `html5ever` 0.40 built
  the same trees. Markdown differs in 17 cases, all from `htmd`:
  - Escaping: `&`, `$` and `~` in text are always written `\&`, `\$`, `\~`;
    `&` also in link destinations and titles (`/r?a=1\&b=2`). `1)` and `+` at
    the start of text, a `#` after a heading marker or ending a heading, and
    `[`/`]` in image alt text are escaped. A line ending in alt text is
    `&#10;`.
  - Links: an empty `href` is `(<>)`. A heading inside a link no longer
    writes `##`. Spaces at the edges of link text stay inside the brackets.
  - An empty heading is `###` without the trailing space.
  - Tables: a caption is followed by a blank line. A cell `|` is `\|` where
    it was `&#124;`. A table with a `<thead>` but no header cells gets an
    empty header row and a delimiter row, where only body rows were written.
    An empty column is one character wide. A `<th>` row after a body row is
    no longer taken as the header: its `<td>` cells are kept and its `<th>`
    cells dropped, where it was the reverse.
- One IronFlow handler was added (`markdown_links.rs`). `htmd` 0.6 writes a
  line ending inside link text as `&#10;`, so an anchor around blocks became
  `[&#10;&#10;Card&#10;&#10;](/c)`. Link text is joined with spaces instead:
  `[Card Body text](/c)`, where 0.5.6 wrote `[### Card`, a blank line and
  `Body text](/c)`. A `<br>` in a link becomes a space. Only the outermost
  anchor is rewritten, so nested anchors cost at most a second walk.
- Not changed, read in both versions: a `<th>` in a body row is dropped from
  a pipe table.

Follow-up: `htmd` 0.6.1 emits literal line endings in preformatted anchor
labels. IronFlow keeps the existing encoded output there and still joins
ordinary link labels with spaces. The preformatted-link regression covers the
compatibility path.

Validation on 2026-11-19: formatting, module size, Clippy (default and
`postgres,redis`), every test target through `scripts/test_rust_targets.ts`,
the policy tests, `cargo audit`, the license gate and regenerated notices,
and `extract_html.lua` and `markdown_conversion.lua` validated and run
(`research_source_snapshot.lua` validated only; it fetches a page). No live
service or deployed build was used.
