# IF-232 — prune_before compares a different precision in the JSON and Redis stores than in SQL

## Evidence and boundary

Found on 2026-11-18 while recording the stored timestamp forms for IF-231
stage 3. `StateStore::prune_before(cutoff)` deletes terminal runs that
started before a cutoff. The SQL store compared `started_micros`, the floor
of the start time in microseconds, with the floor of the cutoff. The JSON
and Redis stores, through the shared page walk, and the trait's default
implementation compared the full nanosecond values.

A cutoff later in a run's own microsecond therefore deleted the run in the
JSON and Redis stores and kept it in SQLite and PostgreSQL. Run listing,
cursors and every catalog are defined at microsecond precision, so the SQL
behaviour is the documented one.

Reproduced for the JSON store before the fix: with a run started at
`2026-01-02T03:04:05.000000500Z` and a cutoff 400 ns later, `prune_before`
removed it. The Redis and default paths were read, not run, before the fix;
they shared the same comparison.

Exposure: low. Nothing in IronFlow calls `prune_before`; it is reachable only
through the library API, and the stores differ only when the cutoff and a
start time share a microsecond.

## Outcome and validation

`storage::run_listing::started_before` floors both values to microseconds,
and the shared page walk and the default implementation use it. A run without
a start time is still kept. Behaviour change, JSON and Redis stores only: a
run that started in the cutoff's own microsecond is now kept.

Regression: `assert_prune_cutoff_is_whole_microseconds` in
`tests/test_timestamp_stores.rs` runs the same two runs and two cutoffs
against the JSON store, SQLite and PostgreSQL, and
`tests/test_redis_timestamp_forms.rs` does the same against Redis. The JSON
case failed before the fix (two runs removed instead of one). The default
implementation has no store that reaches it with a chosen start time and is
covered by reading only.

Validation: `cargo fmt --check`; the module-size gate; Clippy on all targets
with default and `postgres,redis` features; library tests; the `storage`,
`storage_postgres`, `storage_redis`, `api` and `cli` binaries with
`postgres,redis,cjk-fonts` against disposable PostgreSQL and Redis
containers; the policy tests. The other test targets were not run again for
this change.
