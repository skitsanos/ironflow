# IF-120 — Validation rejects a valid callback reused on two steps

## Required outcome and acceptance

- Allow one Lua source function to be registered as the handler for multiple steps without losing source association.
- Retain undefined-global, captured-local, and genuine ambiguity diagnostics.
- Add validate/run parity coverage for reused callbacks, distinct callbacks, and invalid handlers.

## Evidence and cause

Fresh review on 2026-09-12, finding R15. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: lua/analysis.rs:72](../../src/lua/analysis.rs).

Source-handler association is claimed only once. The same Lua function used for two steps runs successfully, but `validate` fails to map the second registration. Support repeated references to the same source function and test validate/run parity. Evidence: engine reusable-handler probe.

## Progress

Open. Implementation and regression validation are pending.
