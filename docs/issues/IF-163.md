# IF-163 — Default JSON state store re-implements database concerns over the filesystem

## Evidence and boundary

Audit of `develop` at 1.20.1-dev.6 on 2026-10-28.

- `src/storage/json_store.rs` plus `src/storage/json_store/**` total 6,647
  lines: 4,152 production lines and about 2,500 lines of in-tree tests. The
  SQL store is 1,979 lines and the Redis store 1,891.
- Components: a crash-safe fixed-record binary catalog
  (`.ironflow-run-catalog-v1.bin`, `.state`, `.lock`) with seven sections, a
  bounded delta overlay (K <= 128) and O(N) compaction
  (`catalog/{format,header,page,page/merge,delta,state,state/token,transaction,transaction/persistence}`),
  schedule claims with a cleanup cadence, a revision and digest codec,
  no-follow secure directory operations (`fs.rs`), lease files, a lease lock,
  lease reconciliation, platform-specific code and temp files. `codec.rs` and
  `fs.rs` hold two of the nine reviewed module-size exceptions.
- History: IF-014, IF-021, IF-029, IF-033 and IF-051 each added a layer to keep
  the filesystem store safe and paged.
- `sqlx` with the `sqlite` feature is a non-optional dependency and `sqlite`
  is a supported state and event backend in `src/cli/store_factory.rs`, giving
  atomic transactions, indexes, keyset pagination and locking natively. The
  default backend is `json` (`store_factory.rs`), the Dockerfile sets
  `IRONFLOW_STORE_DIR=/data/runs`, and `scripts/test_container_store.ts`
  smoke-tests the JSON store.

Boundary: the JSON store is correct as far as its tests show. The finding is
cost and risk concentration in the default path, and the mismatch with the
"lightweight" positioning. Multi-replica deployments already require a shared
durable backend per `docs/REPLICA_DEPLOYMENT.md`.

## Required outcome and acceptance

- Decide and document the default backend. Recommended: SQLite as the default
  for single-node deployments, with JSON retained as an explicitly selected
  simple store.
- If SQLite becomes the default: update `store_factory.rs`, the Dockerfile
  environment, `docs/GETTING_STARTED.md`, `docs/CLI_REFERENCE.md`,
  `docs/ARCHITECTURE.md` (JSON store filesystem boundary section),
  `docs/REPLICA_DEPLOYMENT.md`, `README.md`, affected examples and
  `scripts/test_container_store.ts`; provide a documented path for existing
  JSON store directories (continue via `IRONFLOW_STORE=json`, or an import
  command).
- Freeze the catalog: no new JSON catalog features. Either keep it with a
  documented maintenance-only status, or remove the paged index in favor of
  per-run files with documented O(N) listing for the simple store while still
  honoring `list_run_summaries_page`.
- Resolution evidence: store contract tests green for both backends, container
  smoke green with the new default, and module-size exceptions for `codec.rs`
  and `fs.rs` removed if that code is removed.

## Outcome and validation

Resolved on 2026-10-29 on the local integration stack (not yet pushed).
Decision taken by the maintainer: SQLite is the default for single-node
deployments; the JSON store stays as an explicitly selected, maintenance-only
backend. Nothing is removed, so the `codec.rs` and `fs.rs` exceptions remain.

### Default backend

- `store_factory.rs` resolves `IRONFLOW_STORE` and `store_backend` to the new
  `DEFAULT_STATE_BACKEND = "sqlite"`; `replica_config.rs` uses the same
  constant, so replica-mode validation and store creation agree. The event
  backend default stays `memory`.
- With no URL configured, the default store is `ironflow.sqlite` under the
  store directory (`data/runs` locally, `/data/runs` in the container).
  `sql_config::resolve_url` now creates that directory owner-only (`0700`) on
  Unix and refuses a symbolic link in its place, matching the JSON store's
  root rule, because run records carry workflow context.
- Migration path: an existing JSON store directory keeps working unchanged
  with `IRONFLOW_STORE=json`. There is no automatic import between backends;
  the CLI reference says so, and a deployment that switches backends starts
  with an empty run history unless it keeps the old selection.
- The container image needs no new environment: it leaves `/data/runs` absent
  so the runtime UID creates it, and `scripts/test_container_store.ts` now
  also asserts that `/data/runs` holds `ironflow.sqlite` and no JSON records
  under both UIDs before and after container removal.

### Frozen JSON store

- `src/storage/json_store.rs` carries a module doc declaring it
  maintenance-only: defects are fixed and the `StateStore` contract is kept,
  but no catalog, paging or layout features are added. `AGENTS.md` states the
  same rule, and `docs/ARCHITECTURE.md` introduces the JSON filesystem
  boundary as preserved for existing directories rather than extended.

### Surfaces updated

`README.md`, `docs/CLI_REFERENCE.md` (backend list, both environment tables,
the SQLite default-path paragraph), `docs/GETTING_STARTED.md`,
`docs/ARCHITECTURE.md`, `docs/REPLICA_DEPLOYMENT.md`, the Dockerfile comment,
`examples/21-schedules/ironflow.yaml` (no longer selects `json`) with its
`examples/README.md` entry, and `scripts/test_container_store.ts`.

### Regressions

- `tests/test_sql_backend_cli.rs::default_backend_is_sqlite_under_a_private_store_directory`:
  a run without `IRONFLOW_STORE` logs the SQLite store, writes
  `ironflow.sqlite` and no JSON records under a `0700` directory, and `list`
  reads the run back.
- `tests/test_sql_backend_cli.rs::default_store_directory_must_not_be_a_symlink`
  (Unix): a symlinked store directory is refused before anything is written.
- `tests/test_cli_precedence.rs` seeds its store-directory probes through
  `SqlStateStore`, so the precedence tests exercise the default backend;
  `tests/test_cli_list.rs` keeps seeding JSON records and now selects the JSON
  store explicitly; `unused_sql_urls_do_not_affect_json_or_memory_backends`
  selects `json` explicitly, since the default now validates SQL URLs.
- `tests/test_artifact_retention.rs` seeds the referenced run through
  `SqlStateStore`, so offline artifact pruning is proven against the store the
  CLI opens by default. Before this change it seeded the JSON store, which the
  default prune no longer scans, and the retained artifact was deleted.

### Validation (focused)

- `cargo fmt --all -- --check`; `python3 -B scripts/check_module_size.py`
  (passed, 8/8 exceptions).
- `cargo clippy --all-targets -- -D warnings`, with
  `--features postgres,redis,cjk-fonts`, and with `--no-default-features`:
  green.
- `cargo test --lib`: 572 passed, 1 ignored. Area binaries through
  `scripts/test_rust_targets.ts`: api 52, cli 86, engine 274, examples 11,
  scheduler 73, storage 85, serial 184 (single-threaded), all passed. The
  store contract tests in `storage` cover the SQLite and JSON backends.
- Not run locally: `scripts/test_container_store.ts` needs a freshly built
  image. The Container workflow runs it before publishing any tag; its new
  SQLite assertions are validated there on the next push.
- A local end-to-end smoke of the stack top (CLI run, list, inspect from a new
  process, symlink refusal, explicit `IRONFLOW_STORE=json`, and `serve` with
  webhooks) is recorded in the development log of this change set.
