# IF-178 — extract_pdf font decoding is unbounded for wide ToUnicode ranges and long glyph strings

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12.

1. ToUnicode ranges (reproduced). Hand-built one-page PDFs of about 1.2 KB
   whose font carries a ToUnicode CMap with a single `bfrange`:

   | Range | Result (local debug build) |
   |---|---|
   | `<0001> <00FF>` | 37 MB peak RSS, under 1 s |
   | `<000001> <FFFFFE>` | 286 MB peak RSS, 16.7 s |
   | `<00000001> <FFFFFFFE>` | still running and growing when stopped at 20 s, with `:timeout(5)` on the step |

   On the optimized build the 4-byte case was still running at 25 s with
   `:timeout(2)`. `extract_page` (`src/nodes/extract/pdf/text.rs:15-19`)
   calls `get_font_encoding_with_limit` for each font on each page; the limit
   bounds the CMap stream's decompressed bytes only. lopdf 0.46.0 then builds
   a reverse map by iterating every code in every range
   (`encodings/cmap.rs:93-142`), inside one uninterruptible call on a tracked
   worker. The run cannot finish until it returns, and the map is rebuilt per
   page.
2. Glyph strings (by reading, not executed). `collect`
   (`text.rs:85-91`) charges one item per 4 KiB of operand and then decodes
   the whole operand with `bytes_to_string`. A `bfchar` target may hold 256
   UTF-16 units, so a multi-megabyte `Tj` string expands by orders of
   magnitude before `IRONFLOW_MAX_EXTRACT_OUTPUT_BYTES` is compared.

Boundary: `docs/nodes/extract_pdf.md` describes CMap decoding as bounded.
IF-091 and IF-111 bounded load and stream decompression, not range spans or
decoded length. Memory figures for the 4-byte case are extrapolated.

## Required outcome and acceptance

- Before calling lopdf, scan each ToUnicode stream and charge total range
  span and longest target against an explicit budget; reject over-budget
  fonts as a node error. Cache decoded encodings per font object.
- Decode operands in bounded chunks, admitting each against the remaining
  output budget, or reject when input length times the longest target exceeds
  it.
- Regressions: the three PDFs above (the two wide ones fail fast with bounded
  memory), a long-string fixture, and unchanged output for the existing CID
  fixtures (IF-093, IF-156).
- Report the range-expansion behaviour upstream and record the link here.
