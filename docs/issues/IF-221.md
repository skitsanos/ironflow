# IF-221 — Child input mappings and s3vector flags fall back silently on missing or malformed values

## Evidence and boundary

Recorded on 2026-11-13 from the audit done while fixing IF-192. All items
are by reading; none was executed.

- (a) `subworkflow` `input` mapping drops an entry whose parent context key
  is absent, so the child runs without that key and with no error.
- (b) `tool_dispatch` input mapping resolves a missing `ctx.` path to `null`,
  and treats a bare name that is not a context key as a literal string.
- (c) `s3vector_query_vectors` reads `strict`, `return_metadata` and
  `return_distance` as `false` when the value is not a boolean. A malformed
  `strict` therefore drops the cosine requirement for `min_similarity`.
- (d) The inline `filter` of `s3vector_query_vectors` is not interpolated, so
  `"${ctx.tenant}"` inside it is sent as literal text and matches nothing or
  the wrong thing.

Boundary: this is the class IF-192 fixed for `filter_key`: a value that
scopes or selects is replaced by a permissive default instead of failing.
The other `*_key` inputs were read and fail closed (listed in IF-192).

## Required outcome and acceptance

- (a), (b) Decide per mapping whether a missing source key fails the step or
  is an explicit optional form, and document it in the node pages.
- (c) Reject a non-boolean value for the three flags.
- (d) Interpolate string values inside `filter` once, or state in the node
  page that it is literal and reject a value that contains a placeholder.
- Regressions for each, asserting no child run or request on the failing
  cases.
