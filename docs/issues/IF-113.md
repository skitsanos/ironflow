# IF-113 — XML and OOXML extraction lose entities, CDATA, and split text

## Required outcome and acceptance

- Accumulate split text and correctly decode GeneralRef, CDATA, and attribute values through a bounded event contract.
- Cover XML, DOCX, PPTX, and other affected OOXML consumers without bypassing existing byte/depth budgets.
- Add named/numeric entity, CDATA, mixed-text, Unicode, invalid-reference, and expansion-budget regressions.

## Evidence and cause

Fresh review on 2026-09-12, finding R08. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[XML source: parse.rs:93](../../src/nodes/transform/xml/parse.rs), [DOCX: docx_parser.rs:191](../../src/nodes/extract/docx_parser.rs), [PPTX: slide.rs:56](../../src/nodes/extract/pptx_parser/slide.rs).

Text handling ignores GeneralRef/CData events. Generic XML parsing additionally overwrites earlier `#text` chunks and retains escaped attributes. A valid XML entity/CDATA fixture returned only its last Text chunk. DOCX and PPTX containing `A&amp;B &#xE9; C<![CDATA[D]]>E` returned `AB  CE`. These are ordinary content-fidelity failures. Use a common bounded event-decoding contract, accumulate text, normalize attributes, and cover all relevant OOXML text consumers. Evidence: `xml-cache` and extraction probe `entities`.

## Outcome and validation

Resolved on 2026-09-13. A shared internal XML decoder now converts Text, CDATA
and GeneralRef events into normalized text for generic XML, DOCX and PPTX
consumers. It uses the existing quick-xml parser, XML-only predefined entity
resolver, character-reference resolver and version-aware attribute normalizer.
No dependency or configuration option was added.

### Implemented behavior

- Generic XML accumulates direct text rather than overwriting `#text`, normalizes
  attributes, and trims outer whitespace only after accumulation. Spaces next
  to references and between fragments survive. Parsing now uses a tracked
  blocking worker with cooperative checkpoints. The 128-level nesting guard
  includes empty elements; unclosed documents and malformed attributes error.
- DOCX body, metadata, comments and comment anchors preserve decoded fragments.
  Body text is retained only inside `w:t`; run indentation is not document text.
  Comment text and anchors concatenate runs without invented spaces and use
  paragraph separators. IDs, styles, list properties, theme/color values and
  author attributes are normalized consistently before lookup or retention.
- PPTX titles, paragraphs, table cells, speaker notes, metadata and comments
  preserve fragments. Notes separate paragraphs, not individual events/runs.
  Placeholder types, list levels, image descriptions/embed IDs and comment
  attributes use the declared XML version. Existing relationship and content-type
  normalization remains unchanged and passes its compatibility tests.
- XLSX already handles Text, CDATA and GeneralRef through Calamine. Its decoder
  and shared-string preflight were left unchanged; new inline/shared-string
  extraction regressions confirm the same fixture text remains intact.

### Bounds and compatibility

Only the five built-in XML entities and valid decimal/hexadecimal character
references are supported. References are decoded once; CDATA is literal, not
unescaped again. DTDs and unknown/custom entities are rejected without fetching
external resources or attempting recursive expansion. XML 1.0 is the default;
declarations select 1.0/1.1 newline and attribute-normalization behavior.

The decoder admits source-width text/CDATA and decoded reference bytes before
normalization/allocation. Extraction uses the existing cumulative output budget;
DOCX temporary attribute decoding checks remaining output capacity without
repeatedly charging a transient value as retained output. PPTX cell-text copies
are explicitly charged. Existing ZIP part/aggregate bytes, entry/event/item
limits, anchor fan-out, final serialized-output limits and cancellation checks
remain active. Generic XML's text/attribute decoding is bounded by input UTF-8
length, not by a new input-size or total JSON-memory cap.

The XML-to-JSON projection still cannot retain text/child interleaving: direct
text is one `#text` value and children are separate keys. This is not a lossless
XML DOM or an Office renderer. PPTX presentation membership/order and associated
note selection remain the separate [IF-115](./IF-115.md) contract. No skill,
hook, toolchain, release or service configuration changes were needed.

### Regression evidence

Before implementation, `cargo test --test test_xml_text_fidelity` failed all
three initial regressions: XML returned only `tail`; PPTX returned `AB  CE`
instead of `A&B \u00e9 CDE`; and DOCX failed to match a comment range whose start
ID was `&#49;` and end ID was `1`. All three pass after the repair.

Post-fix validation on current stable Rust 1.98.1:

- `cargo test --lib util::xml`: six new tests passed, including one-byte reader
  fragmentation, Unicode, XML versions, literal CDATA/double-escape behavior,
  invalid/unknown references, DTD rejection and pre-allocation byte admission.
- `cargo test --lib nodes::extract`: 76 tests passed, including two new tests
  proving reference/CDATA and temporary-attribute admission against the actual
  extraction Budget, plus existing archive, cancellation and fan-out coverage.
- `cargo test --test test_xml_text_fidelity --test test_extract_nodes
  --test test_extract_word_safety --test test_extract_pptx_limits
  --test test_extract_pptx_relationships --test test_extract_pptx_media
  --test test_extract_xlsx --test test_xml_yaml_nodes`: 76 tests passed.
  One pre-existing XLSX far-corner stress test remains explicitly ignored; it
  was not used as validation evidence. Total focused coverage: 158 passed,
  including 19 new tests.
- The 11 new integration tests cover generic mixed text, DOCX metadata/comments/
  anchors/styles/numbering/themes, PPTX titles/tables/notes/comments/attributes
  and all three output formats, unchanged XLSX inline/shared strings, strict
  references/attributes, DTD errors, deadline rejection and actual CLI behavior.
- CLI tests use cleared child environments, temporary workspaces and bounded
  process timeouts. Both extractors reject oversized parts at archive admission.
  All four affected XML/Word/PPTX/XLSX examples validate and execute; the XML
  example asserts recovered text and attribute values itself. No credentials,
  external services or fixture-byte changes were needed.
- `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`,
  `python3 -B scripts/check_module_size.py`, `cargo audit --deny warnings`,
  issue-registry validation and `git diff --check` passed.

This is focused local parser/node/CLI evidence, not a full integration gate,
native Office rendering, live LLM reconstruction, or deployed-service validation.
