# IF-103 — Multimodal LLM calls require image bytes in persisted workflow context

## Required outcome and acceptance

The `llm` node accepts provider-native message objects, but image examples must
read rendered files as Base64 and interpolate the resulting strings into data
URLs. Those encoded bytes enter workflow context and durable run state before
the request, amplifying large document workflows and discarding the integrity
and provenance carried by IronFlow artifact descriptors. Runtime-generated
conversation arrays also cannot be supplied directly from context.

Required outcome:

- allow chat messages to be read from an explicit context key as an array,
  with the same validation applied to inline `messages`;
- define an IronFlow-only image-artifact content block that references a
  context artifact descriptor or URI and is converted to the provider's
  `image_url` block only while constructing the outbound request;
- open artifacts through the integrity-verifying artifact-store boundary on a
  tracked blocking worker, enforce an explicit cumulative byte ceiling before
  Base64 expansion, and reject unsupported or ambiguous media types;
- preserve provider fields such as image detail while preventing IronFlow-only
  source selectors from reaching the provider;
- keep artifact bytes and generated data URLs out of node output, errors, and
  persisted workflow context;
- cover descriptor and URI inputs, request shape, multiple-image cumulative
  limits, malformed blocks, missing context keys, integrity failure, and
  cancellation-sensitive reads; and
- update the Gemini PDF/PPTX examples to pass artifacts directly and use
  runtime subworkflow fan-out where the current deck example hard-codes batch
  calls.

This work does not introduce a provider-specific upload service, public
artifact URLs, or arbitrary local-path reads inside LLM messages. Responses
mode remains unchanged until its provider-neutral binary-input contract is
defined separately.

## Outcome and validation

**Resolved on 2026-08-17.** Chat-mode `llm` calls can now select a runtime
message array through `messages_key`. Inline and context-selected messages are
mutually exclusive; context messages are cloned without interpolation so
provider-generated tool-call IDs and assistant content remain exact. The
tool-dispatch example now builds a proper assistant/tool continuation and sends
its next turn through this path.

Message content accepts an IronFlow-only `image_artifact` block referencing a
context artifact descriptor/URI or a directly embedded descriptor/URI. The
resolver opens each source through the integrity-verifying artifact store on a
tracked blocking worker, checks cancellation/deadline state, enforces
cumulative raw-byte and image-count limits before Base64 expansion, sniffs PNG,
JPEG, WebP, or GIF bytes, and rejects MIME conflicts. Only the ephemeral
outbound request receives an OpenAI-compatible `image_url` block. Source
selectors never reach the provider, and provider responses are scrubbed if an
endpoint echoes a generated image data URL into success output or an error.

The Gemini PDF/PPTX examples now use artifacts rather than Base64 context
values and target `gemini-3.7-flash`. Full-deck PPTX reconstruction discovers
runtime batches and fans them into a reusable child through
`parallel_subworkflows`, replacing nine hard-coded model steps. Child-private
batch and provider fields stay out of the parent result.

Six focused artifact-message tests passed, covering descriptor and URI
resolution, outbound shape, byte/count ceilings, malformed inputs, integrity
failure, deadline handling, and provider echo redaction. Live Gemini 3.7 runs
passed for basic chat, the artifact-backed first-page PDF JSON-schema flow, and
the dynamic PPTX JSON-schema parent/child flow. The PDF run retained only the
artifact descriptor for the 55,790-byte image in context, and the PPTX run
discovered and reconstructed both fixture slides through one runtime batch.
The 137-flow catalog validation, clean-checkout fixture runtime matrix, full
`cargo test --all-targets`, module size policy, Rust formatting, and exact
all-target Clippy with warnings denied also passed.
