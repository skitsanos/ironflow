# IF-246 — Child-flow validation can miss invalid descendants depending on declaration order

## Evidence and boundary

Reviewed 2026-11-19 on local `develop` at `ae1f686`.

In `src/cli/commands/validate/children.rs:116`, a cached child is treated as fully checked even when its first traversal stopped at the configured depth limit. A shorter route to the same child can make additional descendants reachable, but their definitions are never validated. A non-strict run may therefore pass a flow that should fail. Distinct from IF-220 depth policy. Source inspection.

## Required outcome and acceptance

Test a root with a conditional path via A to B and an unconditional direct path to B. With a limit of two and an invalid child C of B, non-strict validation must fail naming C through the shorter path in either declaration order. Retain cycle handling and bounded traversal.
