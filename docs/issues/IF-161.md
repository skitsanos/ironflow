# IF-161 — GPL-3.0 html2md is linked into the MIT single binary

## Evidence and boundary

Audit of `develop` at 1.20.1-dev.6 on 2026-10-28.

- `Cargo.toml` declares `html2md = "0.2.15"` as a normal, always-enabled
  dependency; `Cargo.lock` resolves 0.2.17. The crate's registry metadata and
  its crates.io record give the license as `GPL-3.0+` (repository
  `gitlab.com/Kanedias/html2md`).
- Use sites: `src/nodes/extract/html/content.rs` (`parse_html_custom`, custom
  `TagHandler` implementations, `common::get_tag_attr`) behind the
  `extract_html` node, and `src/nodes/utility/markdown.rs` (`parse_html`)
  behind the `html_to_markdown` node.
- IronFlow is MIT (`LICENSE`, `license = "MIT"` in `Cargo.toml`).
  `.github/workflows/release.yml` publishes statically linked binaries for four
  targets in two feature variants and `container.yml` publishes images to GHCR
  and Docker Hub. Each artifact is a combined work that includes GPL code.
- No license gate exists. The CI `audit` job and `scripts/integration_gate.sh`
  run `cargo audit` (advisories only); there is no `deny.toml` or equivalent.
  A scan of the default resolved graph (571 crates) on 2026-10-28 found
  html2md as the only copyleft-only license; `r-efi` is tri-licensed with an
  MIT option.

Boundary: this is a distribution and licensing defect, not a runtime
vulnerability. Private source builds are unaffected; published binaries and
images are.

## Required outcome and acceptance

- Replace html2md with a permissively licensed HTML-to-Markdown conversion
  (candidates: `htmd` (MIT), or an in-tree converter over the
  `html5ever`/`markup5ever` stack already present through `ammonia`) that
  preserves the documented `extract_html` and `html_to_markdown` output
  contracts. `tests/test_extract_html_content.rs`,
  `tests/test_extract_nodes.rs` and `tests/test_shell_markdown_nodes.rs` must
  pass, or any contract change must be documented in `docs/nodes/`.
- Add a license policy gate to the CI `policy` job and
  `scripts/integration_gate.sh` (for example `cargo deny check licenses` with an
  allowlist of MIT, Apache-2.0, BSD, ISC, MPL-2.0, Unicode and Zlib, or a Bun
  script over `cargo metadata`) that fails on copyleft-only or missing
  licenses.
- Document the dependency license policy and shipped third-party notices in
  `docs/SECURITY.md` (fonts already ship `assets/fonts/OFL.txt`).
- Resolution evidence: the resolved graph without html2md, and the new gate
  failing on a seeded copyleft dependency before passing on the real graph.

## Outcome and validation

Resolved on 2026-10-28 on branch `fix/if-161-html2md-license` at
1.20.1-dev.7.

Outcome:

- `html2md` is removed from `Cargo.toml`. `htmd` 0.5.6 (Apache-2.0) renders
  Markdown and `markup5ever_rcdom` 0.38 provides the tree type for the
  existing plain-text walk; both share one `html5ever` 0.38 copy while
  `ammonia` keeps 0.40, so the parser duplicate count is unchanged. The
  lockfile grew by one package to 583.
- `extract_html` (`src/nodes/extract/html/content.rs`) parses once with
  `html_to_tree`, prunes the same non-content subtrees as before, and renders
  `text` through the unchanged DOM walk or `markdown` through
  `tree_to_markdown`. The `TagHandler` workaround html2md required is gone and
  the module shrank by about thirty lines.
- `html_to_markdown` converts through htmd with the shared `NON_CONTENT_TAGS`
  skip list. This also fixes a defect the new characterization test exposed:
  the html2md path emitted `<title>`, `<style>`, and `<script>` text into the
  Markdown output.
- `scripts/check_licenses.ts` evaluates `cargo metadata --locked
  --all-features`, follows normal and build dependencies from the root, parses
  SPDX `OR`/`AND`/`WITH`/parentheses and legacy `/`, and fails closed on
  missing, unparsable, or non-allowlisted licenses; `name@version` exceptions
  carry a rationale and become violations when stale. It runs in the CI `audit`
  job, `scripts/integration_gate.sh`, and `.githooks/pre-commit` for manifest,
  lockfile, or script changes. `scripts/tests/check_licenses.test.ts` covers
  the parser and graph rules; `repository_policy.test.ts` asserts all three
  surfaces and that html2md stays absent from manifest and lockfile.
- Docs: `docs/SECURITY.md` gained "Dependency licenses",
  `docs/nodes/html_to_markdown.md` gained "Content Filtering", and the
  `AGENTS.md` validation rule names the license check next to `cargo audit`.

Contract boundary: the `extract_html` output contract is unchanged and every
pre-existing escape, structure, and filtering regression passes without edits.
`html_to_markdown` now omits head, title, script, style, noscript, and template
content, which is documented. Exact Markdown syntax such as bullet markers may
differ from html2md's output; the documented contract is semantic and the
regressions assert it by rendering through comrak. Build dependencies are
checked conservatively even though they are not linked; dev-dependencies are
excluded because they never ship.

Validation on 2026-10-28:

- Failing first: `bun test scripts/tests/check_licenses.test.ts` failed before
  the script existed and passes with 7 tests after. The gate on the pre-change
  graph reported 578 shipped packages and one violation, `html2md 0.2.17:
  license 'GPL-3.0+' is not allowed`; after the swap it reports 579 shipped
  packages, 0 violations, 0 exceptions.
- `html_to_markdown_omits_head_script_style_and_fallback_content` failed on
  html2md (`leaked Page Title: Page Titlebody{color:red}secret()`) and passes
  after. The other four new characterization tests passed on both
  implementations, pinning headings, nested and ordered lists, GFM tables,
  inline and fenced code, images, block quotes, rules, links with query
  strings, and literal-punctuation escaping.
- Focused: library unit tests 568 passed; `test_extract_html_content` 8,
  `test_extract_nodes` 23, `test_shell_markdown_nodes` 17,
  `test_extract_execution`, `test_extract_text_limits`, `test_extract_config`,
  `test_artifact_nodes`, `test_example_catalog` (loads every Lua example) and
  `test_example_contracts` all green; the HTML example also runs through the
  CLI inside `test_extract_html_content`.
- Gates: `cargo fmt --all -- --check`, module-size policy (9/9 exceptions),
  `cargo clippy --all-targets -- -D warnings` with default features and with
  `postgres,redis`, `cargo check --all-targets` with `postgres` alone and
  `redis` alone, `bun test scripts/tests/*.test.ts` (83 pass), `.codex` hook
  tests (16 pass), hook shell syntax, and `actionlint`.
- Full default suite through `bun --no-env-file scripts/test_rust_targets.ts`
  with `CARGO_INCREMENTAL=0` and line-tables-only debug info: all 180 targets,
  1,823 tests passed, 0 failed. Live TLS gate
  `bun --no-env-file scripts/test_store_tls.ts` on the `postgres,redis`
  binary: 6 checks passed, no `ironflow-tls-*` containers left.
- Not run here: the feature-enabled suite against disposable Redis and
  PostgreSQL containers and the release-build Lua validation loop, both part of
  the pre-push integration gate; this change does not touch storage or the Lua
  runtime. A plain `cargo test --all-targets` attempt was abandoned when its
  per-target artifacts outgrew the available disk space and was replaced by the
  batching runner; that evidence is recorded on [IF-162](IF-162.md).
