# IF-199 — Default SQLite store URL breaks for store directories containing spaces, percent signs or question marks

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12, reproduced with a local
optimized build and a one-step flow on the default backend.

| `--store-dir` | Result |
|---|---|
| `plain` | success |
| `My Runs` (relative) | `Failed to connect SQL state store: error with configuration: invalid domain character` |
| `runs%41data` | `(code: 14) unable to open database file` |
| `a?b` | `unknown query parameter` while parsing the connection URL |
| absolute path with a space | success |
| `My Runs J` with `IRONFLOW_STORE=json` | success |

- In every failing case the directory had already been created.
- `resolve_url` (`src/cli/sql_config.rs:65-84`) formats the raw path into
  `sqlite://{path}?mode=rwc`. sqlx parses it as a URL: the first relative
  component becomes a host, `?` starts the query, and the path is
  percent-decoded, so `%41` opens a different directory than the one that
  was created and protected. If the decoded directory exists, the database
  silently lands outside the private store directory.
- `IRONFLOW_STORE_URL=sqlite::memory:` is accepted and fails at startup with
  `duplicate column name: started_micros`: each pooled connection gets its
  own empty in-memory database.

Boundary: the default `data/runs` and ordinary absolute paths work, which is
why the suites pass. By reading only, Windows drive-letter and backslash
paths (`C:\ironflow\runs`, `.\runs`) take the same parsing route and would
fail; Windows is a release target and is not in CI. Since IF-163 this path
is the default for every installation; the JSON store accepted any
directory.

## Required outcome and acceptance

- Build the SQLite connection from a filesystem path
  (`SqliteConnectOptions::filename`) or percent-encode an absolutized path,
  so any valid directory name works and nothing is decoded.
- Reject in-memory SQLite URLs for the state and event stores, or pin their
  pool to one connection, with a clear message.
- Regressions: relative and absolute directories containing a space, `%41`,
  `?` and `#`; an in-memory URL; and a Windows-style path test that runs on
  the Windows release job or a documented manual check.
- Do not create the directory before the URL is known to be usable, or
  remove it on failure.

## Outcome and validation

Resolved on 2026-11-14.

**Outcome.** The stores share the `sqlx::Any` pool, which accepts only a URL,
so `SqliteConnectOptions::filename` is not reachable without replacing the
pool type. The default path is instead made absolute and every byte outside
`[A-Za-z0-9._-]` is percent-encoded, separators included, into
`sqlite:<encoded>?mode=rwc` (`src/cli/sqlite_path.rs`). That form has an opaque
URL path, which the parser neither splits nor normalizes, and the driver
decodes it back to exactly the path given. Making it absolute also matters
because the driver opens files with URI names enabled: a relative directory
`file:x` would otherwise be read by SQLite as a URI. One resolver serves the
state and event stores and every command. A path that is not UTF-8 is refused
before the directory is created, and the directory is created only after the
URL and the table prefix are accepted.

In-memory and temporary SQLite URLs (`sqlite::memory:`, `mode=memory`,
`file::memory:`, no file name) are rejected, in the CLI resolver with the
setting name and in both store constructors. Rejection was chosen over a
one-connection pool: an in-memory state store cannot be read by a later
`inspect` or `list`, and a single connection would serialize `serve` and stall
any path that needs a second connection while one is held.

Found while fixing, fixed in its own commit: an invalid SQL table prefix was
reported only after the directory and an empty database had been created, and
`serve` opened the state store before rejecting the prefix for the event
store.

**Contract boundary.** An explicit store URL is still passed to the driver
unchanged and must be percent-encoded by the operator; no directory is
created for it. A failure to open the database after the directory was
created leaves the directory in place.

**Evidence.** Debug builds, default features, macOS, scratch directories
outside the repository.

| Case | Before | After |
|---|---|---|
| `My Runs` (relative) | `invalid domain character` | success |
| `runs%41data` | `(code: 14) unable to open database file` | success |
| `runs%42data`, `runsBdata` present | success, database in `runsBdata` | success, `runsBdata` empty |
| `a?b`, also absolute | `unknown query parameter` | success |
| `a#b`; absolute path with a space | success | success |
| `file:x` | `invalid port number` | success |
| absolute path with `%41` | `(code: 14)` | success |
| `sqlite::memory:`, `sqlite:` | `duplicate column name: started_micros` | rejected, names the setting |
| `sqlite://?mode=memory` | `no such table: ironflow_runs` | rejected, names the setting |
| invalid table prefix | error, directory and database left | error, nothing created |

- Stores written by the unfixed binary at `plain`, an absolute path with a
  space and the default `data/runs` were listed by the fixed binary, and a run
  added by the fixed binary was listed by the unfixed one.
- `tests/test_sqlite_store_path.rs` (in the `cli` binary): seven directory
  names, each run with the relative spelling and read by `list` and `inspect`
  with the absolute one and the reverse; the decoded-sibling case; a
  directory that is not UTF-8; `serve`
  with a SQLite event store and a restart; nine in-memory URL forms across
  `run`, `list`, `inspect` and `serve`; three explicit URLs; the prefix
  ordering. Four of the first five tests failed on the unfixed source.
- Unit tests feed Unix and Windows-shaped paths (`C:\dir`, UNC, `\\?\`)
  through the pinned driver's own URL parsing and compare the file name.

**Not run.** Nothing was executed on Windows: release binaries for it are
built without a test job. `docs/CLI_REFERENCE.md` records a manual check.
PostgreSQL and Redis stores were compiled and linted, not exercised live.
