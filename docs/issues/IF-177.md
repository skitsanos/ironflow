# IF-177 — Diagnostic redaction is quadratic on async workers and misses common credential shapes

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12, reproduced with a local
optimized build.

1. Cost. A step that raises `error(string.rep("token ", N))`:

   | Message size | Wall time |
   |---|---:|
   | 30 KB | 5.2 s |
   | 60 KB | 20.7 s |
   | 120 KB | 84.5 s |
   | 240 KB | 334.8 s |
   | 240 KB without sensitive words | 0.02 s |

   `find_first_ascii_case_insensitive`
   (`src/util/sensitive_url/search.rs:1-15`) finishes with `min_by_key` over
   the whole remaining text, and the loops in `assignments.rs:25-44` and
   `urls.rs:70-92` call it once per match. `settle_failed_attempt` runs
   `redact_diagnostic` inline on the task future
   (`src/engine/executor/task_runner.rs:173-175`) with no size cap, so a step
   `timeout()` cannot preempt it. The same function runs on Slack, LLM and
   ArangoDB error bodies, which are admitted up to tens of megabytes.
2. Coverage. A task error containing
   `password=hunter1 credentials=hunter2 db_password=hunter3
   PGPASSWORD=hunter4 aws_secret_access_key=hunter5 X-API-Key: hunter6
   Authorization=Bearer hunter7 Proxy-Authorization: Basic hunter8` is
   persisted with only `hunter1` removed. `Authorization=Bearer hunter7`
   becomes `Authorization=[REDACTED] hunter7`, leaving the token.
   `credentials` is shadowed by the earlier `credential` needle, `_` and `-`
   count as key characters on the left boundary, and `=` values end at the
   first whitespace (`assignments.rs:4-20, 49-97`).

Boundary: provider-body timings were not measured; they use the same
function. Related: IF-013, IF-038, IF-108.

## Required outcome and acceptance

- Make the scan linear (first match, or a single multi-pattern pass) and cap
  diagnostic length before redaction; run large inputs off the async worker.
- Cover compound keys by sensitive suffix, prefer the longest needle at an
  index, keep `Bearer`/`Basic` tokens with their scheme, and handle escaped
  JSON quotes.
- Regressions: a 1 MiB sensitive-word message redacts within a fixed budget;
  every shape above is removed; existing redaction tests stay green.
- State the scrubber's guaranteed shapes in `docs/SECURITY.md`.

## Outcome and validation

Resolved on 2026-11-12 at 1.21.1-dev.2.

Outcome:

- `search.rs` stops at the first index that matches and skips bytes that
  cannot start a needle; the longest needle wins at an index. The URL and
  label passes resume after each match, so each reads the text once.
- `assignments.rs` reads the text word by word and never looks backwards. A
  word is a sensitive key when it ends with one of fourteen credential names,
  where `_` also matches `-` or nothing. `credentials`, `db_password`,
  `PGPASSWORD`, `aws_secret_access_key`, `X-API-Key` and
  `Proxy-Authorization` follow from that one rule.
- `values.rs` (new) bounds the value. After `=`, `Bearer` or `Basic` and the
  next word are one value. A quote escaped by backslashes opens a value that
  the same escaped quote closes.
- `redact_sensitive_text` scans and keeps the first 64 KiB
  (`MAX_DIAGNOSTIC_BYTES`) and appends `...[truncated]`. A URL that reaches
  the cut becomes `[REDACTED URL]`.
- `ExecutionOverlay::redact_diagnostic_async` moves text above that limit to
  the blocking pool. The task runner and the coordinator's panic path use it.
- Docs: "Diagnostic scrubbing" in `docs/SECURITY.md` lists the guaranteed
  shapes and the shapes not recognized. `CLI_REFERENCE.md`, `ARCHITECTURE.md`,
  `LUA_FLOW_GUIDE.md` and the `llm`, `slack_notification` and `send_email`
  pages state the limit.

Contract boundary:

- Behavior change: a diagnostic above 64 KiB is cut. This reaches stored task
  errors, events, `_error_message` and provider bodies quoted in errors.
- Overlay secrets are matched in the whole text before the cut, so a secret
  that straddles it is not emitted in part. That pass is linear. The blocking
  task is not cancelled with its run and holds no admission permit.
- The `llm` node's own credential pass still reads a whole error body on its
  worker. It is linear and was not changed.
- Matching by ending also redacts text the old boundary rule kept, such as
  `/run/secrets/db_password: No such file` or the port after a host named
  `vault-secret`. An escaped value that ends in a backslash is over-redacted
  to the next matching quote.
- Not recognized: a bare token, plural keys other than `credentials`, keys
  whose sensitive word is not last, and a value that continues on another
  line.
- No example was added: no flow syntax or node parameter changed.
- Provider-body timings against live providers were not measured.

Validation on 2026-11-12, unoptimized builds:

- Failing first: the 1 MiB unit cases did not finish in 10 s and the engine
  case not in 30 s. Five shape tests failed, and the engine stored
  `credentials=hunter2 ... Authorization=[REDACTED] hunter7
  Proxy-Authorization: Basic hunter8`. The negative cases and the eight
  existing scrubber tests passed before and after.
- After: `util::sensitive_url` 27 unit tests, covering pinned output for each
  shape, thirteen texts that must stay, the cut cases, 20,000 generated
  multi-byte texts, and 1 MiB of nine adversarial inputs without the cap in
  under 0.4 s each. `engine::executor::overlay` 6.
  `test_diagnostic_redaction` 3.
- The reported reproduction through `ironflow run`: 0.02 to 0.03 s at 30 KB,
  60 KB, 120 KB, 240 KB and 1.05 MB, with the output cut above 64 KiB. The
  credential string printed no `hunter` value.
- Targets: library 624 (1 ignored), `engine` 287, `api` 56, `nodes` 247,
  `nodes_network` 128, `serial` 186 single-threaded, `scheduler` 73,
  `storage` 85, `cli` 92, `examples` 11, doc tests 0.
- `cargo fmt --all -- --check`, the module-size gate and
  `cargo clippy --all-targets -- -D warnings` pass. `src/util/redaction/`
  and the two existing test files are unchanged.
