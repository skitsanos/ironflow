# IF-250 — HTTP response metadata silently discards repeated headers

## Evidence and boundary

Reviewed 2026-11-19 on local `develop` at `ae1f686`.

`src/nodes/http/request/response.rs:43` collects response header pairs into a JSON map keyed by name. Repeated fields overwrite one another. In particular, downstream workflows cannot recover two separately issued `Set-Cookie` values from the node output. Source inspection.

CLI confirmation: a loopback HTTP 200 response sent two fields, `Set-Cookie: alpha=one` followed by `Set-Cookie: beta=two`. The successful `http_get` output contained only `set-cookie: beta=two`.

## Required outcome and acceptance

Return all repeated values in receipt order without comma-joining Set-Cookie. Keep the current string representation for ordinary single-valued fields or offer a compatible additional representation. Test with a local HTTP fixture.
