# IF-250 — HTTP response metadata silently discards repeated headers

## Evidence and boundary

The HTTP nodes collected header pairs into a JSON object by name, so each repeated field overwrote its predecessor. A response containing `Set-Cookie: alpha=one` followed by `Set-Cookie: beta=two` exposed only `beta=two` to downstream steps.

## Required outcome and acceptance

Return all repeated values in receipt order without comma-joining Set-Cookie. Keep the current string representation for ordinary single-valued fields or offer a compatible additional representation. Test with a local HTTP fixture.

## Outcome and validation

A header received once remains a string. Repeated fields with the same name are returned as an array in receipt order, including identical values. Values are not split or joined on commas. Loopback regressions cover inline and artifact responses. Non-text header encoding is tracked separately in [IF-258](IF-258.md).
