# IF-230 — extract_word reads the main document and its parts from fixed paths

## Evidence and boundary

Found while fixing IF-225 (a), which moved core properties onto the package
relationship. By reading: `extract_word` opened `word/document.xml`,
`word/styles.xml`, `word/numbering.xml`, `word/theme/theme1.xml` and
`word/comments.xml` by name. OPC names these parts only by relationship: the
main part by the `officeDocument` relationship in `_rels/.rels`, the others
by the main part's relationships. A package that stores them elsewhere lost
its text, styles, list numbering, theme colours and comments, or read stale
parts left at the conventional paths.

Reproduced with a hand-built package (main part `doc/main.xml`, its parts
under `doc/parts/`, decoys at every conventional path): the unfixed build
returned the decoy body and decoy comment. No office-suite sample stores the
main part elsewhere; Word, LibreOffice and Office for the web all write
`word/document.xml`, so this is a conformance fix, not one seen in the wild.

## Outcome and validation

Resolved on 2026-11-17.

**Outcome.** One package resolver (`word/package.rs`) reads `_rels/.rels`
once for the main and core-properties parts. It then reads the main part's
relationships once for styles, numbering, theme, comments, notes, headers and
footers. Each falls back to its conventional path when nothing names it.
The IF-225 (c) story reader uses the same resolver. Targets keep the shared
checks: internal only, no scheme, no escape above the package root. More
than one relationship for a single-part kind fails the step.

**Contract boundary.** `_rels/.rels` is now read on every call, not only
with `metadata_key`, so a malformed one fails the step. `extract_pptx` still
opens `ppt/presentation.xml` and `ppt/_rels/presentation.xml.rels` by name.
That is the same assumption and is not changed here.

**Evidence.**

- Before: `test_extract_word_package_parts` failed 2 of 3 tests (relocated
  parts, unsafe relationships); the fallback test passed, as intended.
- After: `--test documents` 249 passed (3 ignored), `--test nodes` 336,
  `--test serial -- --test-threads=1` 199, `--test examples` 12,
  `cargo test --lib extract` 115. The Office for the web sample from IF-225
  gives the same blocks, comment, footnote, header, footer and metadata.
  A test that relied on Word skipping `_rels/.rels` without metadata now
  covers PPTX only. `cargo fmt --check`, `check_module_size.py` and
  `cargo clippy --all-targets -- -D warnings` pass.
