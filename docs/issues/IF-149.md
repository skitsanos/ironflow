# IF-149 — Detached-run regression uses a tight persistence watchdog

## Evidence and boundary

On 2026-09-28, local integration of dependency PRs #193–#198 and the IF-148
scheduler-test fix stopped at `dropped_waiter_detaches_without_abandoning_run`.
The two-second `wait_for_terminal` timeout elapsed; six other tests in
`test_engine_terminalization` passed. The target completed in 7.35 seconds.
The gate stopped and cleaned its IronFlow build artifacts as designed.

The test uses real JSON-store filesystem persistence. It already observes node
entry, aborts and awaits only the public waiter, releases the controlled node,
and observes node destruction before waiting for persisted terminal state.
The terminal-state helper polls storage without an interval, only yielding to
the runtime. The evidence does not establish a dependency-induced engine defect;
the focused seven-test target reproduced the same failure (6 passed, 1 failed)
before the fix, completing in 7.65 seconds.

## Required outcome and acceptance

- Keep the detached-waiter, successful run, task terminal-state, and finish-time
  assertions intact.
- Bound observation with a generous deadlock watchdog and avoid a tight
  filesystem polling loop; do not change production runtime behavior.
- Validate the complete terminalization target, including cancellation, panic,
  and persistence-failure cases, and rerun the integration gate.

## Outcome and validation

The observation helper now waits 10 ms between reads and uses a 30-second
deadlock watchdog. Its success and fully-terminal assertions remain unchanged.
After the fix, the focused `test_engine_terminalization` target passed all
seven cases. The final `scripts/integration_gate.sh` passed the complete default
and feature-enabled suites, including all seven terminalization cases in both
configurations, exact all-target Clippy, formatting, module-size and repository
policies, dependency audit, release build, 153 Lua examples, and required
PostgreSQL/Redis and TLS acceptance. The full gate used disposable PostgreSQL
18.6 and Redis 8.10.2 and cleaned its containers and IronFlow artifacts.

The final candidate combines dependency PRs #193–#198 and IF-148/IF-149 fixes
on `d9ecb38cba33bddbb747ad72676bdd15ca16a8be`. Production behavior and public
contracts are unchanged. These are post-fix local results, separate from the
pre-fix failures above; no new hosted or deployed result is claimed.
