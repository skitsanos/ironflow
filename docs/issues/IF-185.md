# IF-185 — Staged writers publish mode 0600 and write_file append loses concurrent writes

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12, reproduced with a local
optimized build under umask 022.

1. File mode.
   - `write_file` creating a new file produced `-rw-------`.
   - Overwriting an existing `0644` file left it `0600`.
   - `append = true` on a `0755` script left it `0600`.
   - The staged file is created with mode `0o600`
     (`src/nodes/file/archive/rooted/unix/syscalls.rs:63-73`) and renamed
     over the destination; only `copy_file` reapplies a mode
     (`src/nodes/file/io/write.rs:149-170, 197-202`).
   - By reading, the same staging call serves `zip_create`, `zip_extract`,
     `pdf_merge`, grouped `pdf_split` and the Markdown document nodes.
2. Concurrent append.
   - A flow with eight parallel `write_file` steps appending one line each
     to the same file, run twice, reported all 16 steps successful and left
     10 lines.
   - Append reads the existing file, writes it plus the new input to a
     staged file and renames (`write.rs:133-137, 177-205`). Two writers read
     the same base and the last rename wins.

Boundary: IF-140 found the same published-`0600` defect and fixed it for
`copy_file` only. `docs/nodes/write_file.md` does not mention a private mode
or append concurrency. Before the staged writer, `write_file` honoured the
umask, kept an existing mode, and used `O_APPEND`. Portable (non-Unix)
behaviour was not checked.

Added on 2026-11-12 with IF-179: `image_resize`, `image_crop`, `image_rotate`,
`image_flip`, `image_grayscale`, `image_watermark`, `image_convert`,
`image_to_pdf` and the `transcribe` `output_file` now publish through the same
staging call (`src/nodes/file/staged_output.rs`). Measured before IF-179 under
umask 022, they created `0644` files and a replaced `0640` file stayed `0640`;
they now publish `0600`, and their node documents say so. A fix here has to
cover them.

## Required outcome and acceptance

- On replace and append, carry the existing destination's permission bits to
  the staged file. For new files apply `0666 & ~umask`, or keep `0600` and
  document it per node as a deliberate contract.
- Serialize appends per destination within the process, and document that
  cross-process appends are last-writer-wins unless a stronger mechanism is
  added.
- Regressions: new, overwrite and append modes for `write_file`; one
  representative archive, PDF and Markdown output; N parallel appends keep N
  lines.
- Update the affected node documents.
