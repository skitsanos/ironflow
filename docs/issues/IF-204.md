# IF-204 — Release archives and the container image ship no third-party license notices

## Evidence and boundary

Observed on 2026-10-29 against the 1.21.0 release (`main` at fc63a47).

- `.github/workflows/release.yml` packages each of the eight archives (default
  and `-full` for Linux musl, macOS arm64, macOS x86-64 and Windows) from
  exactly two files: the `ironflow` binary and `assets/fonts/OFL.txt`. The
  `Dockerfile` copies the same two files into the image (`/usr/local/bin` and
  `/usr/local/share/licenses/ironflow/fonts-OFL.txt`). No archive and no image
  carries a notices file for the Rust crates linked into the binary.
- `bun --no-env-file scripts/check_licenses.ts` reports 577 shipped packages
  and 0 reviewed exceptions for the `--all-features` graph. Every package comes
  from crates.io and declares an SPDX expression; the identifiers in use are
  0BSD, Apache-2.0, Apache-2.0 WITH LLVM-exception, BSD-2-Clause,
  BSD-3-Clause, BSL-1.0, CC0-1.0, CDLA-Permissive-2.0, ISC, MIT, MIT-0,
  MPL-2.0, Unicode-3.0, Unicode-DFS-2016, Unlicense, Zlib and bzip2-1.0.6
  (LGPL-2.1-or-later appears only as an unused alternative). MIT, the BSD
  licenses, Apache-2.0 and MPL-2.0 all require that the license, its notice or
  (for MPL-2.0) the availability of the covered source be passed on to
  recipients of binary distributions.
- IronFlow itself is MIT (`LICENSE`, `license = "MIT"` in `Cargo.toml`). The
  bundled document fonts are the only third-party component whose license
  already ships (`OFL.txt`, since IF-164).

Boundary: the gate from IF-161 proves that no copyleft-only crate is linked;
this finding is the missing attribution for the permissively licensed crates
that are. It affects the published archives and images only, not source
builds, and it is not a runtime or security defect.

## Required outcome and acceptance

- Generate one deterministic notices file from the same shipped-graph
  definition the license gate uses (normal and build dependencies of the root
  with all features; dev-dependencies excluded), listing every crate with its
  version, SPDX expression, the license IronFlow uses it under and a source
  link, with MPL-2.0 crates carrying a source-availability note and each
  applicable license text included once.
- Ship the file in all eight release archives and in the container image next
  to the fonts' OFL license, and keep the checksum manifest covering the
  archives as today.
- Keep the file current: a check that fails closed when the committed file no
  longer matches the lockfile runs wherever the license gate runs.
- Regressions: a policy test that the generator is deterministic, covers every
  shipped crate the gate reports and fails on a license without a stored text;
  a repository policy test that the release workflow, the `Dockerfile` and the
  gate surfaces reference the file.
- Documentation: the script inventory in `AGENTS.md`, the archive contents in
  `docs/GETTING_STARTED.md`, `docs/DOCKER_HUB_OVERVIEW.md`, the license policy
  in `docs/SECURITY.md` and the next release notes.

## Outcome and validation

Resolved on 2026-10-29 on the 1.21.0 tree.

- `scripts/third_party_notices.ts` (new): `write` renders
  `THIRD_PARTY_LICENSES.md` at the repository root and `check` fails closed
  when the file is missing or differs from the rendering, naming the `write`
  command. It reads the graph through `loadMetadata` and `shippedPackages`
  from `scripts/check_licenses.ts` (the loader is now exported; the policy
  gate's behavior is unchanged) and parses expressions with the gate's
  `parseLicense`, so the gate and the notices can never disagree about which
  crates ship. `LICENSE_PREFERENCE` lists the allowlist in the order one
  option is chosen from an `OR` (MIT first, then Apache-2.0, the BSD
  licenses, ISC, Zlib and the rest); every `AND` operand applies; a
  non-allowed alternative such as LGPL-2.1-or-later is never chosen; an
  expression with no allowed option, a crate without an expression or a
  reviewed exception, and a chosen license without a stored text all abort
  the rendering. Canonical texts come from the SPDX license list and live in
  `scripts/licenses/` (16 licenses plus `LLVM-exception`, which `A WITH B`
  identifiers compose).
- The rendered file depends only on `Cargo.lock`, the preference order and the
  stored texts, never on the crate order in the metadata or on the IronFlow
  version: a header with the generation command and the preference order; a
  table of 577 rows (crate, version, SPDX expression, the license IronFlow
  uses it under, repository link, with a crates.io link when a crate declares
  no repository); an MPL-2.0 section naming `cssparser` 0.38.0 and
  `dtoa-short` 0.3.5 with repository and crates.io links and the section 3.2
  source-availability statement; a reviewed-exceptions section when the gate
  has any (none today); and the 14 license texts in use, each once (MIT 492
  crates, Apache-2.0 39, Unicode-3.0 24, BSD-3-Clause 12, ISC 6, and 2 or 1
  each for BSD-2-Clause, Zlib, MIT-0, CDLA-Permissive-2.0, MPL-2.0, 0BSD,
  BSL-1.0, Unicode-DFS-2016 and bzip2-1.0.6; crates under an `AND` count under
  each operand). The file is 98,378 bytes uncompressed and 21,251 bytes
  gzipped, against archives of 24 MB and more.
- Shipping: `.github/workflows/release.yml` adds the file to the `tar` file
  list and to the `Compress-Archive` path list, so all eight archives carry
  it; the `tar` archives keep `assets/fonts/OFL.txt` at that path and the
  notices at the root, while `Compress-Archive` places both at the root. The
  checksum manifest step is unchanged. The `Dockerfile` copies the file to
  `/usr/local/share/licenses/ironflow/THIRD_PARTY_LICENSES.md` beside
  `fonts-OFL.txt`; `.dockerignore` does not exclude it.
- Freshness: the file is committed, and `third_party_notices.ts check` runs
  after `check_licenses.ts` in the CI `audit` job, in
  `scripts/integration_gate.sh` and in `.githooks/pre-commit`, whose trigger
  now also covers the notices file, both scripts and `scripts/licenses/`.
  Contract boundary: any `Cargo.lock` change, including a dependency bot's
  pull request, fails the audit job until `write` is rerun and the result is
  committed; the pre-commit hook enforces the same locally. Per-crate
  copyright lines are not reproduced; each crate's own license file is
  reachable through its source link, as the file states.
- Docs: `AGENTS.md` (script inventory and the regeneration rule),
  `docs/GETTING_STARTED.md` (archive contents and the image path),
  `docs/DOCKER_HUB_OVERVIEW.md`, `docs/SECURITY.md` (license policy section),
  `README.md`, `docs/releases/next.md`, and the check and release skills.
- Regressions: `scripts/tests/third_party_notices.test.ts` (9 tests) covers
  the preference order matching the allowlist, `OR`/`AND`/`WITH` selection,
  normalized texts for every allowed license with a missing text failing,
  byte-identical rendering across runs and reversed metadata order, every
  shipped fixture crate exactly once with dev-only crates absent and
  multi-version crates listed per version, the crates.io fallback, exception
  rendering, the MPL section, each text appearing once, fail-closed rendering
  for copyleft, unlicensed and text-less crates, the freshness messages, and
  the committed file's rows all being locked packages under allowed licenses
  with the stated count. `scripts/tests/repository_policy.test.ts` asserts
  CI runs for the notices inputs, the three gate surfaces run the check, both
  packaging steps and the `Dockerfile` reference the file and `.dockerignore`
  keeps it. `scripts/tests/test_pre_commit_hook.py` asserts the notices
  inputs trigger both license checks.

Validation (focused, 2026-10-29): `bun test scripts/tests/*.test.ts` 91 passed
(10 new); `python3 -B -m unittest discover -s scripts/tests -p 'test_*.py'`
36 passed (1 new); `actionlint .github/workflows/*.yml` clean;
`bun --no-env-file scripts/check_licenses.ts` passed (577 shipped packages, 0
exceptions); `bun --no-env-file scripts/third_party_notices.ts check` reports
the file current (577 crates, 14 texts), exits 1 with the `write` command on
a file with one altered version row and on a missing file, and two
consecutive `write` runs are byte-identical; `bun run scripts/validate_skills.ts`,
`bun run scripts/issues_registry.ts check`, `sh -n .githooks/pre-commit` and
`bash -n .githooks/pre-push scripts/integration_gate.sh` passed. Packaging
dry run: `cargo build --locked --release --target aarch64-apple-darwin`
followed by the workflow's unix `tar` command for that target produced an
archive listing `THIRD_PARTY_LICENSES.md`, `assets/fonts/OFL.txt` and
`ironflow`; the extracted notices were byte-identical to the committed file,
the extracted binary reported `ironflow 1.21.0`, and the manifest command
produced its checksum line. Not verified here: the Windows `Compress-Archive`
step and a live `docker build` of the image, which the repository policy test
covers statically; the first tagged release after this change confirms both.
