# IF-194 — pdf_to_image and pdf_thumbnail can bind Pdfium only once per process

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12, by reading IronFlow and
`pdfium-render` 0.9.4. Not executed: no Pdfium build compatible with 0.9.4
was available, so the failure below is derived from the two code paths.

- Each execution calls `load_pdfium()` and then `Pdfium::new(bindings)`
  (`src/nodes/image/pdf_render/worker.rs:33-34, 79-80`).
- `load_pdfium` (`src/nodes/image/common.rs:74-89`) calls
  `Pdfium::bind_to_library` or `bind_to_system_library` every time.
- In `pdfium-render` 0.9.4, `Pdfium::new` stores the bindings in a
  process-global `OnceCell` (`pdfium.rs:70, 213`), and every `bind_to_*`
  function returns `Err(PdfiumLibraryBindingsAlreadyInitialized)` once that
  cell is set (`pdfium.rs:107-189`).
- Expected result: the first render in a process succeeds. Every later
  render, in the same flow or in any later request to `ironflow serve`,
  fails with `Failed to load pdfium ... PdfiumLibraryBindingsAlreadyInitialized`.
- The suite cannot catch this: `tests/test_pdf_image_nodes.rs:46-49` treats
  any error containing "pdfium" or "failed to load" as a missing-capability
  skip, and CI has no Pdfium library.

Boundary: affects only builds with the default `pdf-render` feature and a
Pdfium library installed. The dependency moved from the 0.8 line to 0.9
without a change to `load_pdfium`.

## Required outcome and acceptance

- Bind once behind a process-wide `OnceLock` and reuse the instance for
  every render, keeping the existing lookup order (`PDFIUM_LIB_PATH`, the
  working directory, then the system library).
- Narrow the test skip to a genuine library-not-found error so any other
  Pdfium failure fails the test.
- Add a regression that renders twice in one process, and run it in at least
  one CI job or documented local gate that provisions a pinned Pdfium build.
- Record the executed two-render result here before resolving, since this
  finding has not been run.
- Note the supported Pdfium version range in `docs/nodes/pdf_to_image.md`.
