# IF-238 — date_format silently returns midnight for conflicting timestamp fields

## Evidence and boundary

At `ae1f686`, the custom-format parser discarded date-time resolution errors and tried the calendar date alone. With `input_format = "%F %T %s"`, the CLI accepted `1970-01-02 12:00:00 0` and returned midnight (epoch 86400), despite the conflicting timestamp. The same flow returned noon for the consistent epoch 129600.

## Required outcome and acceptance

Distinguish a date-only input from an impossible date-time. Test a conflict produces a node error, a consistent timestamp preserves noon, and supported date-only input still defaults to midnight (including with an offset).

## Outcome and validation

Only inputs with no clock fields or Unix timestamp default to midnight at their input offset. A timestamp can fill in missing fields but must agree with those supplied. Regression cases distinguish conflicting and consistent timestamps, incomplete clock fields, and date-only inputs with and without an offset.
