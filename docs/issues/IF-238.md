# IF-238 — date_format silently returns midnight for conflicting timestamp fields

## Evidence and boundary

Reviewed 2026-11-19 on local `develop` at `ae1f686`.

In `src/nodes/utility/date_input.rs:35`, any date-time resolution error falls back to the date at midnight. `src/nodes/utility/strftime/resolve.rs` deliberately rejects conflicting fields, but the fallback drops that error. A CLI flow with `input_format = "%F %T %s"` accepted `1970-01-02 12:00:00 0` and returned `1970-01-02 00:00:00` (epoch 86400). The same flow returned noon for the consistent epoch 129600. This violates the documented agreement requirement for overlapping fields.

## Required outcome and acceptance

Distinguish a date-only input from an impossible date-time. Test a conflict produces a node error, a consistent timestamp preserves noon, and supported date-only input still defaults to midnight (including with an offset).
