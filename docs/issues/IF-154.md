# IF-154 — XLSX preflight regression treats scheduling latency as decompression

## Evidence and boundary

The macOS job for dependency PR #218 failed the existing
`refusal_is_fast_because_nothing_is_decompressed` assertion: the guard took
86.377208 ms, exceeding its 50 ms threshold
([CI evidence](https://github.com/skitsanos/ironflow/actions/runs/40070707671/job/120803312079)).
The check measured filesystem I/O and scheduling as well as archive work, so
elapsed time did not establish whether decompression happened. This is a
confirmed test failure, not evidence of a production decompression bypass or
a serde_json regression. The hosted failure is the pre-fix evidence; it was
not independently reproduced by deliberately loading this machine.

## Required outcome and acceptance

- Prove declared whole-archive size rejection happens before payload decoding.
- Include a negative control establishing that the fixture cannot decompress.
- Remove the incidental latency SLA without changing production guard behavior.
- Pass focused XLSX/schema regressions, strict Clippy, the full integration
  gate, repository policies and hosted macOS/Linux checks.

## Outcome and validation

The replacement test corrupts compressed payload bytes while leaving ZIP
metadata readable. Explicit decoding must fail; the preflight must instead
return its declared-byte-limit diagnostic. The per-part ceiling is unbounded
in this test so it cannot mask a missing whole-archive guard. The fixture is
2 MiB instead of 64 MiB; no wall-clock assertion remains. Production guard
code and limits are unchanged.

The six focused XLSX tests pass, as do 26 focused schema/PDF/Lua integration
tests, the 14 repository-policy tests, module-size policy and the dependency
audit with warnings denied. The PDF policy's previous exact-version assertion
was reproduced failing on lopdf 0.46 before replacing it with structural
feature checks.

The complete local `scripts/integration_gate.sh` passed with
`IRONFLOW_TEST_PUBLIC_TLS=1` on implementation commit
`4159efd4982e277d6c4ffb7a039a2cc5d38f2be4`: 1,773 default tests and 1,898
feature-enabled tests passed, with four preexisting manual tests ignored in
each suite. Default and feature-enabled Clippy passed with warnings denied,
as did formatting, repository policies, the issue registry, the dependency
audit and all 153 Lua example validations.

Required live storage tests used disposable PostgreSQL 18.6 and Redis 8.10.2.
TLS-only CLI/serve persistence and restart checks passed, including PostgreSQL
require/verify-ca/verify-full and the SQL node's provider-boundary probes.
Plaintext, wrong CA/hostname and insecure Redis bypass were rejected. Public
HTTPS acceptance passed its valid control and rejected all four compromised
certificate-chain probes. These are local acceptance results, not deployment
claims; no shared or production services were used.

[Hosted CI for the same implementation](https://github.com/skitsanos/ironflow/actions/runs/40094045272)
passed all checks, including macOS tests, Linux Clippy/tests and full-feature
storage/TLS validation. This closure changes only the issue record and its
generated indexes; the final PR head is independently CI-gated before merge.
