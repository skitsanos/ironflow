# IF-165 — Module-size gate optimizes file length while functions stay complex

## Evidence and boundary

Audit of `develop` at 1.20.1-dev.6 on 2026-10-28.

- `scripts/check_module_size.py` (280 lines) with `module_size_policy.json`
  (nine exceptions, budget nine, hard cap fourteen) and
  `scripts/tests/test_check_module_size.py` enforce a 300-line target and
  400-line hard limit in pre-commit, the CI policy job and the gate.
- Strict Clippy on `--lib` the same day
  (`-W clippy::too_many_lines -W clippy::cognitive_complexity`) reported 26
  findings. Functions over 100 lines: `src/lua/runtime/api.rs` 216,
  `src/engine/executor/task_runner.rs::run_task` 212,
  `src/engine/executor/workflow.rs::run` 197,
  `src/nodes/extract/docx_parser.rs` 196, `src/nodes/ai/llm.rs` 185,
  `src/nodes/composition/subworkflow.rs` 161, `src/api/handlers/flow.rs` 143,
  `src/engine/executor/finalizer.rs` 121, `src/cli/mod.rs` 116,
  `src/nodes/http/request.rs` 109,
  `src/nodes/composition/parallel_subworkflows.rs` 107,
  `src/api/handlers/validate.rs` 104. Cognitive complexity above the default
  25: `workflow.rs::run` 63, `task_runner.rs::run_task` 48,
  `lease.rs::heartbeat_with_timing` 43, `lua/runtime/loader.rs` 40,
  `lua/sandbox.rs` 40, `error_handler.rs` 38, `finalizer.rs` 29,
  `docx_parser.rs` 29.
- Of 561 `src/**/*.rs` files, 44 are at most 30 lines and 63 are 31 to 60
  lines. Several exist only to declare submodules
  (`src/nodes/transform/xml.rs` 5 lines, `csv.rs` 6,
  `src/nodes/composition/conditional.rs` 8). Nesting reaches seven directories
  (`src/nodes/extract/xlsx/archive_preflight/tests`,
  `src/nodes/image/image_basic/resize/budget`).
- The gate counts test-only files: 78 files (10,479 lines) under `src/` are
  `tests.rs`, `*_tests.rs`, `tests/` directories or `test_support`;
  `src/storage/json_store/catalog/complexity_tests.rs` is three lines with
  three submodules because the cap applies to it.
- `evaluate()` treats a module shrinking below its reviewed ceiling as a
  violation, so every improvement to an excepted file requires a policy edit
  in the same change.

Boundary: IF-028 and IF-034 resolved the original 400-plus-line files and this
is not a regression of those. The finding is that the metric rewards file
splitting rather than function cohesion, and that the gate's own cost is high.

## Required outcome and acceptance

- Exclude test-only files from the gate by path convention, and merge trivial
  declaration-only files where cohesion improves.
- Replace shrink-is-violation with "shrinking is allowed; ceilings are lowered
  automatically or reported as a warning".
- Add function-level limits: `clippy.toml` with `too-many-lines-threshold` and
  `cognitive-complexity-threshold`, enabled as warnings first, with the
  current hotspots either refactored or allowed with a rationale, then
  promoted to `-D` in the required lint command.
- Update the Rust design rules in `AGENTS.md`, `test_check_module_size.py` and
  the policy JSON; keep the 400-line hard cap.
- Resolution evidence: gate output listing production files only, and the
  function lints green under the chosen thresholds.

## Outcome and validation

Resolved on 2026-10-29 on the local integration stack (not yet pushed).

### Gate

- `scripts/check_module_size.py` excludes test-only files by path convention:
  `tests.rs`, `*_tests.rs`, `test_support.rs`, and any file under a `tests/`
  or `test_support/` directory. The report now reads
  `Largest Rust production modules (487 scanned, 70 test-only files excluded by
  path convention)`. An exception that names a test-only path is a policy
  error.
- A reviewed module that shrinks, or that now fits the 300-line target, is a
  warning, not a violation. `--ratchet` rewrites `module_size_policy.json`:
  it lowers each shrunken ceiling to the current size, drops exceptions that
  fit the target, and updates `exception_budget`. The first run dropped the
  `src/engine/executor/task_runner.rs` exception (budget 9 to 8). Missing
  modules, growth above a ceiling, growth above the target without an
  exception, and the 400-line hard limit remain violations.
- The two JSON catalog test trees that existed only because the cap applied to
  them (`complexity_tests/{fixture,mutations,reads}.rs`,
  `recovery_concurrency_tests/{helpers,concurrency,paging,recovery}.rs`) are
  single files again, as inline modules with unchanged paths. The other
  declaration-only production files (`transform/xml.rs`, `csv.rs`,
  `conditional.rs`, ...) each front 300 to 500 lines of submodules and were
  left as they are; merging them would recreate the files the gate exists to
  prevent.
- `test_check_module_size.py` covers the exclusion convention (six excluded
  spellings, one near miss that still counts), the shrink warning, the
  `--ratchet` rewrite and its idempotence, the dropped-exception path, and the
  rejection of test-only exception targets: 19 tests.

### Function-level lints

- `clippy.toml` pins `too-many-lines-threshold = 100` and
  `cognitive-complexity-threshold = 25`. `src/lib.rs` and `src/main.rs`
  enable `clippy::too_many_lines` and `clippy::cognitive_complexity` as
  warnings with the test exemption used for IF-171; the required command
  `cargo clippy --all-targets -- -D warnings` therefore denies them. The
  "warnings first" stage collapses into the same change because the
  repository's required lint command already denies every warning.
- Refactored (every function below both thresholds):
  `RunCoordinator::run` (197 lines, complexity 63) became `execute` plus
  `initialize_tasks`, `mark_running`, `settle_phase` and `conclude` in
  `workflow.rs`, with step placement in the new `placement.rs`;
  `WorkflowEngine::run_task` (212, 48) kept the attempt loop and moved the
  running, success, failure and retry-wait records into the new
  `task_attempt.rs`; `finalize` (121, 29) gained a `Terminalization` carrier
  with `persist_final_context`, `repair_tasks` and `publish_finished`;
  `heartbeat_with_timing` (43) delegates to `settle_renewal`;
  `execute_planned_step` (38) delegates its logging; `Scheduler::decide` (63)
  split into `claim`, `post_claim_skip` and `start`; `register_flow_api`
  (216) shares `step_function`, `step_if_function`, `node_config_from_arg`,
  `new_step` and `attach_builder_methods`; the duplicated Lua `env`, `log`,
  `uuid4` and `now_*` globals in `loader.rs` and `sandbox.rs` (40 each) are
  one `register_shared_globals`; `parse_docx_blocks` (196, 29) drives the new
  `docx_parser/blocks.rs::BlockBuilder`; both store factories (complexity 32
  with the `redis` feature) dispatch to one constructor per backend and share
  `RedisSettings::resolve`, with their tests moved to `store_factory/tests.rs`.
- Allowed with a one-line rationale (13 sites): the two request handlers, the
  CLI dispatcher, the HTTP request loop, the `subworkflow`,
  `parallel_subworkflows` and `llm` node lifecycles, the Markdown AST walker,
  the PDF paint and shape passes, the declarative SQL schema, the locked
  PostgreSQL migration, and `emit_log`, whose five tracing macros need one
  constant level each.
- `clippy::cognitive_complexity` counts macro expansions, so tracing-heavy
  functions score far above their visible branching. A toolchain update that
  changes its scoring is handled by refactoring or a scoped allowance, never
  by raising the threshold.

### Validation (focused)

- `cargo fmt --all -- --check`; `python3 -B scripts/check_module_size.py`
  (passed, 8/8 exceptions, production files only).
- `cargo clippy --all-targets -- -D warnings`, with
  `--features postgres,redis,cjk-fonts`, and with `--no-default-features`:
  green.
- `cargo test --lib`: 572 passed, 1 ignored. Area binaries through
  `scripts/test_rust_targets.ts`: api 52, cli 84, documents 114 (3 ignored),
  engine 274, examples 11, nodes 247, scheduler 73, all passed.
- `bun test scripts/tests/*.test.ts`: 91 passed;
  `python3 -B -m unittest discover -s scripts/tests -p 'test_*.py'`: passed.
