# IF-168 — Malformed IRONFLOW_MAX_* limit values silently fall back to defaults

## Evidence and boundary

Audit of `develop` at 1.20.1-dev.6 on 2026-10-28.

- `src/util/limits.rs::env_u64` parses with `.ok()`, `parse::<u64>().ok()`,
  `filter(> 0)` and `unwrap_or(default)`. It has 43 call sites across 21
  variables: `IRONFLOW_LUA_HOOK_INTERVAL`, `IRONFLOW_MAX_AUDIO_BYTES`,
  `IRONFLOW_MAX_DIRECTORY_DEPTH`, `IRONFLOW_MAX_EMBEDDING_VALUES`,
  `IRONFLOW_MAX_EXTRACT_ITEMS`, `IRONFLOW_MAX_FILE_BYTES`,
  `IRONFLOW_MAX_HTTP_BODY_BYTES`, `IRONFLOW_MAX_IMAGE_PIXELS`,
  `IRONFLOW_MAX_PDF_BYTES`, `IRONFLOW_MAX_PDF_DPI`,
  `IRONFLOW_MAX_PDF_MERGE_BYTES`, `IRONFLOW_MAX_PDF_MERGE_FILES`,
  `IRONFLOW_MAX_PDF_MERGE_PAGES`, `IRONFLOW_MAX_PDF_OBJECTS`,
  `IRONFLOW_MAX_PDF_SPLIT_PAGES`, `IRONFLOW_MAX_TASK_OUTPUT_BYTES`,
  `IRONFLOW_MAX_XLSX_CELLS`, `IRONFLOW_MAX_XLSX_ROWS`,
  `IRONFLOW_MAX_ZIP_ENTRIES`, `IRONFLOW_MAX_ZIP_METADATA_BYTES`,
  `IRONFLOW_MCP_SESSION_TTL_SECS`.
- Consequence: `IRONFLOW_MAX_HTTP_BODY_BYTES=10MB`, `=1e6`, `=-1` or `=0` all
  yield the compiled default (50 MiB) with no log line. An operator tightening
  a limit cannot tell it was ignored, and a typo in a tightening value
  silently restores the default.
- Contrast: `src/util/runtime_config.rs` fails closed for
  `IRONFLOW_MAX_CONCURRENT_TASKS`, `IRONFLOW_MAX_CONCURRENT_RUNS`,
  `IRONFLOW_MAX_CONCURRENT_FLOW_LOADS`, `IRONFLOW_MAX_RUN_SECONDS` and
  `IRONFLOW_SHUTDOWN_GRACE_SECONDS`; `tests/test_runtime_limit_config.rs`
  states the rule as "fail-closed parsing for limits whose invalid fallback
  would be unlimited". `AGENTS.md` treats environment configuration as
  untrusted input.

Boundary: no limit becomes unlimited through this path. The defect is silent
loss of operator intent and an inconsistent contract across variables.

## Required outcome and acceptance

- One parsing contract for every numeric `IRONFLOW_*` variable: invalid or
  negative values are fatal at startup for `run`, `serve`, `validate` and the
  scheduler, naming the variable and the accepted format. Define `0`
  explicitly (reject it, or allow "default" only where a node document says
  so).
- Validate all known limit variables once at startup (extending
  `runtime_config`) instead of lazily at first use, so misconfiguration
  surfaces before any run executes.
- Regressions: invalid value fatal for a representative sample of the 21
  variables across `run` and `serve`, valid override honored, unset uses the
  default.
- Update the environment table in `docs/CLI_REFERENCE.md` and every node
  document that lists one of these limits.
