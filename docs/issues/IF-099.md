# IF-099 — Roadmap has no actionable forward plan and the shipped baseline has drifted

## Outcome and validation

**Resolved on 2026-08-05.** The canonical issue registry was mechanically valid
but contained only resolved findings. `docs/IMPLEMENTATION_PLAN.md` contained
165 completed checkboxes, the README roadmap was one unscoped Web UI bullet,
and GitHub had no open issues or milestones. The plan also claimed 130 Lua
flows while the filesystem, catalog, and examples guide contained 132.

Resolution:

- `docs/ROADMAP.md` is now the product-sequencing source of truth, with `Now`,
  `Next`, and `Later` horizons, a capability-maturity matrix, promotion rules,
  and explicit enterprise trust and non-goal boundaries.
- IF-100 and IF-101 are active, bounded records for the committed observability
  and distributed-artifact initiatives. Later candidates remain deliberately
  uncommitted until they receive their own acceptance contract.
- `docs/IMPLEMENTATION_PLAN.md` is explicitly a delivered baseline through
  `1.16.2-dev.4`; its historical snapshot now records all 132 Lua flows.
- The README links to the maintained roadmap and distinguishes current
  priorities from the later read-only UI candidate.
- The issue-registry checker now requires the roadmap file and its core
  horizons. Committed `Now`/`Next` headings must link label-to-target correctly,
  refer to an existing active issue, and appear only once. An exact empty marker
  permits a genuinely empty horizon without manufacturing backlog.

Focused validation passed 5 issue-registry tests and all 35 Bun repository
policy tests. The issue-registry checker passed with 101 canonical findings,
and an independent catalog/filesystem comparison found the same 132 unique Lua
flows. Generated indexes were refreshed and `git diff --check` passed. No Rust,
Lua example, node, storage, external service, or deployed runtime behavior
changed, so Rust, live-storage, and Lua execution gates were not applicable.
