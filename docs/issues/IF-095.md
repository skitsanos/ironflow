# IF-095 — Validation misses undefined globals and captured locals in Lua handlers

## Outcome and validation

**Historical status:** Resolved on 2026-08-05.

A downstream flow deleted a local declaration but retained one read inside a
function handler. Lua resolved that name through `_ENV` as `nil`, so validation
succeeded, execution succeeded, and formatted output silently contained the
text `nil`. The shared function-serialization path also permitted captured
outer locals even though their values are not preserved when handler bytecode
is loaded into the isolated execution VM.

Resolution: validation now parses Lua source with tree-sitter and performs a
lexical scope pass only over function handlers that are actually serialized.
Undefined reads produce stable `undefined_global` diagnostics with character
line and column positions. The ordinary CLI remains warning-only, while
`ironflow validate --strict` rejects warnings. `POST /flows/validate` accepts
the equivalent `strict` boolean and returns structured `warnings` entries.
Malformed source still reaches Lua's parser so its detailed syntax diagnostics
are preserved.

All four function-backed entry points share one serialization helper. It
rejects captured outer locals during ordinary flow loading as well as
validation, before bytecode can silently lose those values. The Lua API and
node-factory responsibilities were split into modules below 300 lines, allowing
the reviewed module-size exception budget to ratchet from 12 to 11. Current
documentation and the runnable function-handler example explain the isolated
handler environment, loader-only `Flow`/`nodes` globals, strict mode, and the
captured-upvalue prohibition.

The contract deliberately does not execute handlers during validation and does
not lexically inspect string-valued `nodes.code.source`; ordinary Lua runtime
semantics apply to that separate source form. The lexical pass covers
function-backed `flow:step`, `flow:step_if`, `nodes.code`, and `nodes.foreach`.

Focused validation passed five analyzer unit tests, two runtime regressions
covering diagnostics and every serialization entry point, and four CLI/API
warning and strict-mode tests. Rust doctests, formatting, the 452-module size
policy with 11/11 reviewed exceptions, exact all-target Clippy, dependency
audit with warnings denied, 14 Bun registry/repository-policy tests, and strict
validation of all 132 Lua examples passed. No live storage, deployment, or full
integration gate was required for this Lua validation change.
