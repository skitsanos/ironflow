# IF-173 — Three new RustSec advisories fail the audit gate; the rmcp one is reachable through mcp_client

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12. `cargo audit --deny
warnings` (the required CI command, `.cargo/audit.toml` has no exceptions)
exits with three vulnerabilities, all published after the 1.21.0 gates ran:

| Advisory | Crate (locked) | Fixed in | Reachable here |
|---|---|---|---|
| RUSTSEC-2026-0462 | `rmcp` 3.8.0 | 3.9.0 | Yes |
| RUSTSEC-2026-0436 | `calamine` 0.37.0 | 0.38.0 | No |
| RUSTSEC-2026-0459 | `libsqlite3-sys` 0.37.0 | 0.39.0 | Narrow |

- `rmcp`: Streamable HTTP clients buffer `application/json` and non-2xx
  response bodies without a limit. `src/nodes/mcp/transport.rs:107-110` builds
  the transport with `StreamableHttpClientTransport::from_config`, so
  `mcp_client` uses rmcp's own reqwest client. A hostile or compromised MCP
  server can grow process memory until the action timeout (default 30 s),
  starting at `initialize`. Stdio frames and SSE events are capped; this path
  is not. `cargo update -p rmcp --dry-run` resolves 3.9.0.
- `calamine`: the defect is in the CFB/OLE2 parser (`.xls`, `.xlsb`, VBA).
  `src/nodes/extract/xlsx` opens `Xlsx` only and never reads VBA, so the
  parser is not reached, but the gate still fails. 0.38 is a breaking bump and
  `xlsx/stream.rs` depends on cell-reader behaviour documented against 0.36.
- `libsqlite3-sys`: bundled SQLite before 3.54 can return uninitialized memory
  when a database is opened with a crafted sibling `-wal` file. The state
  store directory is private (IF-163), so exposure is a `db_query`/`db_exec`
  flow opening an untrusted SQLite file. `sqlx-sqlite` 0.9.0 requires
  `<0.38.0`, so no fixed version resolves today.
- `.github/workflows/ci.yml` runs on push, pull request and manual dispatch
  only. A released `main` is not re-audited, so these stayed invisible until
  the next push.

Boundary: only the advisory database and local resolution were exercised; no
exploit was run.

## Required outcome and acceptance

- Update `rmcp` to at least 3.9.0 and add a regression with a local HTTP
  server whose JSON body exceeds the cap, asserting a bounded failure.
- Update `calamine` to 0.38 and re-verify the streaming cell-reader
  assumptions in `xlsx/stream.rs` with the existing XLSX suites.
- For `libsqlite3-sys`: move to a fixed version as soon as `sqlx` allows it.
  Until then record a reviewed, dated exception in `.cargo/audit.toml` with
  the exposure analysis above and an exit criterion, per `AGENTS.md`.
- Add a scheduled CI run of the audit and license jobs so advisories against
  released code surface without a push.
- Evidence: `cargo audit --deny warnings` green (with at most the one reviewed
  exception), `bun --no-env-file scripts/check_licenses.ts`, focused MCP and
  XLSX tests, and feature-enabled Clippy.
