# IF-173 — Three new RustSec advisories fail the audit gate; the rmcp one is reachable through mcp_client

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12. `cargo audit --deny
warnings` (the required CI command, `.cargo/audit.toml` has no exceptions)
exits with three vulnerabilities, all published after the 1.21.0 gates ran:

| Advisory | Crate (locked) | Fixed in | Reachable here |
|---|---|---|---|
| RUSTSEC-2026-0462 | `rmcp` 3.8.0 | 3.9.0 | Yes |
| RUSTSEC-2026-0436 | `calamine` 0.37.0 | 0.38.0 | No |
| RUSTSEC-2026-0459 | `libsqlite3-sys` 0.37.0 | 0.39.0 | Narrow |

- `rmcp`: Streamable HTTP clients buffer `application/json` and non-2xx
  response bodies without a limit. `src/nodes/mcp/transport.rs:107-110` builds
  the transport with `StreamableHttpClientTransport::from_config`, so
  `mcp_client` uses rmcp's own reqwest client. A hostile or compromised MCP
  server can grow process memory until the action timeout (default 30 s),
  starting at `initialize`. Stdio frames and SSE events are capped; this path
  is not. `cargo update -p rmcp --dry-run` resolves 3.9.0.
- `calamine`: the defect is in the CFB/OLE2 parser (`.xls`, `.xlsb`, VBA).
  `src/nodes/extract/xlsx` opens `Xlsx` only and never reads VBA, so the
  parser is not reached, but the gate still fails. 0.38 is a breaking bump and
  `xlsx/stream.rs` depends on cell-reader behaviour documented against 0.36.
- `libsqlite3-sys`: bundled SQLite before 3.54 can return uninitialized memory
  when a database is opened with a crafted sibling `-wal` file. The state
  store directory is private (IF-163), so exposure is a `db_query`/`db_exec`
  flow opening an untrusted SQLite file. `sqlx-sqlite` 0.9.0 requires
  `<0.38.0`, so no fixed version resolves today.
- `.github/workflows/ci.yml` runs on push, pull request and manual dispatch
  only. A released `main` is not re-audited, so these stayed invisible until
  the next push.

Boundary: only the advisory database and local resolution were exercised; no
exploit was run.

## Required outcome and acceptance

- Update `rmcp` to at least 3.9.0 and add a regression with a local HTTP
  server whose JSON body exceeds the cap, asserting a bounded failure.
- Update `calamine` to 0.38 and re-verify the streaming cell-reader
  assumptions in `xlsx/stream.rs` with the existing XLSX suites.
- For `libsqlite3-sys`: move to a fixed version as soon as `sqlx` allows it.
  Until then record a reviewed, dated exception in `.cargo/audit.toml` with
  the exposure analysis above and an exit criterion, per `AGENTS.md`.
- Add a scheduled CI run of the audit and license jobs so advisories against
  released code surface without a push.
- Evidence: `cargo audit --deny warnings` green (with at most the one reviewed
  exception), `bun --no-env-file scripts/check_licenses.ts`, focused MCP and
  XLSX tests, and feature-enabled Clippy.

## Outcome and validation

Resolved on 2026-11-12.

- `rmcp` 3.9.0, now also the `Cargo.toml` minimum. It caps a JSON response at
  16 MiB and a non-2xx body at 64 KiB while streaming; the limits are library
  constants. `tests/test_mcp_response_limits.rs` runs `mcp_client` against a
  local HTTP server that records how much it could deliver: a body declared
  one byte over the cap, a 48 MiB body without a length, a 32 MiB JSON error
  body, an oversized `tools/list` reply on an established session, and a body
  exactly at the cap, which is accepted.
- `calamine` 0.38.0. Compared with 0.37 in source: `next_cell`, the `Cell`
  accessors, `Range::from_sparse` and the shared-string reader are unchanged,
  and `worksheet_range_ref` still drops empty cells. Two things did change.
  - The re-verification found a new defect. 0.38 builds one `Style` per `xf`
    when a workbook opens and copies the font name and format code into each.
    A standalone program opening the same 3.7 KB workbook (1 MiB name and
    code, 1,000 formats) peaked at 9.7 MB resident with 0.37 and 2.1 GB with
    0.38. The per-part ceiling does not bound that product, so
    `src/nodes/extract/xlsx/styles.rs` (new) streams every `styles.xml`
    before the open and refuses a table whose records, at 320 bytes each plus
    the longest name and code per format, exceed
    `IRONFLOW_MAX_XLSX_OUTPUT_BYTES`. A workbook at Excel's format limits
    still opens.
  - `_xHHHH_` escapes in cell text now decode for every UTF-16 code unit; a
    test pins it.
- `libsqlite3-sys`: `sqlx` 0.9.0 is still the newest release and its SQLite
  driver requires `<0.38.0`; the `sqlx` development branch accepts `<0.40.0`.
  `.cargo/audit.toml` holds the one reviewed, dated exception with the
  exposure analysis and exit criterion. `docs/SECURITY.md` and the `db_query`
  and `db_exec` pages carry the operator guidance.
- `.github/workflows/ci.yml` runs daily on a `schedule`; every job except
  `audit` opts out.
- Policy tests: the exception must go once a fixed `libsqlite3-sys` is locked
  and no second entry may join it; a scheduled run selects only `audit`.

Boundary: no SQLite exploit was run, and the 0.37 escape behaviour was read,
not run. The MCP limits belong to `rmcp`, and a response of up to 16 MiB still
enters workflow context. The schedule starts once this workflow is on the
default branch; it was linted, not observed running. The style-table defect
has not been reported to `calamine`.

Pre-fix baseline: `cargo audit --deny warnings` listed the three advisories.
With `rmcp` 3.8.0, four of the five new MCP tests failed: three oversized
bodies reached workflow output and the error body produced a 33,554,446-byte
message. With `calamine` 0.38.0 and no preflight, `extract_xlsx` accepted a
2 KB workbook that expands to 250 MiB.

Validation (focused, post-fix): `cargo audit --deny warnings` passes with the
one exception (581 dependencies); `bun --no-env-file scripts/check_licenses.ts`
577 packages; `cargo test --test nodes_network test_mcp` 23 passed;
`cargo test --test documents test_extract_xlsx` 21 passed, and the one ignored
far-corner test passed with `--ignored`; `cargo test --lib
nodes::extract::xlsx` 74 passed; `cargo fmt --all -- --check`;
`python3 -B scripts/check_module_size.py`; `cargo clippy --all-targets -- -D
warnings`, also with `--features postgres,redis`; `bun test
scripts/tests/*.test.ts` 83 passed; the Python policy tests 35 passed;
`actionlint`. The full integration gate, live stores and CI were not run.
