# IF-109 — SQLite numeric expressions silently become null

## Required outcome and acceptance

- Decode SQLite expressions and aggregate values using runtime value types, preserving integer, float, text, null, and supported binary semantics.
- Do not turn unsupported or incompatible decoding into successful JSON null.
- Test COUNT, SUM, AVG, numeric literals, declared columns, and nulls against actual SQLite; check the PostgreSQL contract separately.

## Evidence and cause

Fresh review on 2026-09-12, finding R04. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: database/sql.rs:93](../../src/nodes/database/sql.rs).

`db_query` selects its decoder from declared column metadata, then converts unsupported decode failures to JSON null. A real SQLite query returning COUNT, SUM, AVG, and a numeric literal produced null for all four while reporting success; its string literal remained correct. Expected numeric values were 2, 30, 15, and 1. This affects ordinary analytical queries, independently of optional BLOB support.

Fix and coverage: inspect runtime value types and do not silently suppress incompatible decoding. Add SQLite expression, aggregate, null, and declared-column tests, then check PostgreSQL separately. Evidence case: `db-aggregate`.

## Outcome and validation

Resolved on 2026-09-13. The shared decoder in
[`database/row.rs`](../../src/nodes/database/row.rs) selects the decoder from
`AnyValueRef::type_info().kind()` for each cell. Column declarations no longer
determine how an expression or a later row's value is interpreted. Integer
variants decode to `i64`; SQLx `REAL` decodes to `f32` before widening, while
`DOUBLE` decodes to `f64`. Booleans and text preserve their types, and BLOB/BYTEA
values become JSON byte arrays, including `[]` for empty binary data.

Only a runtime SQL NULL becomes JSON null. Incompatible decoding and non-finite
floating-point values fail the node without partial result output. Local decoder
errors report the column index without preserving a potentially value-bearing
driver error chain. Existing query streaming, parameter binding, pagination,
and serialized-result caps are unchanged. No dependencies were added or changed.

## Contract Boundary

- PostgreSQL still requires the `postgres` feature. SQLx 0.9's generic driver
  rejects unsupported types before this decoder, including NUMERIC, date/time,
  JSON/JSONB, and arrays; unsupported typed NULLs also fail. This issue does not
  add native support for them. Explicit SQL casts to text preserve decimal digits;
  casts to double precision permit approximate numeric output. In particular,
  PostgreSQL AVG over integers requires an explicit supported-type cast.
- Integer result serialization preserves all signed 64-bit digits, but consumers
  with narrower numeric precision may need SQL text casts. Non-finite values
  reaching the decoder fail; NULLs produced by the database itself stay NULL.
- Binary results are byte arrays, not Base64 or artifact descriptors. Array/object
  parameter binding remains unsupported. The existing byte cap measures serialized
  results after materialization, not total driver or process memory.
- The updated `sqlite_crud.lua` asserts numeric COUNT/SUM/AVG results in Lua;
  `docs/nodes/db_query.md` documents the result types and PostgreSQL cast boundary.

## Validation

The new aggregate regression was run before the fix and failed: COUNT, SUM,
AVG, a numeric literal, and a computed number were all JSON null while the text
literal survived. The same regression passes after the fix.

Post-fix focused validation on Rust 1.98.1:

- `cargo test --lib nodes::database::row`: 2 tests, including non-finite values
  and incompatible decoding without cell-content disclosure.
- `cargo test --test test_db_value_types --test test_db_nodes`: 14 tests covering
  real SQLite aggregates, expressions, declared columns with changing storage
  classes, NULL-first rows, empty aggregates, integer limits, text, binary data,
  inclusive byte caps, invalid UTF-8, integer overflow, and existing node contracts.
- The same 14 tests passed with `--features postgres`, together with 4 live
  PostgreSQL tests. The PostgreSQL target was also rerun serially with
  `IRONFLOW_POSTGRES_TEST_REQUIRED=1` against a disposable PostgreSQL 18.6
  container: supported scalar/null values, REAL, typed bound parameters,
  aggregates, unsupported types, explicit casts, and non-finite values all passed.
  These tests use read-only queries and explicit environment configuration without
  dotenv discovery; no shared database or persistent test tables were used.
- `cargo test --test test_example_contracts sqlite_example_parallel_runs_use_disposable_independent_databases`:
  1 test; the updated Lua example validates and runs twice concurrently with
  isolated environment/configuration, numeric assertions, independent temporary
  databases, and cleanup verification.
- `cargo clippy --all-targets -- -D warnings` and the PostgreSQL-feature
  all-target Clippy command passed. Formatting, module-size policy, security audit,
  issue-registry validation, and `git diff --check` passed.

This is 21 distinct focused tests, not the full integration suite, deployment
validation, or a release. No Redis/state-store behavior was changed or claimed
as validated by these query-node checks.
