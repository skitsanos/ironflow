# IF-235 — Six lettre advisories fail the audit gate; send_email over SMTP uses the affected code

## Evidence and boundary

Found on 2026-11-18 while validating IF-231 stage 4. `cargo audit --deny
warnings` failed on six advisories against `lettre` 0.11.23, all published on
2026-11-17 and all fixed in 0.11.24:

| Advisory | Title |
|---|---|
| RUSTSEC-2026-0560 | STARTTLS response injection lets a man-in-the-middle forge SMTP replies |
| RUSTSEC-2026-0561 | Missing dot-stuffing after a bare LF or CR allows SMTP command injection |
| RUSTSEC-2026-0562 | Panic on an `EHLO` reply line of only white space |
| RUSTSEC-2026-0563 | Messages for an address with a quoted local part are sent to a different address |
| RUSTSEC-2026-0564 | Panic on a mailbox display name containing CR or LF |
| RUSTSEC-2026-0565 | Unbounded buffering of an SMTP reply lets a server exhaust memory |

`src/nodes/notify/email/smtp.rs` is the only user. `send_email` with the SMTP
provider builds the message and its mailboxes from flow input and talks to
the relay through `lettre`'s transport, with STARTTLS as the default mode, so
the affected code is on the node's path. The Resend provider does not use
`lettre`.

Boundary: only the advisory titles and local dependency resolution were
read. The advisory texts and the `lettre` changes were not, and no exploit
was run, so which of the six a flow can actually trigger is not established.

## Outcome and validation

`lettre` is 0.11.24 in `Cargo.lock`, and `Cargo.toml` requires it as the
minimum so a later resolution cannot go back. No IronFlow code changed and
no regression test was added: the fixes are inside `lettre`, and none of the
six behaviours was reproduced here.

Validation (focused, default features): `cargo audit --deny warnings` passes
with the two reviewed exceptions (IF-173, IF-231); `cargo test --test serial
test_send_email_node -- --test-threads=1` 12 passed; the license and notices
gates (the notices file is unchanged); `cargo fmt --check`; Clippy on all
targets; the policy tests. No live SMTP relay was used.
