# IF-186 — File-source helper interpolates twice and lets write_file artifact inputs name local paths

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12, reproduced with a local
optimized build.

1. Second interpolation pass.
   - Context `upload = "/nonexistent/${ctx.api_token}.html"`, `api_token =
     "s3cr3t-token"`. `extract_html({ path = "${ctx.upload}" })` fails with
     `failed to read '/nonexistent/s3cr3t-token.html'`, while a `log` node
     with the same template prints the placeholder unexpanded.
   - `extract_html({ source_key = "upload" })` expands it as well: context
     data is treated as a template.
   - The documented escape is lost: `path = "/nonexistent/\\${ctx.name}.html"`
     opens `/nonexistent/resolved.html`.
   - `get_file_source` interpolates `path` and passes the result to
     `parse_file_source`, which interpolates again
     (`src/util/file_source.rs:23, 29, 43`). Callers: the `extract_*` nodes,
     subtitles, `transcribe`, the image nodes, `pdf_merge` sources and
     `write_file` artifact inputs.
   - `docs/LUA_FLOW_GUIDE.md` states that resolution is one pass and that a
     placeholder inside a resolved context string is not evaluated again. A
     flow that validates an untrusted value before using it in a path can be
     bypassed through the indirection, and the expanded value appears in the
     error text.
2. `write_file` artifact parameter.
   - `write_file({ path = "out.txt", artifact = "/path/to/secret.env" })`
     succeeds and copies the local file. `source_key` with `encoding =
     "artifact"` behaves the same for a context string.
   - `src/nodes/file/io/write/input.rs:38-47, 60-66` reuses
     `parse_file_source`, where any string that is not `artifact://...`
     becomes a path. `docs/nodes/write_file.md` defines the parameter as an
     artifact descriptor or canonical URI, and the HTTP node rejects paths for
     the same input (`src/nodes/http/request/body.rs:142-166`).

Boundary: the s3vector parameter helpers that interpolate keys read from
context (`src/nodes/s3vector/parameters.rs:136`, `vectors.rs:123`) were read,
not executed. Related: IF-023, IF-069.

## Required outcome and acceptance

- Interpolate once, at the configuration boundary. `parse_file_source` and
  values read through `source_key` are data and are never re-expanded.
- Accept only artifact descriptors and canonical URIs for `write_file`
  artifact inputs, matching the HTTP node.
- Regressions: the three cases above for one extract node and one image
  node; a path string passed as an artifact is rejected; existing artifact
  inputs still work.
- Audit other helpers that interpolate context-derived strings and list them
  in the resolution note.

## Outcome and validation

Cause: `get_file_source` interpolated `path` and handed the result to
`parse_file_source`, which interpolated every string it was given, including
values read from context. `write_file` reused that parser, whose fallback for
a non-URI string is a local path.

Implementation:

- `src/util/file_source.rs` takes a `SourceOrigin`: `Config(ctx)` resolves a
  string once, `Data` uses it as stored. The interpolated string goes
  straight to a classifier that cannot interpolate. `get_file_source` uses
  `Config` for `path` and `Data` for the `source_key` value.
- `pdf_merge` and `image_to_pdf` use `Config` for `files` / `sources` and
  `Data` for a `source_key` array; the single-image nodes use `Data` for a
  `source_key` value, including its `{ path = ... }` form.
- `write_file` parses every artifact input with `parse_artifact_source`,
  which accepts a descriptor, a canonical URI or an `{ artifact = ... }`
  wrapper and rejects any other string. A configured `artifact` or `content`
  URI is still interpolated once; a `source_key` value is not.

Contract boundary: configuration strings are templates and are resolved
once; a value read through a key parameter is data. Existing behaviour kept:
configured `files`, `sources` and `{ path = ... }` entries interpolate once,
and all artifact forms that worked before still do. Behaviour change: a
context value can no longer carry a template into a source path, and
`write_file` artifact inputs refuse paths (`docs/releases/next.md`).

Audit of the 100 other non-test interpolation call sites (read, each traced
to its origin; 97 take configuration strings or interpolate only the name of
a context key). Three had the same defect and are fixed here:

- `s3vector/parameters.rs` `resolve_string_array`: keys read through
  `keys_source_key` were interpolated (`s3vector_delete_vectors`).
- `s3vector/vectors.rs` `resolve_vectors_data`: vector keys read through
  `vectors_source_key` were interpolated (`s3vector_put_vectors`).
- `notify/slack.rs`: `payload.text` was interpolated with the payload and
  then again as the message text.

Evidence, unoptimized build, `ironflow run` with the context from the
finding, before on the unchanged code and after the fix:

| Case | Before | After |
|---|---|---|
| `extract_html` `path = "${ctx.upload}"` | reads `.../s3cr3t-token.html` | reads `.../${ctx.api_token}.html` |
| `extract_html` `source_key = "upload"` | reads `.../s3cr3t-token.html` | reads `.../${ctx.api_token}.html` |
| `extract_html` escaped `\${ctx.name}` | reads `.../resolved.html` | reads `.../${ctx.name}.html` |
| `image_resize` `path`, escaped `path` | single pass | unchanged |
| `image_resize`, `pdf_merge`, `image_to_pdf` `source_key` | placeholder expanded | used as stored |
| `write_file` `artifact = "secret.env"` | file copied | rejected, nothing written |
| `write_file` `source_key`, `encoding = "artifact"`, path value | file copied | rejected, nothing written |

Regressions, each failing before the fix: `tests/test_file_source_interpolation.rs`
(the three cases for `extract_html`, `pdf_metadata` and `image_resize`,
context source objects and arrays; 5 of 6 failed, the sixth pins configured
lists), `artifact_inputs_reject_local_paths` and
`slack_notification_interpolates_payload_text_once` in the serial binary,
and unit tests in `file_source.rs`, `s3vector/parameters.rs` and
`s3vector/vectors.rs` (the s3vector tests failed with the fix lines
reverted). `artifact_uri_inputs_copy_from_the_store` passes before and after
for seven descriptor and URI forms.

Validation on the fixed tree: library tests 675 passed and 1 ignored;
`nodes` 258, `documents` 154 (3 ignored), `nodes_network` 134, `examples` 11
and `serial` (`--test-threads=1`) 190 passed, none failed; `ironflow validate`
accepts the 59 examples that use the affected nodes. `cargo fmt --all -- --check`,
`python3 -B scripts/check_module_size.py` and
`cargo clippy --all-targets -- -D warnings` pass.

Not run: the full integration gate, feature-enabled (`postgres`, `redis`)
builds, and any live service. `transcribe`, the subtitle nodes and the other
`extract_*` nodes share `get_file_source` and were covered by the helper's
unit tests and their existing suites, not probed one by one. The s3vector
and Slack fixes were exercised in-process only, not against AWS or Slack.
