# IF-130 — ZIP duplicate handling and entry limits occur after deduplicating metadata

## Required outcome and acceptance

- Validate raw archive entry count, duplicate destination names, and central-directory metadata budget before ZipArchive deduplicates/materializes them.
- Reuse established archive/XLSX admission helpers where their contracts match; preserve traversal and symlink defenses.
- Test duplicate identical names under max_entries=1, oversized raw metadata, unique entries at the limit, and cancellation without large-memory probes.

## Evidence and cause

Fresh review on 2026-09-12, finding R25. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: archive/read.rs:17](../../src/nodes/file/archive/read.rs), [extract: extract.rs:35](../../src/nodes/file/archive/extract.rs).

ZipArchive parses central-directory metadata before admission and deduplicates identical entry names. A two-entry archive containing duplicate `same.txt` names succeeded with `max_entries=1` and produced one file, bypassing the explicit duplicate-destination check. Validate raw entry count, duplicate names, and metadata size before construction, following the existing XLSX guard approach. Evidence: `/tmp/ironflow-scope-review-z7J6GT/zip-duplicate/result.json`; no large-memory fixture was used.

## Outcome and validation

Resolved on 2026-09-13. `zip_list` and `zip_extract` now run the shared raw
ZIP/ZIP64 preflight on the same opened regular file before constructing
`ZipArchive`. The scanner was moved from the XLSX implementation into
`src/util/zip_preflight.rs`; small OOXML/XLSX adapters retain their existing
raw-input and dedicated XLSX metadata limits.

Raw entry counts, exact central-header boundaries, duplicate raw names, and
variable metadata budgets are checked before ZIP library construction. Duplicate
detection retains fixed-size name hashes and compares matching names in bounded
chunks. The constructor's resulting entry count must also match the admitted
raw count, rejecting Unicode path aliases that would silently collapse entries.
Extraction's existing decoded-path collision, traversal, special-file, symlink,
declared/actual byte, and staged-publication checks remain in place.

`max_metadata_bytes`, with context interpolation, overrides
`IRONFLOW_MAX_ZIP_METADATA_BYTES` (default 8 MiB) for list/extract. This budget
counts raw central-directory filenames, extra fields, file comments, the archive
comment, and ZIP64 end-record extension data. ZIP64 extension lengths are checked
before the ZIP library allocates that sector. The shared XLSX metadata budget
now also charges archive comments and ZIP64 extensions; other XLSX/OOXML limits
and `zip_create` behavior are unchanged.

### Contract boundary

- Invalid raw metadata fails before listing publication or extraction destination
  changes. Decoded destination collisions are checked after admitted ZIP
  construction, still before destination mutation.
- Single-disk ZIP/ZIP64 directory bounds must be consistent, and the classic
  end record, including its comment, must terminate at EOF.
- The metadata ceiling is not a compressed-payload or total process-memory cap.
  The scanner has a bounded tail buffer and per-entry hashes; ZIP/decoded output
  structures may retain additional copies. The same file handle prevents a path
  replacement from changing the opened input, but does not freeze writes to its
  inode by another process.
- Cancellation is cooperative between raw central headers, filename chunks,
  listing/extraction entries, and copied chunks, and around the synchronous ZIP
  constructor. The constructor cannot be preempted midway. Tracked-worker
  admission and partial-extraction semantics are unchanged.
- Node docs, CLI limits, architecture, XLSX docs, and the ZIP workflow example
  describe the new admission boundary. No dependencies, toolchain pins, skills,
  hooks, services, or release configuration changed.

### Regression evidence

ZIP library reports only one entry for two identical raw names. Running
`cargo test --test test_zip_metadata` failed with
`zip_list accepted two raw entries under max_entries=1`. The same regression
passes after the fix, without a large-memory probe.
