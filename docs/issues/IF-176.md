# IF-176 — Forwarded-header fragments become run-wide secrets and rewrite live step output

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12, reproduced against a local
`ironflow serve` with a webhook that lists one header in `forward_headers`.

- Header `X-Feature-Flags: beta=true,legacy=false`, flow with
  `step_if("ctx.amount > 100", "needs_approval", ...)` and `amount = 250`:
  the guard evaluates true, but its output `_route__if_needs_approval`
  becomes `"[REDACTED]"`, the guarded step is `skipped`, and the run reports
  `success`. Without the header the step runs.
- Header `X-Amzn-Trace-Id: Root=1-...;Parent=...;Sampled=1`: a code step
  returning `{ order1 = "first", total = 1, items = {1,2,3}, note = "room 101,
  1 item" }` is published as `total = "[REDACTED]"`, `items =
  ["[REDACTED]",2,3]`, `note = "room [REDACTED]0[REDACTED], [REDACTED]
  item"`, and the key `order1` is gone. The next step interpolates the
  rewritten values, so the corruption is in live context, not only in storage.
- Cause: `collect_secret_strings` (`src/util/redaction.rs:95-170`) adds the
  whole header value plus every `k=v` component split on `,` or `;`, header
  names, and JSON keys and scalars, with no minimum length.
  `src/util/redaction/owned.rs` then drops any key containing a secret and
  rewrites any string containing one, and `prepare_output`
  (`src/engine/executor/output.rs:63-70`) applies it before publication. The
  8-byte floor in `src/api/webhook_config.rs:162-171` covers the whole value
  only.

A sender who can set an allowed header can therefore suppress `step_if`
branches or blank fields in every later step.

Boundary: requires a webhook with `forward_headers`. IF-011 made whole-value
and structured scrubbing deliberate; the unbounded fragments and name/key
matching are the missed part. `docs/CLI_REFERENCE.md` describes
`forward_headers` as business metadata and documents literal-value redaction
only.

## Required outcome and acceptance

- Apply a minimum length to every derived token; stop treating header names
  and JSON keys as secrets; match short tokens exactly rather than as
  substrings.
- Never rewrite engine-reserved routing keys (`_route_*`,
  `_condition_result_*`) or change JSON types in live output; if a value must
  be withheld, fail the step visibly.
- Regressions: both headers above leave routing, numbers, keys and unrelated
  strings intact while the full header value is still absent from persisted
  runs and events.
- Update the webhook section of `docs/CLI_REFERENCE.md` and `docs/SECURITY.md`
  with the exact redaction contract.

## Outcome and validation

Resolved on 2026-11-12. The cause above was confirmed in source.

- `src/util/redaction/tokens.rs` (new) derives the secrets. A complete overlay
  value is always one. A component (the credential after `Bearer`/`Basic`, a
  `key=value` value split on `,` or `;`, a JSON string or number scalar) is
  one only with at least eight non-whitespace bytes. Header names, JSON keys,
  booleans and shorter components never are. A complete value below the floor
  matches only an identical value; a webhook cannot produce one, because
  `webhook_config` rejects it with the same floor function.
- `src/util/redaction/owned.rs` separates two boundaries. Live (step output,
  failure output, a child result returned to its parent) scrubs strings and
  keys but keeps numbers and top-level `_route_*` / `_condition_result_*`
  keys. Record (task history, stored initial and final context, legacy run
  output) also replaces a number equal to a secret and treats routing keys as
  ordinary fields.
- `src/engine/executor/output.rs` publishes the live form and derives the
  task-history value and the stored child snapshot through the record form,
  re-checking the size cap. Its inline tests moved to `output/tests.rs`.
- No step fails. Nothing has to be withheld from live output, since what
  cannot be rewritten safely is withheld at the record boundary instead, so a
  sender gains no new way to fail a run.
- Docs: contract tables in `docs/CLI_REFERENCE.md`, a "Forwarded webhook
  headers" section in `docs/SECURITY.md`, and matching text in
  `docs/LUA_FLOW_GUIDE.md`, `docs/ARCHITECTURE.md` and
  `docs/IMPLEMENTATION_PLAN.md`. New example
  `examples/15-webhooks/forwarded_header.lua` with catalog and README entries.

Contract boundary: string scrubbing of live output is unchanged (IF-011). A
sender who controls a forwarded header can still blank a string of eight or
more bytes that a later step outputs, which can change a branch that compares
that string. `docs/SECURITY.md` states this; removing it needs a decision
between record-only scrubbing and failing the step, and is a separate
candidate. Matching stays literal: transformed copies are not recognized.

Regressions:

- `tests/test_webhook_header_redaction.rs` (API area, 4 tests) drives the real
  webhook route: both headers above, a route label sent as a header
  component, and a numeric header equal to a body number. On `develop`
  5c3852d all four failed: guard output `[REDACTED]`, routed step `Skipped`,
  and two runs `failed` on rewritten values. Each asserts the header value is
  absent from the response, `GET /runs/{id}`, events and every state file.
  The API test binary now loads `tests/support/webhook.rs` once, so these
  tests and `test_webhook.rs` share its admission lock.
- Unit tests written with the fix: 6 in `src/util/redaction/tests.rs`, 2 in
  `src/engine/executor/output/tests.rs`. The 9 existing redaction tests pass
  unchanged.

### Follow-up: IF-108 regression (2026-11-12)

The first commit of this change (d7f2990 on `develop`) broke an existing
IF-108 contract. `src/nodes/ai/llm.rs` built its error redactor from the
authentication headers it resolves, using the same constructor as the
overlay, so the new exact-match rule for complete values below the floor left
a short provider key in provider error text. On the combined `develop` tree
(3284d68) `test_llm_secret_errors::llm_redacts_resolved_authentication_values_in_both_modes`
in the `nodes_network` binary failed with "credential remained in error" for
the keys `k` and `llm` (reproduced: 1 failed, 3 passed). The validation above
had not run that binary.

`SecretRedactor::from_credentials` now keeps the two contracts apart. A
credential a node resolved itself, and the credential after its `Bearer` or
`Basic` scheme, is redacted wherever it occurs whatever its length (IF-108,
as `docs/nodes/llm.md` states). Overlay values, which a remote party chooses,
keep the eight-byte floor. `llm.rs` uses the new constructor and
`docs/ARCHITECTURE.md` names both rules. Three unit tests cover short and
JSON-escaped resolved credentials and show that the same short value as an
overlay value leaves ordinary text alone. No existing test was changed.

Validation after the follow-up (default features, final tree): `cargo fmt

`--test scheduler` 73; `--test examples` 11; `--test serial --
