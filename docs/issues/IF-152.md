# IF-152 — AWS SigV4a retains an affected bigint dependency

## Evidence and boundary

On 2026-10-24, cargo audit identified RUSTSEC-2026-0387 in
`crypto-bigint 0.5.5`: arithmetic intended to be constant-time may contain
secret-dependent branches. The patched version is >=0.7.6. The latest AWS
cohort (`aws-sdk-s3 1.155.0`, `aws-sigv4 1.6.3`) updates its P-256 dependencies
to the patched line but retains a direct optional `crypto-bigint ^0.5.4`
dependency for SigV4a key derivation. No compatible 0.5 patch is published.
IronFlow explicitly enables the S3 `sigv4a` feature. This is separate from
the eMudhra certificate-authority incident.

## Required outcome and acceptance

- Keep `cargo audit --deny warnings` fail-closed without a silent exception.
- Either obtain approval to disable SigV4a and document the loss of S3
  Multi-Region Access Point support, or retain the feature and hold integration
  pending an upstream fix or a separately reviewed remediation.
- Preserve standard regional S3 and S3 Vectors signing and storage workflows.
- Validate the final resolved default and feature-enabled dependency graphs.

## Outcome and validation

On 2026-10-24 the user approved disabling SigV4a and documenting the limitation.
The S3 dependency no longer enables `sigv4a`. Regional SigV4 signing remains;
S3 Multi-Region Access Points are unsupported. Node, artifact and security
documentation state this boundary. No audit exception or vendored crypto patch
was introduced. The resolved lockfile contains neither the affected bigint nor
its SigV4a curve dependencies. `cargo audit --deny warnings` passes with no
warnings and an empty ignore list. Policy tests guard both this feature
exclusion and the absence of affected bigint versions.

The CLI regression `tests/test_s3_signing_cli.rs` passes in focused default
and full-feature tests. With isolated synthetic credentials, GET/PUT/HEAD/DELETE
presigning uses `AWS4-HMAC-SHA256` and a regional S3 credential scope. A
Multi-Region Access Point fails without returning a regional signed URL; the
current SDK reports a missing endpoint configuration. No AWS service or real
credential is used. Default/full-feature Clippy and the full integration gate
pass; the new signing tests and final evidence also require PR #217's final CI.
