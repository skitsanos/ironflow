# IF-126 — File-cache sanitization aliases distinct logical keys

## Required outcome and acceptance

- Use collision-resistant persistent cache keys and verify original logical key identity on reads.
- Distinct punctuation, Unicode, and path-like keys must not replace or read each other's values.
- Define migration/miss behavior for existing sanitized filenames and test cache-hit, expiration, and normal memory-cache compatibility.

## Evidence and cause

Fresh review on 2026-09-12, finding R21. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: utility/cache.rs:205](../../src/nodes/utility/cache.rs).

`report:a/b` and `report:a?b` map to the same filename. Sequential writes silently replace the other entry and reads return the wrong value with `cache_hit=true`. Use collision-resistant filenames and verify original key identity. Evidence case: `xml-cache`; memory cache is not implicated.

## Outcome and validation

Resolved on 2026-09-13. File entries now use
`<cache_dir>/v1/<sha256>.json`, hashing the exact interpolated key's UTF-8 bytes
with the existing SHA-256 and hex dependencies. Records retain `schema_version`,
the original `key`, `value`, and optional `expires_at`. Reads verify the version
and exact key before accepting a value or deleting an expired entry.

### Contract boundary

- Punctuation, case, Unicode normalization forms, empty keys, and path-like
  strings remain distinct. Keys are neither sanitized nor interpreted as paths.
- Missing/mismatched identity and missing/unsupported version metadata produce
  cache misses without modifying the file. Malformed JSON and incompatible
  field types remain errors. A verified cached JSON null remains a hit.
- Legacy root-level sanitized files are ignored, not migrated or deleted.
  Their original identities cannot be established, so workflows must repopulate
  the versioned namespace after upgrading. The separate directory also avoids
  aliasing a legacy filename that happens to resemble a digest.
- File I/O runs in tracked blocking workers with cooperative checks before and
  after the operation. Synchronous I/O is not preemptible or rolled back. This
  remains a best-effort cache: concurrent writes and expiry cleanup are not
  coordinated or transactional, and keys/values remain plaintext in a trusted,
  operator-controlled directory. The digest is not authentication or encryption.
- Memory-cache behavior, TTL semantics, output fields, directory defaults, and
  per-node/environment precedence are unchanged. No dependencies, configuration
  options, toolchains, skills, hooks, or release metadata were changed.
- Node and CLI documentation describe the format and upgrade behavior. The file
  example writes and verifies two formerly colliding keys; the context-key
  example documents the same identity contract.

### Regression evidence

Before implementation, `cargo test --test test_cache_identity` failed in
`punctuation_keys_do_not_replace_each_other`: reading `report:a/b` returned
`"question value"` instead of `"slash value"` after writing `report:a?b`.
The same regression passes after the fix.

Post-fix validation on the current stable Rust 1.98.1:

- `cargo test --test test_cache_identity --test test_cache_identity_cli
  --test test_cache_nodes`: 26 tests passed, none skipped. Coverage includes 19
  distinct keys, an independently specified SHA-256 filename, copied/wrong-key
  records, missing/null/version metadata, identity checks before expiry cleanup,
  malformed JSON and metadata types, legacy preservation, TTL/overwrite/null
  behavior, unchanged memory identity, and deadline rejection before file I/O.
- CLI tests use separate processes to write/read entries, validate and run all
  three cache examples, and check directory defaults and configuration
  precedence. Fixtures use temporary directories and cleared child environments.
- `cargo test --lib bounded_cache`: seven tests passed, none skipped, covering
  the existing bounded memory-cache primitive. Total focused coverage: 33 tests.
- `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`,
  `python3 -B scripts/check_module_size.py`, `cargo audit --deny warnings`,
  issue-registry validation, and `git diff --check` passed.

This is focused local node/CLI evidence, not the full integration gate,
cross-process concurrency verification, or a deployment test. No external
