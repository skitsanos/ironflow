# IF-172 — Full pre-push gate outlives GitHub's SSH idle timeout, so a gated develop push cannot complete

## Evidence and boundary

Observed on 2026-10-29 while pushing the IF-161 to IF-171 integration stack to
`develop` (1.20.1-dev.8).

- `.githooks/pre-push` ran `scripts/integration_gate.sh` inside the push, as
  designed. The gate took 15 minutes and every phase passed: formatting and
  policy, default Rust gates (every area binary), feature-enabled gates, the
  release build, 156 Lua examples, the disposable PostgreSQL and Redis suites
  and the TLS acceptance, ending with `IronFlow full integration gate passed.`
- `git push` then reported `Connection to github.com closed by remote host.`
  and exited 141 (SIGPIPE): GitHub had closed the idle SSH session while the
  hook ran, so the pack was never sent. Remote `develop` was unchanged.
- The push only landed on a retry with `IRONFLOW_PREPUSH_GATE=fast`, justified
  at the time by the full gate having passed on the identical commit minutes
  earlier, but the hook had no way to know that.
- The first attempt of the same push had failed inside the gate (a test that
  the SQLite default broke), so it never reached the connection drop; the
  defect only shows once the gate is green and long.

Boundary: the hook failed closed and nothing unverified was pushed. The defect
is that the default (`full`) mode of the documented `develop` push path cannot
succeed over SSH once the gate exceeds the server's idle timeout, which pushes
real work toward the `fast` mode and makes the full gate a promise rather than
an enforced step.

## Required outcome and acceptance

- Run the full gate outside the push session and bind the push to it: a
  passing `scripts/integration_gate.sh` records what it validated, and
  `.githooks/pre-push` in `full` mode accepts a fresh record whose content
  matches the commit being pushed, failing closed otherwise with the command to
  run.
- Bind the record to the tree, not the commit, so a message-only amend keeps a
  passing gate while any content change invalidates it; refuse to record on a
  dirty worktree; expire records after a bounded age.
- Keep `IRONFLOW_PREPUSH_GATE=fast` unchanged for intermediate pushes and keep
  the full gate mandatory before merging a release branch or tagging.
- Document the new push sequence in `AGENTS.md`, `README.md`, the check and
  release skills and the implementation plan.
- Resolution evidence: behavioral tests of the receipt (write, accept, amend,
  content change, dirty tree, stale, malformed) and of every hook branch
  (receipt accepted, receipt missing, fast mode, dirty tree, unknown mode,
  non-develop ref), plus one real develop push that passes through the receipt.

## Outcome and validation

Resolved on 2026-10-29.

- `scripts/gate_receipt.ts` (new): `write` records
  `{ tree, commit, completed }` as `ironflow-gate-receipt.json` in the Cargo
  target directory (`CARGO_TARGET_DIR` or `target/`), refusing a dirty
  worktree; `check <commit>` accepts a receipt that exists, parses, is at most
  `IRONFLOW_GATE_RECEIPT_MAX_AGE_SECONDS` old (default 86,400, non-negative
  integer, malformed values fail closed), and whose tree equals
  `<commit>^{tree}`. Rejections name the cause and the command to run.
- `scripts/integration_gate.sh` records the receipt as its last step; a dirty
  worktree yields a warning instead of a receipt, and the gate result is
  unchanged.
- `.githooks/pre-push` `full` mode runs
  `bun --no-env-file scripts/gate_receipt.ts check "$develop_local"` instead
  of the gate. The incoming-PR, clean-worktree, ancestry and development
  version checks run first as before; `fast` mode is unchanged.
- Docs: `AGENTS.md` (push rule and script inventory), `README.md`,
  `docs/IMPLEMENTATION_PLAN.md`, `.agents/skills/check-ironflow/SKILL.md` and
  `.agents/skills/release-ironflow/SKILL.md` describe the sequence: run the
  gate, then push.
- Regressions: `scripts/tests/gate_receipt.test.ts` covers write, same-tree
  acceptance across an amend, rejection after a content change, the dirty
  worktree refusal, missing, stale, future-dated and malformed receipts, and
  the CLI's exit codes including the malformed age limit;
  `scripts/tests/pre_push_hook.test.ts` runs the real hook against a disposable
  repository with faked `bun` and `cargo` and asserts the exact tool sequence
  for an accepted receipt, a rejected receipt (blocked before any build), fast
  mode, a dirty worktree, an unknown mode and a non-develop ref.

Validation (focused): `sh -n .githooks/pre-commit` and
`bash -n .githooks/pre-push scripts/integration_gate.sh`;
`bun test scripts/tests/*.test.ts` 81 passed (8 new);
`python3 -B -m unittest discover -s scripts/tests -p 'test_*.py'` 35 passed;
`bun run scripts/validate_skills.ts`; `bun run scripts/issues_registry.ts
check`. The development version moves to 1.20.1-dev.9 for the push of this
change, which is the first real push through the receipt; its outcome is
appended below once it has happened.
