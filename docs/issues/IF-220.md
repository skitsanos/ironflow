# IF-220 — Operational and validation follow-ups from the 2026-11 fix batches

## Evidence and boundary

Recorded on 2026-11-13. Small items left after the fixes for IF-173 to
IF-211. Each says how it was established; none was re-verified for this page.

- (a) Observed: a run record that cannot be decoded is skipped by
  reconciliation and can be deleted, but `inspect` still fails on it, the
  unbounded `StateStore::list_runs` fails on one, and a damaged lease file or
  Redis index key still fails a reconciliation pass (IF-181).
- (b) Observed: `POST /flows/validate` is still served during a drain
  (IF-183).
- (c) Decision needed: the five-second runtime shutdown bound is a constant
  with no configuration (IF-183).
- (d) Not run: the extended `scripts/replica_acceptance.ts` under Docker
  (IF-183).
- (e) Observed: `ironflow validate` does not load child flows, so a
  recursive flow is found only at run time (IF-188).
- (f) By reading: `IRONFLOW_MAX_REPEAT_ITERATIONS` is parsed outside
  `limits::ALL`, so a malformed value is not rejected at startup.
- (g) By reading: the load-time rejection of an undefined guard comparison
  runs only in the Lua loader (IF-187).
- (h) Closed by IF-215 on 2026-11-15: with `IRONFLOW_LUA_MAX_MEMORY_BYTES=0`
  only the node budget bounded `json_parse` (IF-189). The `json_parse` node
  now has its own budget, `IRONFLOW_MAX_JSON_PARSE_NODES`; the Lua global
  keeps the conversion budget.
- (i) By reading: a detached child's flow load now holds the launching step
  until the load returns (IF-211).
- (j) Not reported upstream: the `calamine` style-table growth (IF-173) and
  the `lopdf` range walk that remains on its main branch (IF-178).
- (k) Cosmetic: `localhost.` with a trailing dot is refused by DNS
  validation, not by the literal-host check, so the error text differs.
- (l) By reading: both Redis stores use the client's default 500 ms response
  timeout, which is not configurable. Under load it failed six unrelated
  tests in one parallel run (IF-216).
- (m) By reading: the run-owned TTL test in `tests/test_redis_store.rs` uses
  fixed 1.2 s and 2 s sleeps around a short TTL, the pattern IF-216 removed
  elsewhere. It has not failed.
- (n) By reading: `html_sanitize` `link_rel` is neither interpolated nor
  type-checked; a non-string value silently uses the default (IF-195).
- (o) Observed: in `examples/20-date/date_format.lua` the handler log and the
  final log both write `log_message`, so its final value depends on step
  order.
- (p) By reading: `llm` in responses mode cannot complete a tool loop.
  `messages` and `tool_dispatch` are chat-only, so reported `function_call`
  items cannot be answered (IF-197).
- (q) By reading: a whitespace-only `llm` reply counts as usable, and a
  non-string `prompt` silently falls through to `input_key` (IF-197).
- (r) Fixed with the IF-200 work: a blank `IRONFLOW_ARTIFACT_DIR` was
  accepted and the server started. Reproduced: an empty value failed only at
  the first artifact publication, and a whitespace-only value created a
  directory of that name under the working directory. Startup now fails and
  names the variable (IF-198).
- (s) By reading: a webhook `secret_env` variable of 16 or more spaces passes
  the length check in `src/api/webhook_signature.rs` (IF-198).
- (t) Decision needed: a blank `IRONFLOW_API_KEY` together with
  `IRONFLOW_ALLOW_UNAUTHENTICATED_API=true` serves unauthenticated even when
  `api_key` is set in the config file. Documented; it could fail instead
  (IF-198).
- (u) Fixed under IF-197 on 2026-11-14: the embeddings OAuth path accepts a
  missing `expires_in` (the token is used once and not cached) and a numeric
  string.
- (v) Decision needed: an explicit `sqlite://<relative path>` store URL still
  treats its first path component as a host. Documented, with `sqlite:<path>`
  recommended; accepted URL forms were not changed (IF-199).
- (w) Decision needed: `artifacts prune` on a store larger than `--scan`
  digests must be looped on `--after`. A flag that loops internally would be
  simpler to schedule but removes the per-invocation bound. Every invocation
  also reads every retained run once; a cheaper audit needs a reference index
  in the state store (IF-200).
- (x) Decision needed: the PostgreSQL schema-change lock bound is a fixed 5
  seconds. During a schema-changing start, statements of running replicas on
  that table can wait that long per attempt, while event publication gives up
  after 500 ms (IF-202).
- (y) Not run: a second replica starting while another builds a missing index
  on a large table (IF-202), and the in-place SQL claim-column upgrade on
  PostgreSQL, which was tested on SQLite only (IF-201).
- (z) Fixed on 2026-11-15, and it was not a flake:
  `test_extract_pdf_font_bounds::wide_ranges_fail_fast_with_bounded_memory_in_the_cli`
  (IF-178) failed in two of three Ubuntu CI runs from 1.21.1-dev.12, never on
  macOS. On Linux a child's `ru_maxrss` starts from the spawning process's
  peak, so the test measured the test binary's own memory. The IF-215 output
  budget tests in the same binary allocate tens of megabytes concurrently.
  Reproduced in a Linux container: alone the test passed 12 of 12 on dev.11
  and on the current tree; together with those tests it failed 6 of 6, with a
  reported peak of about 283 MB. The helper now samples the CLI's own `VmHWM`
  from `/proc` after `exec`; the same pair then passed 6 of 6 and the whole
  `documents` binary 3 of 3. Boundary: growth in the last few milliseconds
  before exit is not sampled, and before this fix the bound was weaker on
  Linux than IF-178 states, because the baseline was the test binary's memory.
- (aa) Measured on 2026-11-15: `test_event_fence_incarnation::sqlite_resubmitted_run_has_complete_events`
  failed once in a local gate while four other builds ran (load average
  above 18): the first run's stream had no `run_started`. Events are
  best-effort and a publish is dropped after 500 ms, so a saturated machine
  loses one. The test, and its memory and Redis siblings, assume a complete
  stream. Not reproduced in isolation; the cause is inferred from the bound.

## Required outcome and acceptance

- Triage as work allows: fix, or close with the reason. (d) needs one live
  run before the next release. (j) is the maintainer's decision.
- A fixed item gets a regression. Resolve the page when none is left.
