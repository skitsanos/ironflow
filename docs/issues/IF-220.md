# IF-220 — Operational and validation follow-ups from the 2026-11 fix batches

## Evidence and boundary

Recorded on 2026-11-13. Small items left after the fixes for IF-173 to
IF-211. Each says how it was established; none was re-verified for this page.

  reconciliation and can be deleted, but `inspect` still fails on it, the
  unbounded `StateStore::list_runs` fails on one, and a damaged lease file or
  Redis index key still fails a reconciliation pass (IF-181).
- (b) Observed: `POST /flows/validate` is still served during a drain
  (IF-183).
- (c) Decision needed: the five-second runtime shutdown bound is a constant
  with no configuration (IF-183).
- (d) Not run: the extended `scripts/replica_acceptance.ts` under Docker
  (IF-183).
- (e) Observed: `ironflow validate` does not load child flows, so a
  recursive flow is found only at run time (IF-188).
- (f) By reading: `IRONFLOW_MAX_REPEAT_ITERATIONS` is parsed outside
  `limits::ALL`, so a malformed value is not rejected at startup.
- (g) By reading: the load-time rejection of an undefined guard comparison
  runs only in the Lua loader (IF-187).
- (h) By reading: with `IRONFLOW_LUA_MAX_MEMORY_BYTES=0` only the node
  budget bounds `json_parse` (IF-189).
- (i) By reading: a detached child's flow load now holds the launching step
  until the load returns (IF-211).
- (j) Not reported upstream: the `calamine` style-table growth (IF-173) and
  the `lopdf` range walk that remains on its main branch (IF-178).
- (k) Cosmetic: `localhost.` with a trailing dot is refused by DNS
  validation, not by the literal-host check, so the error text differs.
