# IF-108 — LLM provider errors copy environment-only credentials into durable history

## Required outcome and acceptance

- Redact resolved request credentials before constructing provider errors, including environment-only keys and custom authentication headers.
- Sanitize endpoint and transport diagnostics without losing the provider/status context needed to diagnose failures.
- Use a controlled credential-echo response and verify the returned error, CLI/log output, and durable run/task/event history contain no synthetic secret.

## Evidence and cause

Fresh review on 2026-09-12, finding R03. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: ai/llm.rs:157](../../src/nodes/ai/llm.rs).

A mock 401 response echoing the submitted synthetic credential in an error message caused that credential to appear in tracing, CLI output, and persisted task errors. The key was supplied through the environment, not initial context. Generic downstream text scrubbing misses this form. This is a controlled echo-response finding, not a claim that a particular cloud provider currently returns a full key.

Fix and coverage: redact known request credentials at the provider boundary before constructing errors; verify logs, task errors, and event history with distinctive synthetic keys. Evidence case: `llm-secret-error`.

## Outcome and validation

Resolved locally on 2026-09-12. LLM requests build a redactor from the resolved
authentication header values, including environment-only keys, and mark
those header values sensitive for debug output. Exact and JSON-escaped secret
variants are scrubbed before request, response-read, or provider-status errors
leave the node. Transport errors omit their raw URL; displayed endpoints hide
userinfo, path, and query. Status errors retain the HTTP status. Existing
artifact data-URL scrubbing remains intact.

All four new regressions failed before the fix and now pass. They cover Chat
and Responses modes, Bearer and custom authentication, short and escaped keys,
transport URL diagnostics, and actual workflow task/event/durable JSON errors.
A real CLI subprocess receives its synthetic key only through the environment;
its flow has no embedded key, and captured stdout, stderr, and persisted JSON
contain no key after a controlled provider echo response.

Validation: `test_llm_secret_errors` passed all four tests. The combined default
`cargo test --all-targets` run passed 1,423 tests with zero failures and two
existing manual tests ignored. Formatting, module-size policy,
`cargo clippy --all-targets -- -D warnings`, and
`cargo audit --deny warnings` passed; 34 affected Lua examples validated.
The LLM document explains the error-redaction contract. Successful model
outputs are intentionally unchanged: this does not permit putting secrets in
prompts or persisted workflow context. Tests use synthetic loopback providers
and temporary stores, not real credentials or a live deployment.
