# IF-222 — Document extraction fidelity follow-ups for DOCX, PPTX and PDF metadata

## Evidence and boundary

Recorded on 2026-11-13 from the IF-193 fix. All items are by reading. The
IF-193 fixtures are hand-built; no office-authored file was tested, and the
notes placeholder shapes for fields, header, date and footer follow the
PresentationML schema from memory.

- (a) Fixed under IF-193 on 2026-11-14: the previous properties kept under
  `w:rPrChange` and `w:pPrChange` are skipped.
- (b) Comment anchors inside `mc:Fallback` are still seen by the anchor
  collector, so a comment may be collected twice.
- (c) Toggle style inheritance is not resolved: an explicit off cancels the
  flag on that run only.
- (d) PDF Info strings with a UTF-16LE byte-order mark, or language tags
  inside PDFDocEncoding strings, are not handled.
- (e) `a:br` inside notes or slide paragraphs adds no line break.
- (f) Not verified: extraction of speaker notes from a deck written by a
  presentation tool.

## Required outcome and acceptance

- (f) first: run `extract_pptx` and `extract_word` on one tool-authored file
  each with notes, text boxes and tracked formatting, and record the result.
- Fix (b) to (e) with a fixture and regression each, or close with the
  reason.
