# IF-203 — Assorted engine, API and documentation follow-ups from the November review

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12. Each item says how it was
established. None is a security or data-loss defect on its own.

Reproduced with a local optimized build:

- (a) Unschedulable step options end the run `stalled`. `:timeout(1e19)` and
  `:retries(1, 2e19)` pass `ironflow validate`, then fail at run time with
  `step timeout is too large to schedule` or `step retry backoff is too
  large to represent as a duration`, and the run reports `stalled: execution
  ended with non-terminal task state` instead of a failed step
  (`src/engine/recovery.rs:59-78`, `executor/deadline.rs:25-28`,
  `task_attempt.rs:150-160`).
- (b) `POST /flows/run` with inline source whose step depends on an
  undefined step returns `500 internal_error`; `POST /flows/validate` on the
  same source returns `valid: false` with the reason
  (`src/api/handlers/flow.rs:151-172`).

By reading, not executed:

- (c) API and webhook callers can set `_schedule` in the initial context.
  The overlap check identifies a schedule's active run by that key alone
  (`src/scheduler/execution.rs:164-168`), so a long run carrying
  `{"_schedule":"nightly_report"}` makes every instant of that schedule skip
  as overlapped. Webhooks reserve `_headers`, `_webhook` and `_flow_dir`
  only.
- (d) A heartbeat tick that lands between the terminal status write and the
  heartbeat stop sees the lease row already deleted, logs a lost lease,
  increments the lost-lease metric and starts a reconciliation pass
  (`src/engine/executor/lease.rs:130-214`, SQL store). Run state is
  unaffected; the metric and log are false alarms.
- (e) If the scheduler task dies, `supervise` begins draining and returns an
  error at once, and `main` exits without waiting for active runs
  (`src/scheduler/runtime.rs:51-63`).
- (f) A JSON-store schedule claim uses a temporary file name 38 bytes longer
  than the final name, which exceeds 255 bytes for a 48-byte schedule name
  combined with the longest IANA zone names
  (`src/storage/json_store/fs.rs:245`, `claims.rs:18-33`), so that schedule
  can never claim.

Documentation drift, checked against the code:

- (g) `docs/ARCHITECTURE.md` line 19 still says JSON file storage ships by
  default; SQLite has been the default since IF-163.
- (h) `docs/CLI_REFERENCE.md` (environment table, for example
  `IRONFLOW_MAX_FLOW_SOURCE_BYTES` and
  `IRONFLOW_MAX_TRANSCRIBE_RESPONSE_BYTES`) says zero or invalid values
  "retain the safe default"; since IF-168 they fail startup.
- (i) `docs/nodes/code.md` documents a user-supplied `bytecode_b64`
  parameter, which IF-035 made unusable for flow authors.

## Required outcome and acceptance

- (a) Validate that timeout and maximum backoff are representable in
  `validate_step_options`, and compute the delay before persisting
  `Running`.
- (b) Validate the graph and node types in the handler and return 400 with
  the validation errors.
- (c) Reserve `_schedule` and `_schedule_instant` on API and webhook input,
  or match overlap on the deterministic run ID.
- (d) Check the stop signal or terminal state before reporting a lost lease.
- (e) Drain active runs before returning the scheduler error.
- (f) Use a fixed-length temporary name.
- (g) to (i) Correct the three documents.
- Each item gets a focused regression where it changes behaviour; items may
  be resolved in separate changes and ticked off here.
