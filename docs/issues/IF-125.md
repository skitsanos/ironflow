# IF-125 — External JSON Schema references panic inside async node execution

## Required outcome and acceptance

- Provide an explicit contract for external references: reject retrieval or move it to a bounded runtime-safe compilation path.
- Ensure valid and failing external refs produce a normal validation result/error rather than a Tokio panic or stalled run.
- Use loopback fixtures to test remote-ref success/rejection, unreachable refs, timeout/cancellation, and ordinary local schemas.

## Evidence and cause

Fresh review on 2026-09-12, finding R20. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: utility/validate.rs:11](../../src/nodes/utility/validate.rs).

Synchronous `validator_for` invokes a blocking HTTP retriever inside Tokio. A loopback `$ref` caused a runtime-drop panic and a stalled run, rather than an ordinary node error. Either reject external retrieval explicitly or compile through a suitable bounded async/blocking boundary. Evidence case: `schema-http-ref`; no external service was contacted.

## Outcome and validation

Resolved on 2026-09-13. Both `validate_schema` and `json_validate` now use
`jsonschema::options().offline().build(...)` in their shared validation helper.
Unresolved resources return a normal error instead of invoking the default HTTP
or file retriever. The policy covers inline schemas and `schema_key` values
supplied as decoded JSON or JSON text.

Compilation and validation run through `run_tracked_blocking_step` with
cooperative checkpoints before/after compilation, between reported validation
errors, and before returning results. Physical worker lifetime stays attached to
task/run admission. Reference-resolution errors are replaced with a generic,
actionable message without retaining URI-bearing error chains. Ordinary
data-validation failures retain their existing `NodeFailure` output.

### Contract boundary

- Definitions, pointer fragments, anchors, and embedded resources identified by
  `$id` remain available without retrieval. Known standard draft meta-schemas
  remain supported. An HTTP-shaped reference can succeed when it identifies a
  resource already embedded in the supplied schema; this is not a URL-string ban.
- External network/file retrieval, unresolved relative references, and unbundled
  custom meta-schemas are rejected. There is no opt-in network resolver. Loading a
  root schema explicitly through `read_file` does not authorize filesystem access
  for its references or establish a file-directory search path.
- Schema-compilation errors do not publish data-validation result fields. They
  still terminalize the step normally and can be handled by `on_error`.
- Cancellation does not preempt an opaque library compilation/validation call.
  Admission may wait for that call to return; checkpoints prevent late successful
  output. This change does not add hard CPU, input-size, error-count, or memory
  limits for arbitrary local schemas. Initial context preparation/JSON parsing
  remains separate from the offloaded compilation/validation stage.
- No dependencies, feature flags, toolchain pins, skills, or hooks changed.
  `docs/JSON_SCHEMA_VALIDATION.md` and both node pages document the shared policy;
  the two existing Lua validation examples now use bundled `$defs` references.

### Regression evidence

The new loopback regression was run before the fix. It failed with Tokio's
"Cannot drop a runtime in a context where blocking is not allowed" panic,
observed as a failed spawned node task rather than a normal validation error.
The same test passes after the fix.

Focused post-fix checks on Rust 1.98.1:

- `cargo test --test test_schema_reference_safety`: 7 tests covering both nodes
  and all schema sources, ordinary/slow loopback endpoints with zero HTTP requests,
  unreachable HTTPS, readable/missing local files, relative refs, `$dynamicRef`,
  custom meta-schemas, URI-credential suppression, bundled pointer/anchor/resource
  refs, five standard drafts, reference-shaped data/annotations, boolean schemas,
  malformed schemas, structured data failures, and workflow failure/recovery.
- `cargo test --test test_schema_execution`: 2 tests. Expired deadlines reject
  work before compilation. A controlled compiler-entry gate on a current-thread
  runtime proves timers/cancellation remain runnable while the blocking worker is
  held, and admission is retained until worker exit, for both nodes and both
  explicit cancellation and step timeout. This does not claim mid-library-call
  preemption.
- `cargo test --test test_schema_examples`: 1 test; both updated examples validate
  and execute their valid/invalid CLI paths with cleared environments and temporary
  state directories. Invalid data still exits unsuccessfully with structured
  validation output.
- `cargo test --test test_nodes validate_`: 7 existing validation-node tests.
- `cargo clippy --all-targets -- -D warnings`, formatting, module-size policy,
  `cargo audit --deny warnings`, issue-registry validation, and `git diff --check`
  passed.

This is 17 focused tests, not a full integration suite, live external service
check, or deployment validation. All endpoint/file fixtures are local and
synthetic; no existing credentials or shared storage services were used.
