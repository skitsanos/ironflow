# IF-153 — JSON lease regression uses a tight reaper-start watchdog

## Evidence and boundary

The macOS job for dependency PR #213 failed in
`storage::json_store::leases::tests::live_renewal_proceeds_while_expired_backlog_is_reaped`
at the one-second wait for the controlled reaper hook
([CI run](https://github.com/skitsanos/ironflow/actions/runs/39867650157/job/120133788064)).
The fixture creates 32 filesystem-backed expired runs before the hook can be
reached. The evidence is an observed hosted watchdog failure, not proof of a
production lease-lock deadlock or an independently rerun pre-fix local failure.

## Required outcome and acceptance

- Preserve the paused-reaper ordering and live-renewal assertions.
- Use a generous deadlock watchdog, not an incidental filesystem latency SLA.
- Release the paused reaper if the test unwinds, and leave production code alone.
- Validate default and full-feature tests plus macOS CI.

## Outcome and validation

Both hook admission and renewal use 30-second watchdogs. The reaper remains
paused while renewal must complete, so retaining the lease lock still fails
the test regardless of the longer bound. A drop guard releases the hook on
unwind. Production lease code is unchanged.

The test passes in default and full-feature local suites. Strict Clippy,
formatting and module policy pass. The combined implementation's macOS and
Linux CI jobs pass at `9d771f9`; the final follow-up is rechecked in PR #217.
