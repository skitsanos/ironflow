# IF-128 — Semantic chunking selects minima of a distance signal

## Required outcome and acceptance

- Select boundaries using the correct polarity for the computed cosine-distance signal.
- Preserve existing minimum/maximum chunk constraints and sensible degenerate-input behavior.
- Use deterministic synthetic embeddings with a known orthogonal topic boundary, homogeneous input, and constrained chunk sizes.

## Evidence and cause

Fresh review on 2026-09-12, finding R23. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: boundaries.rs:18](../../src/nodes/ai/chunking_semantic_engine/boundaries.rs).

The preceding calculation produces cosine distance (`1 - similarity`), but boundary selection prefers minima. Synthetic embeddings for two homogeneous, orthogonal topics produced cuts inside each topic and a chunk crossing the sole topic transition. Correct the signal polarity and add a known-boundary end-to-end test. Evidence case: `semantic-boundary`; this isolates the algorithm and does not measure real-document RAG quality.

## Outcome and validation

Resolved on 2026-09-14. The shared semantic pipeline selects positive interior
maxima of the smoothed cosine-distance curve, retaining the near-zero first
derivative and using negative curvature. Explicit neighboring-value checks
reject low-slope non-peaks and numerical noise on flat curves. Flat-topped peaks
contribute one center boundary, using the left center for even widths; endpoints
are not candidates. Internal helper names now identify distance and maxima.

Peak filtering keeps distances at or above the `1 - threshold` percentile.
Higher threshold continues to admit more candidates: zero retains the strongest
peak(s), including ties, and one admits all candidates before spacing. Existing
left-to-right `min_distance` filtering and saturating gap arithmetic are retained.
Defaults, provider transport, public output keys, sentence order, and embedding
count/dimension validation are unchanged.

Acceptance clarification: the current node has no hard minimum or maximum
chunk-size parameter. Its constraint is the sentence-index gap between accepted
splits, not a minimum first/last chunk size or maximum byte/token budget. The
regressions preserve this actual contract with three eight-sentence topics and
split gaps of zero, eight, and nine, without adding a new size policy. Existing
fixed-size, delimiter, cue, and merge nodes remain separate downstream controls.
Multi-sentence grouping still normalizes inter-sentence whitespace; this is not
a byte-preserving transform.

Empty and single-sentence inputs continue to skip provider requests. Homogeneous,
zero-vector, constant-distance, numerically flat, short, and unsupported-window
cases do not invent boundaries. The new `semantic_topic_boundary.lua` example
uses two inline topics without a document dependency. Node/architecture docs and
the existing semantic examples now explain peak polarity, threshold, spacing,
and size limitations. The example catalog and README counts were reconciled
against all 148 classified flows. No dependency, version, public parameter,
feature flag, or module-size exception changed.

Validation used stable Rust 1.98.1 and deterministic local fixtures:

- Before the production fix, `cargo test --lib chunking_semantic -- --nocapture`
  had 16 passes and five failures: the exact topic transition, flat distances,
  minimum spacing, percentile selection, and threshold direction. Two orthogonal
  eight-sentence topics produced chunk lengths `[2, 11, 3]` instead of `[8, 8]`;
  a flat signal produced `[1, 22, 1]` instead of one chunk. This executable
  baseline is separate from the original audit observation above.
- The same focused unit command passed all 26 final tests. Additional cases
  cover positive peaks versus valleys/endpoints, flat-top centering, tied peak
  strengths, saturating spacing, numerical noise, orthogonal/opposite vectors,
  and existing configuration and malformed-embedding behavior.
- `cargo test --test test_semantic_chunk_boundaries -- --nocapture` passed four
  tests. Mock OpenAI and Ollama responses produce exact `[8, 8]` topic chunks,
  preserve every sentence, and use the expected request content and output
  schema. Homogeneous inputs remain one chunk; empty/single inputs make no HTTP
  request. The CLI test strictly validates all three semantic examples and
  executes the new example with the actual binary and a loopback provider.
  Its cleared environment, synthetic key, and temporary working directory
  prevent project dotenv or live credentials from being loaded.
- `cargo test --test test_ai_chunk_nodes --test test_provider_redirect_security
  -- --nocapture` passed 30 tests; the four semantic tests selected by
  `cargo test --test test_ai_nodes ai_chunk_semantic -- --nocapture` also passed.
- The exact catalog classification test passed, for 65 distinct focused Rust
  tests overall. Only the three affected Lua examples were validated/executed
  as described above; the full example execution matrix was not run.
- `cargo fmt --all -- --check`, `python3 -B scripts/check_module_size.py`, and
  `cargo clippy --all-targets -- -D warnings` passed. All changed production
  modules remain below 300 lines.

This is algorithm, mock-provider, node, and local CLI evidence. It does not
