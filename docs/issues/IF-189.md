# IF-189 — s3_list_objects, json_parse and task error text materialize without a bound

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12. Three paths where a limit
is missing or applied after the data is built.

1. `s3_list_objects` (by reading `src/nodes/cloud/s3_listing.rs:33-77`).
   `max_keys` is only the page size. The loop appends every page until
   `is_truncated` is false, with no object or byte cap. If a response is
   truncated but carries no continuation token, the token becomes `None`,
   the next request restarts at the first page, and the loop never ends.
   That shape is possible with S3-compatible endpoints set through
   `endpoint_url`.
2. `json_parse` Lua global (reproduced, optimized build). Parsing a
   20-million-element array (38 MB of input) raised peak RSS to 746 MB under
   the default 128 MiB `IRONFLOW_LUA_MAX_MEMORY_BYTES`. A 5-million-element
   array reached 279 MB before the 100,000-node conversion cap rejected it.
   `serde_json::from_str` builds the whole tree outside the Lua allocator
   before `json_value_to_lua` applies its budget
   (`src/lua/conversion/mod.rs:50-54`, `json_to_lua.rs:59-74`).
3. Task error text (reproduced). A step raising an 8 MiB error with two
   retries left a 16.8 MB SQLite store for one run, and the CLI printed 42
   MB. Each attempt writes the full message to task state and to a
   `TaskFailed` event, and the last one is copied into `_error_message`
   (`src/engine/executor/task_runner.rs:173-207`, `task_attempt.rs:110-133`).
   Only the child failure summary is truncated.

Boundary: IF-036 and IF-063 bounded S3 get and put, and IF-048 bounded task
output and final context; these three were not covered. S3 was not executed.
The Lua figures are single-call peaks; parallel steps multiply them.

## Required outcome and acceptance

- `s3_list_objects`: add a total object ceiling with a documented default,
  fail on a truncated page without a token or with a repeated token, and
  return the continuation token and common prefixes so callers can page.
- `json_parse`: enforce node, depth and byte budgets while parsing, or bound
  input length from the node limit, so memory stays within the Lua limit's
  order of magnitude.
- Truncate redacted task error text to a fixed budget before it is stored,
  published or copied into context, with a marker that it was cut.
- Regressions for each: a mock endpoint that never stops truncating, an
  oversized `json_parse` input with a memory assertion, and an oversized
  error with a store-size assertion.
- Update the node documents and the limits table.

## Outcome and validation

Resolved on 2026-11-12 at 1.21.1-dev.7.

Outcome:

1. `s3_list_objects`. `s3_list_pages.rs` (new) bounds one call. It returns
   at most `IRONFLOW_MAX_S3_LIST_OBJECTS` objects and common prefixes
   (default 10,000, registered in `limits::ALL`), and the last page is
   requested with a smaller `max_keys` so the bound is exact. Without
   `max_objects` a larger listing fails; with it the call stops and returns
   `{key}_truncated` and `{key}_next_continuation_token`, which
   `continuation_token` resumes. `{key}_common_prefixes` is new. A truncated
   page without a token, a token already used in the call (including the one
   supplied), a page larger than requested and 16 consecutive empty
   truncated pages fail the step.
2. `json_parse`. `conversion/json_parse.rs` (new) deserializes the text
   straight into Lua tables with a `serde` visitor and borrows the text from
   the Lua string. Node and depth budgets are charged per value as it is
   read, and all growth is allocated by the Lua state. After a budget is
   exceeded the rest is scanned without building, which keeps the order
   syntax error, 123-level nesting limit (IF-181), conversion budget.
3. Task error text. No new mechanism: the 64 KiB diagnostic cut from IF-177
   already runs in `settle_failed_attempt` before the text reaches task
   state, the `TaskFailed` event and `_error_message`. This finding adds the
   store-size regression and states the bound in `ARCHITECTURE.md`.

Contract boundary:

- Behavior change: a listing above the ceiling fails unless the step pages.
  `max_keys` is now always sent (1,000 when unset).
- One page's response body is read by the AWS SDK and is not bounded here.
- `json_parse` results within the budgets are unchanged. Over a budget, the
  error path is in document order rather than sorted key order, values
  under a repeated key all count, and the node-budget message no longer
  mentions `context_keys`.
- The `json_parse` node still parses into a `serde_json::Value`; its input
  is a context string and its output is step output. Not changed.
- With `IRONFLOW_LUA_MAX_MEMORY_BYTES=0` only the node budget bounds
  `json_parse`.
- Each failed attempt still stores one bounded event, so the store grows
  with the retry count at up to 64 KiB per attempt.

Validation on 2026-11-12, unoptimized builds, local mock endpoint only (no
AWS call):

- Before, item 1: the ten new `test_s3_list_objects` cases all failed; the
  four endless-pagination cases did not settle in 30 s.
- Before, item 2: `ironflow run` of a 40 MB, 20-million-element array peaked
  at 799 MB resident and ended in a Lua memory error. After: 118 MB and the
  node-budget error at `$[99999]`; a 100 KB array parses as before.
- Before, item 3: on this tree the 8 MiB, two-retry flow already left a
  188 KB store and 331 KB of output (16.8 MB and 42 MB when reviewed, before
  IF-177).
- After: `test_s3_list_objects` 10; `lua::conversion` 18 unit tests (10 new,
  including retained Lua memory under 1 MiB after a refused 5-million-element
  array); `test_cli_materialization_bounds` 3 (peak resident memory under
  320 MiB by `wait4`, store and output each under 1 MiB, ordinary error
  stored whole).
- Targets: library 715 (1 ignored), `engine` 304, `nodes` 258,
  `nodes_network` 144, `storage` 96, `api` 60, `cli` 98, `examples` 11,
  `serial` 190 single-threaded, `limits_defaults` 2,
  `conversion_limits_env` 2. `cargo fmt --all -- --check`, the module-size
  check and `cargo clippy --all-targets -- -D warnings` pass.
  `s3_put_get_list.lua` validates.
- Not run: real S3, optimized-build memory figures, the `postgres` and
  `redis` feature targets, the integration gate.
