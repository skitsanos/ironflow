# IF-226 — Verify extract_pptx comments and notes header and date placeholders against a PowerPoint deck

## Evidence and boundary

Split from IF-222 (f) on 2026-11-16. Verification that could not be done,
plus one gap known from the documentation.

The deck in the sample run of 2026-11-16 (PowerPoint 16, 86 slides, 83
notes pages) confirmed what IF-193 assumed about notes pages for `sldImg`,
`body`, `sldNum` and `ftr`. Two things it could not show:

- It has no comment parts, only an authors part. Comment extraction has
  never been compared with a deck PowerPoint saved.
- `hdr` and `dt` placeholders occur only on its notes master, never on a
  notes page, so the rule that notes omit them is untested on real output.

By reading: `docs/nodes/extract_pptx.md` states that only legacy comments
(`comments` relationships, `commentAuthors`) are parsed and that modern
comments are not supported. Current PowerPoint writes modern comments, so a
deck commented today is expected to return no comments at all. Not
reproduced: no such deck was available.

## Sample run of 2026-11-17

A one-slide deck saved by PowerPoint for the web, with made-up text, was
compared with its package XML in all three formats. The file stays outside
the repository.

- **Modern comments return nothing, as the node page predicts.** The comment
  and its reply are stored in `ppt/comments/modernComment_*.xml`
  (`p188:cmLst`, `p188:cm`, `p188:replyLst`, text in `p188:txBody`), linked
  from the slide by the `http://schemas.microsoft.com/office/2018/10/relationships/comments`
  relationship, with authors in `ppt/authors.xml`. `comments_key` returned an
  empty array and no slide carries a comment. Reproduced.
- **Slide furniture is left out, as IF-228 intends.** The slide holds `ftr`
  and `sldNum` placeholders from "Apply to All"; neither appears in any format.
- **Notes hold the body text only.** The notes page has `sldImg`, `body` and a
  `sldNum` placeholder with a `slidenum` field; only the body text is returned.

- **Metadata is read correctly.** The deck stores core properties at
  `docProps/core.xml`, named by the package relationship, so the IF-225 (a)
  fix does not change its output: its title, creator and last-modified-by
  elements are empty, so only `created`, `modified`, `revision` and
  `slide_count` are returned, before and after.

Still not covered: PowerPoint for the web offers no notes-page header or date
setting, so `hdr` and `dt` on a notes page remain untested on real output, and
no legacy comment was available.

## Required outcome and acceptance

Needs a `.pptx` saved by PowerPoint with made-up text that has slide
comments (one from a current version, and a legacy one if obtainable) and a
notes page on which the header and date placeholders are switched on.

Acceptance: compare `extract_pptx` output with the package XML and record
the structure here. Notes must hold the body text only. If modern comments
come back empty, either support them (author, date, text, replies) with a
hand-built fixture and failing-first regression, or record the maintainer's
decision to keep them unsupported and make the node page say what a caller
sees.

## Modern comments: outcome and validation

Decided by the maintainer on 2026-11-17: support modern comments.
`extract_pptx` now reads the slide's modern `comments` relationship
(MS-PPTX 2.16.3, `p188:cmLst`) and the presentation's modern `authors`
relationship. Element and attribute names were checked against the deck
above and the published schema (`cm` and `reply` with `id`, `authorId`,
`created`, `status`; `ST_CommentStatus` is `active`, `resolved` or `closed`).

Contract boundary:

- A modern comment returns `id`, `author_id`, `author`, `initials`, `date`
  (from `created`), `status` when present, `text` and nested `replies`; the
  flat `comments_key` array has one entry per comment, not per reply. Text
  and Markdown print replies under their comment and show the status.
- A slide with a modern comments part reports only those; its legacy part
  must be internal and present but is not read, because the formats share
  no identifier to deduplicate by. Legacy-only slides are unchanged.
- An unknown author ID or a missing author list keeps `author_id` only.
  External, escaping, missing or duplicated modern relationships are errors,
  as for legacy parts; the part root must be `cmLst`.
- Parsing runs under the existing ZIP, XML event, item and output budgets
  and checks cancellation per event; replies and the flat copy are charged.

Regressions, failing first (all 7 failed before the change: no comments
returned, or the legacy copy returned): `tests/test_pptx_modern_comments.rs`
on hand-built decks — a comment with a reply in PowerPoint's element order
(reply list before the text body), a resolved comment, an unknown author, no
author list, both formats on one slide and on different slides, hostile
comment and author targets, and malformed or ambiguous parts.
`tests/test_extract_pptx_limits.rs` adds item and output budget cases.

Checked on the deck of the 2026-11-17 run, read in place: one comment with
one nested reply in all three formats, author name and initials resolved,
no `status` attribute in the file, and text lengths equal to the package XML.

Validation, default features: `documents` 253 passed (3 ignored), `nodes`
336, `examples` 12, the 43 extraction tests of `serial`, 115 extraction unit
tests, the 4 PPTX tests of `cli`, the changed example run and validated,
formatting, the module-size check and
`cargo clippy --all-targets -- -D warnings`. Not run: the integration gate
and feature-enabled suites.

`examples/fixtures/ironflow-sample.pptx` now carries one hand-built modern
comment thread on slide 1 (a comment and one reply), so
`examples/08-extraction/extract_pptx.lua` checks the nested reply on real
output. The deck still renders with Quick Look, and `SHA256SUMS` records the
new bytes.

## Still open

Not producible from the samples available: a notes page with the header and
date placeholders switched on (PowerPoint for the web has no such setting),
so the rule that notes omit `hdr` and `dt` is still untested on real output,
and no legacy comment saved by a real PowerPoint has been compared. Both
need a deck from desktop PowerPoint.
