# IF-226 — Verify extract_pptx comments and notes header and date placeholders against a PowerPoint deck

## Evidence and boundary

Split from IF-222 (f) on 2026-11-16. Verification that could not be done,
plus one gap known from the documentation.

The deck in the sample run of 2026-11-16 (PowerPoint 16, 86 slides, 83
notes pages) confirmed what IF-193 assumed about notes pages for `sldImg`,
`body`, `sldNum` and `ftr`. Two things it could not show:

- It has no comment parts, only an authors part. Comment extraction has
  never been compared with a deck PowerPoint saved.
- `hdr` and `dt` placeholders occur only on its notes master, never on a
  notes page, so the rule that notes omit them is untested on real output.

By reading: `docs/nodes/extract_pptx.md` states that only legacy comments
(`comments` relationships, `commentAuthors`) are parsed and that modern
comments are not supported. Current PowerPoint writes modern comments, so a
deck commented today is expected to return no comments at all. Not
reproduced: no such deck was available.

## Required outcome and acceptance

Needs a `.pptx` saved by PowerPoint with made-up text that has slide
comments (one from a current version, and a legacy one if obtainable) and a
notes page on which the header and date placeholders are switched on.

Acceptance: compare `extract_pptx` output with the package XML and record
the structure here. Notes must hold the body text only. If modern comments
come back empty, either support them (author, date, text, replies) with a
hand-built fixture and failing-first regression, or record the maintainer's
decision to keep them unsupported and make the node page say what a caller
sees.
