# IF-121 — Redis lease-aware mutations partially commit before type errors

## Required outcome and acceptance

- Preflight types and arguments for every key touched by lease status, lease renewal, and deletion before any mutation.
- On WRONGTYPE, preserve primary data, revision, indexes, lease deadlines, TTLs, and deletion state.
- Exercise compiled storage APIs on disposable Redis with required-test flags and faulted secondary keys; retain ordinary CAS and lease-expiry coverage.

## Evidence and cause

Fresh review on 2026-09-12, finding R16. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: lease_status.lua:52](../../src/storage/redis_store/scripts/lease_status.lua), [renewal: lease_renew.lua:33](../../src/storage/redis_store/scripts/lease_renew.lua), [deletion: delete.lua:71](../../src/storage/redis_store/scripts/delete.lua).

Unchecked wrong-type catalog/lease keys fail only after primary/index mutation. Unchanged production scripts on disposable Redis 8.10.1 changed status/revision, renewed a deadline without refreshing TTL, or deleted the primary before returning WRONGTYPE. Ordinary CAS correctly rejected an equivalent fault without mutation. Preflight every touched key's type and argument before writes. Evidence is actual Redis script execution, not a compiled Rust API test; the disposable container was removed.

## Progress

Open. Implementation and regression validation are pending.
