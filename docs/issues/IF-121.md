# IF-121 — Redis lease-aware mutations partially commit before type errors

## Required outcome and acceptance

- Preflight types and arguments for every key touched by lease status, lease renewal, and deletion before any mutation.
- On WRONGTYPE, preserve primary data, revision, indexes, lease deadlines, TTLs, and deletion state.
- Exercise compiled storage APIs on disposable Redis with required-test flags and faulted secondary keys; retain ordinary CAS and lease-expiry coverage.
- Include the same lease-index preflight in stale-index sweeping used by listing and reconciliation.

## Evidence and cause

Fresh review on 2026-09-12, finding R16. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: lease_status.lua:52](../../src/storage/redis_store/scripts/lease_status.lua), [renewal: lease_renew.lua:33](../../src/storage/redis_store/scripts/lease_renew.lua), [deletion: delete.lua:71](../../src/storage/redis_store/scripts/delete.lua).

Unchecked wrong-type catalog/lease keys fail only after primary/index mutation. Unchanged production scripts on disposable Redis 8.10.1 changed status/revision, renewed a deadline without refreshing TTL, or deleted the primary before returning WRONGTYPE. Ordinary CAS correctly rejected an equivalent fault without mutation. Preflight every touched key's type and argument before writes. Evidence is actual Redis script execution, not a compiled Rust API test; the disposable container was removed.

Follow-up reproduction on 2026-09-14 confirmed the same missing lease-index
type check in `scripts/sweep.lua`: compiled `list_runs` removed a stale Set
member before failing against a wrong-type lease-expiry index. This shared
cleanup path is included in the same preflight fix.

## Outcome and validation

Resolved on 2026-09-14. Lease status, renewal, deletion, and stale-index sweep
scripts now validate their key types, distinct key identities, argument counts,
and applicable numeric arguments before writing. Status/release/owner-guard
arguments are checked before stale lease-index cleanup. Retention uses the
existing bounded seconds policy; persisted deadlines and computed lease
windows are checked against Lua's exact integer range. TTL calculations happen
before mutation and expiration commands receive decimal integer strings.

The Rust storage API, key layout, revision/incarnation fencing, 90-second lease
and safety policy, live-owner deletion conflict, terminal retention, and
persistent behavior without a configured TTL are unchanged. Preflight errors
use the existing typed storage-corruption mapping. These checks prevent
deterministic type/argument failures from partially writing; they do not add
rollback for arbitrary Redis server, memory, or ACL failures, nor a transaction
across separate state and event operations.

Validation used freshly pulled Redis 8.10.1 in disposable container
`ironflow-if121-20260914-41b0773`, bound only to loopback with a temporary data
filesystem. Every live test command set `IRONFLOW_REDIS_TEST_URL` to that
instance and `IRONFLOW_REDIS_TEST_REQUIRED=1`; no live test was skipped.

- Before the fix, four of the initial five compiled regression tests failed:
  owned writes, reconciliation, renewal, and deletion altered durable keys.
  The ordinary CAS control passed. A subsequent compiled listing regression
  separately reproduced the stale-index sweep failure before its fix.
- After the fix, 14 new regression tests passed. Their fault matrices cover
  every secondary script key, primary-type and deadline corruption, normal and
  terminal owned writes, task/context updates, expired reconciliation,
  persistent/expiring renewal, terminal/expired/missing deletion, and listing
  cleanup. Full key payloads and absolute expiry timestamps are compared with
  `DUMP` and `PEXPIRETIME`, including neighboring runs and corrupt index keys.
- Direct production-script probes additionally cover invalid arity, aliases,
  malformed/overflowing numeric arguments, missing/ownerless cleanup,
  revision/incarnation/owner guards, and successful TTL boundary behavior.
- All 18 tests in `test_redis_store` passed. The `state` filter in
  `test_redis_atomicity` passed 18 tests, and its `ttl::` filter passed three
  tests (one overlaps the state selection). Together with the new tests this
  is 52 distinct live tests. The Redis TTL configuration unit test also passed:
  53 distinct focused tests total.
- `cargo fmt --all -- --check`, `python3 -B scripts/check_module_size.py`,
  `cargo clippy --all-targets -- -D warnings`,
  `cargo clippy --all-targets --features redis -- -D warnings`, and
  `cargo audit --deny warnings` passed on current stable Rust 1.98.1. No module
  size exceptions or dependencies changed.
- The disposable Redis container was stopped and its automatic removal
  verified. The pre-existing PostgreSQL container was left untouched.

CLI/storage and architecture documentation describe the preflight boundary.
There is no new Lua workflow API or example requirement. Validation was local
and feature-enabled, not a deployed CLI/serve smoke test or full release gate.
No commit of this issue or push was performed.
