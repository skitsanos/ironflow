# IF-245 — A small task output cap breaks replay of completed API requests

## Evidence and boundary

Reviewed 2026-11-19 on local `develop` at `ae1f686`.

`src/engine/executor/output.rs:125` applies the per-value output cap to final context entries, including the internal 64-character idempotency fingerprint. At a valid cap of 32 bytes it is persisted as a truncation object. `src/api/idempotency.rs:74` expects the stored marker to be a string, so an identical request can be misclassified as a conflict after completion. Source inspection.

## Required outcome and acceptance

Keep replay metadata independent of user-output truncation. With the cap set to 32, a completed request retried with identical input must return its original run ID. Changed input with the same key must still conflict. Verify ordinary output remains bounded.
