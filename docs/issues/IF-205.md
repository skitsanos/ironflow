# IF-205 — Pre-commit hook rejects linked-worktree commits that stage policy tests

## Evidence and boundary

Found on 2026-10-29 and again on 2026-11-12, on `develop` at 1.21.1-dev.1.

- A commit made from a linked worktree was rejected by `.githooks/pre-commit`
  whenever a staged path matched the hook's automation pattern (`.githooks/`,
  `.codex/`, `scripts/tests/` and the scripts they cover). The hook's
  `bun test scripts/tests/*.test.ts` step ended with 81 passed and 2 failed,
  both in `scripts/tests/gate_receipt.test.ts`, with `the worktree has
  uncommitted changes, so no commit describes what the gate validated`.
- Cause: git exports repository-scoped variables to the hooks it runs. From a
  linked worktree `GIT_INDEX_FILE` is an absolute path. The `git` helper in
  `scripts/gate_receipt.ts` spawned git with the inherited environment, so
  `writeReceipt` on a test's disposable repository read the index of the
  worktree being committed and saw its staged changes. The test fixtures
  already stripped `GIT_*`; the production helper did not.
- From the main checkout the exported index path is relative, so the same
  commit passed. Outside a hook the tests passed 4 of 4.
- Consequence: the 2026-10-29 license-notices commit was made with the hook
  bypassed, and on 2026-11-12 a dependency fix could not be committed from its
  worktree and was committed from the main checkout instead.

Boundary: only commits from linked worktrees that stage those paths were
affected. The receipt logic itself, the pre-push check and the integration
gate behaved correctly. Related: IF-172 (introduced the receipt).

## Required outcome and acceptance

- A git command that `scripts/gate_receipt.ts` aims at an explicit repository
  must describe that repository whatever the calling hook exported.
- A regression that fails without the fix, and a real commit from a linked
  worktree that stages a policy test and passes the hook unmodified.

## Outcome and validation

Resolved on 2026-11-12.

- `scripts/gate_receipt.ts` exports `REPOSITORY_SCOPED_GIT_VARIABLES` (the
  names `git rev-parse --local-env-vars` reports) and
  `repositoryNeutralEnvironment`, and its `git` helper runs with the caller's
  environment minus those variables. Other settings, such as
  `GIT_SSH_COMMAND`, are kept.
- Regressions in `scripts/tests/gate_receipt.test.ts`: a receipt is written
  and accepted for a clean repository while `GIT_INDEX_FILE` and `GIT_DIR`
  point at another repository with staged changes; and the removed list must
  cover every variable git reports and remove nothing else.

Contract boundary: `scripts/development_version.ts` also runs git, but against
the repository the hook belongs to, so it keeps the inherited environment. No
hook, gate or receipt format changed.

Validation, policy tests only (no Rust change):

- Before the fix: the new behaviour test failed outside a hook, and a commit
  of that test alone from a linked worktree was rejected by the hook with
  three failures (the two existing tests and the new one).
- After the fix: `bun test scripts/tests/gate_receipt.test.ts` 6 passed, also
  with an absolute foreign `GIT_INDEX_FILE` exported; the fix itself was
  committed from the same linked worktree through the unmodified hook (35
  Python tests, 85 Bun tests, 0 failed).
- Not run: the full integration gate, and a pre-push from a linked worktree.
