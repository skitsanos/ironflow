# IF-198 — An empty IRONFLOW_API_KEY disables the configured API key on loopback

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12, reproduced against a local
`ironflow serve` bound to `127.0.0.1` with `api_key` set in `ironflow.yaml`.

| Environment | `GET /runs` without a key |
|---|---|
| `IRONFLOW_API_KEY` unset | 401 |
| `IRONFLOW_API_KEY=` (present, empty) | 200 |

- In the second case the server logs `API authentication is not configured;
  allowing unauthenticated loopback server` and serves every route,
  including `POST /flows/run`.
- `environment_string` returns `Some("")` for a present variable, so the
  YAML fallback is skipped (`src/cli/resolution.rs:83-91, 133`).
  `build_api_auth` trims and discards the empty key, then permits a loopback
  bind without one (`src/api/mod.rs:151-176`).
- An empty value is a common artefact of a compose file, an orchestrator
  secret that failed to resolve, or a `.env` placeholder.

Boundary: on a non-loopback bind, startup fails without a key, so that case
is safe. The exposure is a loopback bind behind a reverse proxy or sidecar on
the same host, where the operator believes the YAML key is enforced. IF-018
set the rule that an invalid higher-priority value fails rather than falling
through; an empty key is not covered by it.

## Required outcome and acceptance

- Treat a present but empty or whitespace-only `IRONFLOW_API_KEY` (and the
  equivalent CLI or YAML value) as a startup error naming the source, unless
  `IRONFLOW_ALLOW_UNAUTHENTICATED_API=true` is set explicitly.
- Apply the same rule to other secret-bearing settings resolved through
  `environment_string` where an empty value silently changes behaviour, and
  list which ones were checked.
- Regressions: empty and whitespace-only values fail startup; unset falls
  back to YAML; an explicit unauthenticated opt-in still works.
- Document the rule in the configuration precedence section of
  `docs/CLI_REFERENCE.md`.

## Outcome and validation

Resolved on 2026-11-14. Rule: a setting that is present but empty or
whitespace-only is neither unset nor a value; startup fails with a message
naming the source (the variable or the config field), never a value.

- `src/cli/presence.rs` holds the rule. `resolve_api_key` takes the
  environment value when the variable is present, else `api_key`; a blank
  winner fails unless the unauthenticated opt-in resolves to `true` (variable
  or config field), in which case it means no key.
- `build_api_auth` (`src/api/mod.rs`) refuses a blank key on every bind
  address unless the opt-in is set, so a library caller of `serve` cannot
  reach the loopback allowance with a blank key either.
- `serve` has no API key flag, so there is no CLI form to cover.

Settings checked (reproduced with a debug binary unless marked "read"):

| Setting | Before | Result |
|---|---|---|
| `IRONFLOW_API_KEY` blank | 200 without a key on loopback | fixed: fails |
| `api_key` blank in config | unauthenticated on loopback | fixed: fails |
| `IRONFLOW_CORS_ORIGINS` blank or only separators | replaced configured origins with none | fixed: fails |
| `IRONFLOW_SQL_TABLE_PREFIX` blank | replaced configured prefix with the default | fixed: fails |
| `REDIS_PREFIX` blank (read) | unprefixed keys | fixed: fails |
| `REDIS_URL` blank (read) | passed to the client | fixed: fails with the name |
| `IRONFLOW_STORE`, `IRONFLOW_EVENT_STORE` blank | failed, variable not named | now named |
| `IRONFLOW_STORE_URL`, `IRONFLOW_EVENT_STORE_URL` blank | failed, named | unchanged |
| `IRONFLOW_ALLOW_UNAUTHENTICATED_API`, `IRONFLOW_METRICS_ENABLED` blank; other booleans and numbers (read) | failed, named | unchanged |
| `HOST`, `PORT`, `MAX_BODY`, `FLOWS_DIR`, `IRONFLOW_STORE_DIR` blank | failed at parse or bind | unchanged |
| `IRONFLOW_ARTIFACT_BACKEND`, `IRONFLOW_ARTIFACT_S3_*` (read) | rejected on first artifact use | unchanged |
| Webhook `secret_env` variable (read) | under 16 bytes fails startup | unchanged |
| `IRONFLOW_ENV_ALLOWLIST` blank | denies every key, documented | unchanged on purpose |
| `sql_table_prefix`, `redis_prefix`, `cors_origins: []` in config | default prefix, unprefixed keys, no origins | unchanged on purpose: typed deliberately, nothing overridden |
| `IRONFLOW_ARTIFACT_DIR` blank | server starts | not changed: outside this layer |

There are no TLS settings in this resolution layer; store TLS is part of the
store URL.

Boundary: a loopback bind with no key configured anywhere still starts
unauthenticated, and a non-loopback bind without a key still fails. A blank
`IRONFLOW_API_KEY` with the opt-in set serves unauthenticated even when
`api_key` is configured. Settings read lazily by nodes and the artifact store
are not validated at startup. A `secret_env` variable of 16 or more spaces is
accepted.

Evidence, debug build, probe directory with `api_key` in `ironflow.yaml`,
`serve` on `127.0.0.1`, empty environment:

| Case | Before | After |
|---|---|---|
| variable unset | 401 without key, 200 with | same |
| `IRONFLOW_API_KEY=` | 200 without key | exit 1, variable named |
| `IRONFLOW_API_KEY` of three spaces | 200 without key | exit 1, variable named |
| blank key with the opt-in `true` | 200 | 200, "disabled by explicit configuration" logged |
| `IRONFLOW_CORS_ORIGINS=`, `IRONFLOW_SQL_TABLE_PREFIX=` | server starts | exit 1, variable named |
