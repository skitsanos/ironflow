# IF-162 — One integration test binary per test file drives disk and CI compensation

## Evidence and boundary

Audit of `develop` at 1.20.1-dev.6 on 2026-10-28.

- `cargo metadata` reports 177 `test` targets plus the lib, bin and example
  (180 selections). `tests/` holds 1,371 test functions, fewer than eight per
  binary on average; many binaries hold one to three tests.
- Every test binary links the whole `ironflow` library and its 571 reachable
  crates (AWS SDK, pdfium-render, parley/krilla, image, mlua, sqlx,
  tree-sitter, rmcp).
- Compensation that exists only because of this layout:
  `scripts/test_rust_targets.ts` runs batches of eight targets (23 `cargo test`
  invocations per suite) and deletes each batch's executables;
  `scripts/integration_gate.sh` exports `CARGO_INCREMENTAL=0` and runs
  `cargo clean --package ironflow` before, between and after phases;
  `.github/workflows/ci.yml` sets `CARGO_BUILD_JOBS=2`, `line-tables-only`
  debug info and `cache-targets: false` on every `Swatinem/rust-cache` step so
  no target artifacts are cached; `AGENTS.md` documents reclaiming linked test
  executables to avoid "tens of gigabytes"; `scripts/tests/rust_targets.test.ts`,
  `integration_cleanup.test.ts`, `ci_resources.test.ts` and parts of
  `repository_policy.test.ts` test that machinery.
- Measured cost (CI run 40705138098 on `develop`, 2026-10-28): Clippy and
  tests 11.5 min, feature job 12.8 min with `--test-threads=1` over every
  target, macOS 17.1 min; 51.7 runner-minutes and about 17 min wall. A
  default debug build's `target/` directory is about 12 GB.

Boundary: on macOS the Apple linker leaves DWARF in object files, so a linked
test binary (`test_types`) is about 3.3 MB there; the executable bloat is a
Linux property (CI runners and containers). Test coverage itself is good; the
finding is layout and its downstream cost.

Additional evidence, 2026-10-28, during IF-161 validation: a plain
`cargo test --all-targets` with default incremental settings grew the
`target/` directory from about 12 GB to 38 GB (29 GB under `deps`, 5 GB under
`incremental`) and failed while linking six test binaries once the disk
filled. `cargo clean --package ironflow` afterwards reclaimed about 27 GB.
The per-binary object and incremental artifacts, not only the Linux
executables, scale with the 177 targets.

## Required outcome and acceptance

- Consolidate `tests/` into a bounded set of binaries (target: at most ten),
  for example `tests/engine/main.rs`, `tests/storage/main.rs`,
  `tests/nodes_*/main.rs`, `tests/api/main.rs`, `tests/cli/main.rs` and
  `tests/examples/main.rs`, each including the existing files as modules.
  Keep `tests/support` shared. Keep storage and TLS tests in their own
  binaries so the feature job can run only those.
- The test function count must not decrease, test names stay greppable, and
  `cargo test --test <area>` selects one area.
- Afterwards: delete or reduce `scripts/test_rust_targets.ts` to a thin
  wrapper, drop the repeated `cargo clean` phases and the `CARGO_BUILD_JOBS=2`
  throttle, re-enable target caching in CI, and update `AGENTS.md`, the
  validation docs and the script tests.
- Resolution evidence: before/after `cargo metadata` target counts, CI job
  timings over at least three `develop` pushes, and peak `target/` size on a
  Linux runner.
