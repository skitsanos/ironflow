# IF-193 — Document extraction garbles PDF metadata and drops DOCX paragraph text around text boxes

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12. Items 1 and 2 were
reproduced with a local optimized build on hand-built fixtures; item 3 is by
reading.

1. PDF Info strings. A PDF whose `/Title` is the UTF-16BE text string for
   "Müller Report" (`<FEFF...>`) comes back from `pdf_metadata` as two
   replacement characters followed by NUL-interleaved letters; `/Producer`
   likewise. An ASCII `/Author` is correct. Both
   `src/nodes/image/pdf_metadata.rs:34-38` and
   `src/nodes/extract/pdf.rs:215-218` decode with `String::from_utf8_lossy`,
   while `/ActualText` is decoded correctly with `lopdf::decode_text_string`
   (`pdf/text_output.rs:117`). UTF-16 Info strings are common in
   office-exported PDFs. The embedded NUL characters also enter run context;
   PostgreSQL rejects NUL in text and JSON values (not tested).
2. DOCX text boxes. A paragraph `BEFORE-BOX [anchored text box: INSIDE-BOX]
   AFTER-BOX` extracts as `INSIDE-BOX` only; both runs of the host paragraph
   are lost. `BlockBuilder`
   (`src/nodes/extract/docx_parser/blocks.rs:75-83, 198-216`) keeps one flat
   paragraph and run state, so the nested `w:p` inside `w:txbxContent`
   resets it and its end tag clears `in_paragraph`.
   In the same fixture a run with `<w:b w:val="0"/><w:i w:val="false"/>` is
   emitted as bold italic (`***explicitly-not-bold***`): toggle properties
   are treated as on whenever present (`blocks.rs:157-160`).
3. PPTX speaker notes. `parse_pptx_notes`
   (`src/nodes/extract/pptx_parser/notes.rs:27-40`) appends the text of every
   `t` element in the notes part. A notes slide normally also carries a
   slide-number placeholder field, so notes for slide 3 would end with "3",
   and a slide with no notes would report "3" instead of none. The slide
   parser skips fields; the notes parser does not. Existing tests use
   synthetic notes with body text only.

Boundary: silent wrong or missing text, no crash. Item 3 needs a deck
authored in a presentation tool to confirm. Related: IF-115, IF-156.

## Required outcome and acceptance

- Decode Info strings with `lopdf::decode_text_string` in both nodes and
  dereference indirect values in `pdf_metadata`.
- Keep a paragraph and run stack in the DOCX block builder so host text
  survives a nested text box; emit box paragraphs as separate blocks, once
  (skip `mc:Fallback`). Honour `w:val` on toggle properties.
- Collect notes text from the body placeholder only, skipping field runs and
  number, date, header and footer placeholders.
- Fixtures and regressions for each, including a tool-authored PPTX with
  notes.

## Outcome and validation

Resolved on 2026-11-13. All fixtures are hand-built in test code (lopdf
objects, raw `word/document.xml`, raw PresentationML parts). No tool-authored
PPTX was available: the notes placeholder layout matches the notes parts of
`examples/fixtures/ironflow-sample.pptx`, while field runs and the header,
date and footer placeholders follow the PresentationML schema only.

1. PDF Info strings. `pdf_metadata` and `extract_pdf` share one decoder built
   on `lopdf::decode_text_string` (0.47.0, read: UTF-16BE and UTF-8 by
   byte-order mark, otherwise PDFDocEncoding with undefined bytes dropped).
   lopdf rejects ill-formed UTF-16 or UTF-8, so those fall back to U+FFFD
   replacement. Values are trimmed; language-tag escapes and control
   characters other than tab, line feed and carriage return are removed, so
   NUL terminators cannot reach context. `pdf_metadata` dereferences the
   Info entry and each value. `extract_pdf` still fails on a non-string field.
2. DOCX. The block builder keeps a stack of open paragraphs, each with its
   own run and property state. A paragraph closed directly inside another is
   text-box content: it follows the anchoring paragraph as a separate block
   (in the same cell when anchored in a table), as does a table inside a
   box. `mc:Fallback` content is skipped. Empty `w:p`, `w:r`, `w:rPr`, `w:pPr`
   and table elements no longer leave state open. `w:b`, `w:i` and `w:strike`
   honour `0`/`false`/`off` and `1`/`true`/`on`; `w:u` is off for `none`.
   The previous properties under `w:rPrChange` and `w:pPrChange` are skipped
   like fallback content; they had replaced the current style, list state and
   run flags (reproduced by the failing regression before the change).
3. PPTX notes. Text is collected from the shape whose `p:ph` has
   `type="body"`, from `a:t` outside `a:fld`. Other placeholders, typeless
   placeholders and shapes without one are skipped. A notes part without any
   shape is read as before, which keeps the shapeless synthetic fixtures;
   one fixture that held its notes in a shape without a placeholder now
   declares the body placeholder.

Boundary: style inheritance of toggles and box position are not resolved;
skipping `mc:Fallback` applies to every alternate-content block, not only
text boxes; comment anchors inside a fallback are still observed; a
UTF-16LE mark and language tags in PDFDocEncoding strings are not handled.
Remaining fidelity gaps are tracked in [IF-222](IF-222.md).

Evidence, debug build, `ironflow run` on scratch copies of the fixtures:

- Before: `title` was `\ufffd\ufffd\u0000M\u0000\ufffd\u0000l...`, PDFDocEncoding
  `café •` was `caf\ufffd \ufffd`, a UTF-8 subject kept its mark, and
  `pdf_metadata` omitted an indirect `/Creator`. The DOCX gave
  `INSIDE-BOX\nINSIDE-BOX\n***explicitly-not-bold***` (twice because of the
  fallback copy). Notes for slides 1 to 3 ended with
  `HEADER-TEXT\n11/13/2026\nFOOTER-TEXT\n<slide number>`, and the slide
  without notes reported exactly that. This reproduces item 3, which the
  review had only read.
- After: `Müller Report`, `café •`, `Größe`, `Indirect Créateur` from both
  nodes; `BEFORE-BOX  AFTER-BOX\nINSIDE-BOX\nexplicitly-not-bold`; notes
  `First note line\nPage  remark`, none, `Third slide note`.
- Failing first: 10 of the 12 new node tests failed on the unfixed sources;
  the two that passed assert unchanged sample-fixture output.
- Existing fixtures: the sample PDF and PPTX extract identically before and
  after. The sample DOCX changes as intended: its table body cells carry
  `<w:b w:val="0"/>` and are no longer bold, and the test that pinned
  `| **Engine** | **IronFlow** |` was corrected.
- Passing: library 737 (1 ignored), `documents` 166 (3 ignored) and 168 with
  `cjk-fonts`, `nodes` 265, `examples` 11, `serial` 191 single-threaded,
  `extract_execution` 2, the four deck tests in `cli`; the four extraction
  examples validate; formatting, module-size check and
  `cargo clippy --all-targets -- -D warnings` clean.
- Not run: a deck or document saved by an office application, PostgreSQL
  storage of the former NUL values, and the integration gate.
