# IF-193 — Document extraction garbles PDF metadata and drops DOCX paragraph text around text boxes

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12. Items 1 and 2 were
reproduced with a local optimized build on hand-built fixtures; item 3 is by
reading.

1. PDF Info strings. A PDF whose `/Title` is the UTF-16BE text string for
   "Müller Report" (`<FEFF...>`) comes back from `pdf_metadata` as two
   replacement characters followed by NUL-interleaved letters; `/Producer`
   likewise. An ASCII `/Author` is correct. Both
   `src/nodes/image/pdf_metadata.rs:34-38` and
   `src/nodes/extract/pdf.rs:215-218` decode with `String::from_utf8_lossy`,
   while `/ActualText` is decoded correctly with `lopdf::decode_text_string`
   (`pdf/text_output.rs:117`). UTF-16 Info strings are common in
   office-exported PDFs. The embedded NUL characters also enter run context;
   PostgreSQL rejects NUL in text and JSON values (not tested).
2. DOCX text boxes. A paragraph `BEFORE-BOX [anchored text box: INSIDE-BOX]
   AFTER-BOX` extracts as `INSIDE-BOX` only; both runs of the host paragraph
   are lost. `BlockBuilder`
   (`src/nodes/extract/docx_parser/blocks.rs:75-83, 198-216`) keeps one flat
   paragraph and run state, so the nested `w:p` inside `w:txbxContent`
   resets it and its end tag clears `in_paragraph`.
   In the same fixture a run with `<w:b w:val="0"/><w:i w:val="false"/>` is
   emitted as bold italic (`***explicitly-not-bold***`): toggle properties
   are treated as on whenever present (`blocks.rs:157-160`).
3. PPTX speaker notes. `parse_pptx_notes`
   (`src/nodes/extract/pptx_parser/notes.rs:27-40`) appends the text of every
   `t` element in the notes part. A notes slide normally also carries a
   slide-number placeholder field, so notes for slide 3 would end with "3",
   and a slide with no notes would report "3" instead of none. The slide
   parser skips fields; the notes parser does not. Existing tests use
   synthetic notes with body text only.

Boundary: silent wrong or missing text, no crash. Item 3 needs a deck
authored in a presentation tool to confirm. Related: IF-115, IF-156.

## Required outcome and acceptance

- Decode Info strings with `lopdf::decode_text_string` in both nodes and
  dereference indirect values in `pdf_metadata`.
- Keep a paragraph and run stack in the DOCX block builder so host text
  survives a nested text box; emit box paragraphs as separate blocks, once
  (skip `mc:Fallback`). Honour `w:val` on toggle properties.
- Collect notes text from the body placeholder only, skipping field runs and
  number, date, header and footer placeholders.
- Fixtures and regressions for each, including a tool-authored PPTX with
  notes.
