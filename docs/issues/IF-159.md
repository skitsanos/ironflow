# IF-159 — Font-only changes do not trigger container publication

## Evidence and boundary

The Markdown document generators embed fonts from `assets/fonts`, and the
Dockerfile copies `assets` into the build. The container workflow's push-path
filter excludes that input, so an asset-only update on main/develop can leave
the published image stale. The existing document candidate included Cargo,
source and Dockerfile changes and did trigger publication; this is a future
asset-only update gap, not evidence that the checked image was stale.

## Required outcome and acceptance

- Include `assets/**` in the container workflow's existing push-path filter.
- Retain branch restrictions and runtime storage acceptance before publication.
- Add a structured workflow regression and validate workflow syntax.

## Outcome and validation

The existing push-path filter now includes `assets/**`, covering bundled fonts
and future build assets on main/develop. Branch restrictions and the storage
acceptance-before-publication order are unchanged. The structured Bun workflow
regression failed before the fix and passes afterward; actionlint passed.
This qualifies trigger configuration, not a claim that a font-only commit was
published to a deployment. Release and deployment acceptance remain separate.
