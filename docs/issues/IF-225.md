# IF-225 — Verify extract_word against a document saved by Word or LibreOffice

## Evidence and boundary

Split from IF-222 (f) on 2026-11-16. Nothing here is a reproduced defect:
it is verification that could not be done.

The DOCX behaviour fixed under IF-193 and IF-222 is covered by hand-built
fixtures and by two tool-authored files (pandoc and `textutil`). The one
real document available in the sample run of 2026-11-16 was written by a
generator library, not by an office suite: it has no text box, no comment
on a range, no tracked change, no header, footer or footnote text. So the
structures those fixes handle have never been compared with what Word or
LibreOffice actually writes.

## Sample run of 2026-11-17

A document saved by Word for the web, with made-up text, was compared with
its package XML in all three formats. Word for the web cannot insert a text
box, so the box came from a minimal hand-built base document that Word then
re-saved; every other structure was made in Word. The file stays outside the
repository.

Read as expected: the text box (`mc:AlternateContent` with `wps:txbx` and the
VML fallback) is read once, after its anchoring paragraph; a comment range
that spans the box returns the box text in `anchored_text`; the tracked
insertion is kept and the tracked deletion dropped; the italic added under
`w:rPrChange` is reported as current formatting; bold that comes only from the
`Strong` character style is reported as bold.

Reproduced defects:

- **(a) Metadata is empty.** Word for the web writes core properties to
  `package/services/metadata/core-properties/<id>.psmdcp`, named by the
  package relationship, not to `docProps/core.xml`. `extract_word` (and
  `extract_pptx`) read only the fixed path, so `metadata_key` returns `{}`.
- **(b) Markdown emphasis breaks on Word's run splits.** Each run is wrapped on
  its own, including its surrounding spaces, so adjacent italic runs and an
  italic run holding one space produced `*finished**units** *`, and a bold run
  ending in a space produced `**expects **`, which CommonMark does not read as
  emphasis.
- **(c) Header, footer and footnote text are not extracted** in any format,
  and the node page does not say so. The parts and the `w:footnoteReference`
  are present in the package.

Not covered by this file: a comment inside the text box (Word for the web
cannot edit inside it).

## Required outcome and acceptance

Needs a `.docx` saved by Word or LibreOffice that contains, with made-up
text:

- a text box (`mc:AlternateContent` with `wps:txbx` and the VML fallback),
- a comment anchored on a range, ideally one around or inside the text box,
- a tracked formatting change (`w:rPrChange`) and a tracked insertion and
  deletion,
- a header, a footer and a footnote,
- bold or italic that comes only from a paragraph or character style.

Acceptance: run `extract_word` in each format and compare with the package
XML; record the structural facts here; fix each defect found with a
hand-built fixture and a failing-first regression. If the file may be
committed, add it under `examples/fixtures/` and to
`test_tool_authored_documents`. Close when the comparison is recorded, with
or without defects.

## Outcome and validation

Resolved on 2026-11-17 for everything Word for the web can produce. Each
defect has a hand-built fixture whose tests failed on the unfixed tree.

**Decisions.**

- Footnotes and endnotes are on by default (`notes = true`); headers and
  footers are page furniture, read only with `headers_footers = true`, as
  slide furniture is left out under IF-228.
- Note labels follow reference order (`1`, `2`; endnotes `e1`, `e2`), not the
  `w:id`: the sample's only footnote has id 6857.

**Outcome.**

- (a) `extract_word` and `extract_pptx` take the core-properties part from
  the package relationship in `_rels/.rels`, falling back to
  `docProps/core.xml`. The OPC relationship parser and target resolution
  moved from the PPTX reader into the shared OOXML module, so the target is
  internal, scheme-free and kept inside the package. No other OOXML reader
  reads core properties.
- Found while confirming (a): both parsers matched core-property fields by
  prefix. Word for the web writes `lastModifiedBy` unprefixed in the default
  namespace, so it was dropped. Fields are now matched by namespace.
- (b) Markdown treats a paragraph's runs as one stream: equal emphasis
  shares one marker pair, whitespace stays outside markers, whitespace-only
  runs open none, and a change closes only the markers that end. This also
  applies in table cells and headings. Overlapping spans with no whitespace
  between them have no CommonMark form; the node page says so.
- (c) References become `[^label]` in every format. Notes follow the body as
  `[^label]: text`, or in JSON `footnotes` / `endnotes` with a `note` object
  on the run. Headers and footers come before and after the body, or in JSON
  `headers` / `footers`. Parts are resolved through
  `word/_rels/document.xml.rels`, and only referenced notes are kept.
- Follow-up on (c), same day: a reference with `w:customMarkFollows` gave
  `[^1]*`, because the custom mark that follows it in the run was copied
  after the marker. The mark is now kept as `mark` on the reference and the
  note in JSON instead. A hand-built fixture failed on the unfixed tree. A
  mark written as `w:sym` is not read.

**Contract boundary.** Text and Markdown of documents with note references
now contain markers and definitions; `notes = false` restores the old
output. A comment inside a text box was not producible (Word for the web
cannot edit inside a box) and stays covered only by the IF-222 fixtures.
IF-226 is unchanged: its deck stores core properties at
`docProps/core.xml`, and the empty title, creator and last-modified-by
elements there are why only dates and revision come back.

**Evidence.**

- Before: the new tests failed: 5 of 7 core-property tests, the namespace
  test, all 6 emphasis tests, and 7 of 8 note/header tests. The one that
  passed only checks that headers are absent by default.
- Sample re-run with the fixed build: metadata has `last_modified_by` and
  `modified`, which was `{}` before. Markdown rendered through
  `markdown_to_html` leaves no literal asterisk, with one `em` and one
  `strong`. The footnote is marked and defined in all three formats
  (label `1`). Header and footer each return a table and a paragraph from
  `word/header.xml` / `word/footer.xml`.
- After: `--test documents` 246 passed (3 ignored), `--test nodes` 336,
  `--test serial -- --test-threads=1` 199, `--test examples` 12,
  `cargo test --lib extract` 115. The text-fidelity fixtures now use the real
  core-property namespaces. The text-box test expected the defective
  `bold* then italic*`. `cargo fmt --check`, `check_module_size.py` and
  `cargo clippy --all-targets -- -D warnings` pass. Both changed Lua examples
  validate and run.
