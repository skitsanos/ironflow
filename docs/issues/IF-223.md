# IF-223 — Data transform follow-ups: YAML non-finite and large numbers, CSV formula cells, neq on a missing field

## Evidence and boundary

Recorded on 2026-11-14 from the sibling audit done while fixing IF-196.

- (a) Reproduced by that session: `yaml_parse` turns `.nan` and `.inf` into
  `null`, and integers above the signed 64-bit range into rounded floats.
  This is the loss IF-196 removed from `csv_parse`.
- (b) Reproduced: `csv_stringify` writes a cell that starts with `=` (also
  `+`, `-` or `@`, by reading) unchanged. A spreadsheet opens it as a
  formula, so exported untrusted text can execute as one.
- (c) Observed and now documented: in `data_filter`, an item without the
  field matches neither `eq` nor `neq`. IF-187 made `!=` the exact negation
  of `==` for guards; whether `neq` should include items that lack the field
  is undecided.

## Required outcome and acceptance

- (a) Keep such YAML scalars as strings or fail the step, matching the
  `csv_parse` rule, and document it.
- (b) Add an opt-in or default neutralization for formula-leading cells
  (prefix with a single quote or tab), documented in `csv_stringify`.
- (c) Decide and document; add a regression either way.
