# IF-260 — Child-flow recursion severity still depends on declaration order

## Evidence and boundary

Found on 2026-11-20 while validating the IF-246 fix. Reproduced with the CLI:
`root.lua` starts `a.lua` tolerantly; `a.lua` starts `b.lua` twice, once with
`on_error` and once unconditionally; `b.lua` always starts `a.lua`. With the
tolerant step declared first `ironflow validate` printed a warning and exited
0; with the two steps swapped it reported `a.lua -> b.lua -> a.lua always
starts itself again` and exited 1.

Cause: the walk in `src/cli/commands/validate/children.rs` skips a child it
has already visited at the same nesting level with the same whole-route
conditionality. Whether a cycle is certain depends only on the edges inside
the cycle, so two routes that are both conditional as a whole, but differ
below the cycle's start, shared one memo entry and the second was skipped.
The same happened without parallel edges, when one child was reached at one
depth through a tolerant and through an unconditional intermediate flow.

## Outcome and validation

- The memo key is the nesting level and the stack position of the deepest
  conditional edge on the route (0 when there is none). That position decides
  both the depth severity and the severity of every cycle that can close
  below it, so equal keys really are equal visits.
- A cycle is reported once: an error replaces an earlier warning for the same
  chain, and repeats are dropped. A cycle reachable at several depths was
  printed once per depth before.
- Contract boundary: validation work per file is bounded by the number of
  distinct keys, about half the square of `IRONFLOW_MAX_SUBWORKFLOW_DEPTH`
  (136 at the default of 16), where it was twice the limit. Depth warnings
  and errors, and which files are loaded, are unchanged.
- Regressions in `tests/test_validate_child_flows.rs`, both failing before
  the change and both run in each declaration order:
  `a_tolerant_route_does_not_downgrade_an_unconditional_cycle` and
  `an_unconditional_cycle_through_another_route_is_an_error_in_either_order`.
- Validation: the 11 tests of that module, default Clippy, `cargo fmt` and
  the module-size check. `docs/CLI_REFERENCE.md` states the rule.
