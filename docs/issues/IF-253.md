# IF-253 — Inconclusive verification can unlink a valid retained artifact

## Evidence and boundary

Reviewed 2026-11-19 on local `develop` at `ae1f686`.

`src/artifacts/publication.rs:21` treats every verification error as permission to enter the repair branch. `src/artifacts/integrity.rs` can return cancellation, read errors or a permissions error, none of which establishes a size or digest mismatch. The branch unlinks the existing regular file before installing its replacement. Readers may see a missing artifact; a subsequent replacement failure can leave it absent. Source inspection, not an observed loss of user data.

## Required outcome and acceptance

Distinguish confirmed corruption from inconclusive verification. Cancellation or I/O error must leave the existing file untouched. Deterministically interrupt verification of a duplicate publication and check the original remains readable and unchanged; retain repair coverage for actual corruption and test replacement failure.

## Outcome and validation

Verification now reports a size or digest mismatch separately from an error.
Only a mismatch permits repair, after a cancellation checkpoint. The publisher
hardens the staging file and renames it over the existing entry before syncing
the directory. No repair branch unlinks the destination. This is shared by
reader and seekable-writer publication and by verified remote cache restores;
there is no change to artifact references or workflow configuration.

Two regression tests failed under the old logic: cancellation at the existing
file's hash checkpoint returned success, and a failed replacement left no
file at the digest path. Both now pass. The tests also cover an unreadable
regular file and successful repair of read-only entries with the wrong size
or same-length wrong contents. Cancellation preserves the Unix inode, not
just the bytes; failure to rename preserves the old entry and its permissions.

On macOS, all 20 default Rust targets passed (2,791 tests passed, five
ignored), including the simulated S3 restore. Formatting, module-size
policy, and `cargo clippy --all-targets -- -D warnings` passed.
No native Windows or live S3 run was performed.
