# IF-118 — Child context overwrites authoritative parallel-result metadata

## Required outcome and acceptance

- Keep authoritative child success, flow identity, and related result metadata outside child-controlled overwrite paths.
- Preserve documented result shape or explicitly document a compatible namespacing/reserved-key contract.
- Test successful and failed children publishing colliding metadata under fail-fast and ignored-error policies.

## Evidence and cause

Fresh review on 2026-09-12, finding R13. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: parallel_runner.rs:153](../../src/nodes/composition/parallel_runner.rs).

Child context is merged after `success` and `flow`. With `on_error="ignore"`, a failed child that had published `success=true` returned an item claiming success, although the aggregate error count was one. Reserve metadata fields or namespace child data. Evidence: engine parallel-result probe.

## Outcome and validation

Resolved on 2026-09-13. The shared static/dynamic parallel result builder now
reserves top-level `success`, `flow`, and `error` for engine-owned metadata.
Flattened child fields, including inherited input, cannot replace those fields
or add a misleading error to a successful result.

- Non-reserved per-child namespaces retain all public child domain fields,
  including fields named `success`, `flow`, and `error`. Nested domain fields
  are not filtered by metadata names. Existing `_`-prefixed private-key
  filtering and execution-overlay redaction remain unchanged.
- Static per-flow `output_key` and dynamic `child_output_key` reject the three
  reserved names before any child loads or starts, including empty dynamic
  sources and a reserved namespace on a later static entry. These are node
  configuration errors and are not suppressed by `on_error = "ignore"`.
- Node-level `output_key` still names the parent results array and is not
  restricted by the per-entry metadata rule. Result order, aggregate counts,
  failure policies, full live values, and cancellation ownership are unchanged.
- Loaded children report their actual declared flow name; loading/execution
  failures without a finalized result retain the configured path and engine
  error. The existing envelope shape is preserved.
- Node and architecture docs describe the rule and migration. The catalogued
  offline `parallel_result_metadata.lua` / `metadata_child.lua` pair verifies
  successful and failed static/dynamic children with colliding domain fields.

Pre-fix evidence: four of the initial six `test_parallel_result_metadata`
regressions failed. Successful children reported `success=false`, failed
children reported `success=true`, reserved namespaces executed children and
overwrote the status field with an object, and empty dynamic fan-out accepted
a reserved namespace. Namespaced preservation and fail-fast behavior already
passed and remain covered.

Post-fix validation on Rust 1.98.1:

- `test_parallel_result_metadata`: eight tests passed across static/dynamic
  fan-out, both error policies, flattened/namespaced fields, inherited input,
  nested fields, ordered mixed outcomes, child-loading failures, every reserved
  namespace, empty sources, and side-effect markers proving pre-start rejection.
- `test_parallel_result_cli`: two tests passed. CLI validated and executed the
  existing parallel example and new parent/helper pair from an isolated working
  directory. Invalid static and empty-dynamic namespaces exited unsuccessfully
  despite the ignore policy. The empty-source fixture uses `json_array({})`,
  corrected after an initial fixture mistakenly supplied an object.
- `test_parallel_subworkflows_node`, `test_child_result_fidelity`, and
  `test_nested_workflow_cancellation`: 27 existing tests passed, retaining
  parallel behavior, full large child values, physical child-process cleanup,
  and parent deadlines.
- `test_example_catalog`: three tests passed, loading/validating all 143 Lua
  examples and checking catalog classification and built-in node coverage.
- `cargo fmt --all -- --check`, `python3 -B scripts/check_module_size.py`,
  `cargo clippy --all-targets -- -D warnings`, and `cargo audit --deny warnings`
  passed. Both changed production modules remain below 300 lines; no module
  exceptions or dependencies changed.

Compatibility boundary: previously accepted reserved child namespaces now
fail at node execution and must be renamed. Workflows needing same-named
flattened domain fields must opt into a non-reserved child namespace. This does
not add generic node-configuration checking to `ironflow validate`, change
durable storage or public API shapes, or address IF-119's literal fan-out input
mapping. Validation was focused and local; the full integration gate, live
external services, push, and release remain separate.
