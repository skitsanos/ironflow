# IronFlow fresh audit: 2026-09-12

This is a historical review snapshot, not current issue status. The canonical
[issue registry](./README.md) and each issue's frontmatter track remediation.
The review found 27 actionable defects: seven P1 and twenty P2. Existing
IF-001 through IF-105 were resolved before this review; new findings do not
rewrite their historical acceptance evidence.

## Candidate and evidence boundary

The reviewed dependency candidate was `701430801cfaaf3cfc52267c59c7f3cf98415acd`,
subsequently integrated with content-equivalent PR merges at local
`526e958f8ea60cf2e125400363155e77a0c2d77f` (`1.18.1-dev.1`, Rust 1.98.1).
These are defects in that candidate, not a claim that dependency upgrades
introduced every defect.

Six scoped reviewers covered the API/HTTP, engine/composition, storage,
documents/images, artifacts/files/cloud, and AI/MCP/transforms/database areas.
The parent also checked CLI/configuration, scheduling, metrics, and delivery
policy, recovered three reviewers' unfinished notes/probes, and checked each
retained finding.

Evidence used synthetic credentials, bounded fixtures, loopback servers, actual
local SQLite, disposable Redis, and checksum-verified native Pdfium. No real
provider credentials, shared storage, cloud mutations, or resource-exhaustion
probes were used. Individual pages distinguish compiled workflow/API probes
from query-level interleavings, production Redis-script probes, static source
tracing, and mocked external protocols.

The complete original report and small evidence archive remain outside the
checkout as `review-2026-09-12.md` and
`review-evidence-2026-09-12.tar.gz` in the product directory. The `/tmp` paths
quoted in issue pages are historical working locations, not CI prerequisites.
Each repair must add a portable regression to the repository rather than
depending on those temporary artifacts.

## Healthy baseline does not close these findings

Before fixes, the full local integration gate passed: 1,410 default tests and
1,505 full-feature tests with required disposable PostgreSQL/Redis, zero failed
tests, and two existing manual tests ignored in each configuration. Exact
all-target Clippy, audit, policy checks, release build, and validation of all
137 Lua examples also passed. Native PDF conversion was separately executed.
This is baseline evidence only: existing tests did not cover the new defects.

## Unconfirmed and excluded follow-ups

Documented best-effort scheduler overlap suppression is not a defect in this
audit. JSON blocking-pool saturation and artifact replacement after transient
verification errors remain unconfirmed. Total S3 listing budgets, malformed
provider-response robustness, and Responses-mode tool-loop support are capacity
or contract follow-ups, not additional verified findings.

## Remediation sequence

Address confidentiality and availability first, then ingestion/execution
fidelity and the remaining storage/protocol correctness work. Select one issue
or a tightly coupled pair at a time. Preserve each original trigger, add a
regression, document the current contract, and record exact post-fix validation
before resolving a page. Keep publication separate from local implementation.

## First local remediation batch: 2026-09-12

[IF-106](./IF-106.md), [IF-107](./IF-107.md), and [IF-108](./IF-108.md) now have
implemented fixes, regressions that failed before those fixes, updated public
contracts, and post-fix validation. Their pages contain the exact coverage and
remaining boundaries. This batch leaves 24 findings open: four P1 and twenty P2.

The final default `cargo test --all-targets` run passed 1,423 tests with no
failures and two existing manual tests ignored. Exact all-target Clippy,
formatting, module-size policy, and warning-denying dependency audit passed.
All 34 affected Lua examples passed validation; loopback integration and a real
CLI subprocess supplied runtime evidence without external provider credentials.
Feature-enabled/live PostgreSQL and Redis gates were not rerun for these
non-storage fixes; the earlier full integration gate remains historical only.

Repository agent skills and guidance now preserve review evidence, distinguish
focused checks from integration gates, and require issue outcomes before
closure. Codex hooks reject malformed patch payloads and protected-path aliases;
pre-commit checks issue/roadmap consistency. CI now includes hook-only paths and
executes hook tests and shell syntax checks in the repository-policy job.
Validation passed 15 Python hook tests, 37 Bun policy tests, all three skill
checks, the issue registry check, actionlint, and shell syntax checks. The valid
Codex hooks-enabled configuration required no change. Script/config validation
does not establish native app hook invocation or a filesystem sandbox.

This is local, uncommitted work. No hosted CI, release, or deployed validation
is claimed for this batch.
