# IF-171 — Dependency and lint hygiene: unpinned actions, duplicate crates, unguarded unwraps

## Evidence and boundary

Audit of `develop` at 1.20.1-dev.6 on 2026-10-28.

- GitHub Actions are tag-pinned (`actions/checkout@v7` twelve uses,
  `dtolnay/rust-toolchain@1.99.1` seven, `oven-sh/setup-bun@v2` six,
  `Swatinem/rust-cache@v2` six, `docker/*` nine,
  `softprops/action-gh-release@v3`, `raven-actions/actionlint@v2`) while the
  Docker builder image is digest-pinned. Renovate's `config:recommended` does
  not pin action digests.
- `.github/workflows/ci.yml` has no top-level `permissions:`. The repository
  default is `read` (verified through the API on 2026-10-28), so the token is
  read-only by inheritance rather than by declaration.
- Duplicate crate versions in `Cargo.lock`: base64 0.22/0.23, digest
  0.10/0.11, block-buffer 0.10/0.12, crypto-common 0.1/0.2, cpufeatures
  0.2/0.3, getrandom 0.2/0.3/0.4, hashbrown 0.16/0.17, html5ever 0.39/0.40,
  markup5ever 0.39/0.40, miniz_oxide 0.8/0.9, font-types 0.11/0.12,
  core-foundation 0.9/0.10.
- `num_cpus` (two call sites: `src/util/runtime_config.rs` and
  `src/nodes/composition/parallel_subworkflows.rs`) duplicates
  `std::thread::available_parallelism`; `futures-util` is listed in both
  `[dependencies]` and `[dev-dependencies]`.
- `cargo clippy --lib -W clippy::unwrap_used -W clippy::expect_used` reports
  57 sites in production code (catalog header and format, `zip_preflight`
  fields, `run_lease`, scheduler config and identity, Markdown PDF shaping).
  Most are provably infallible, but nothing prevents new ones.
- `noyalib` 0.0.58 (created 2026-05-10, updated 2026-10-15, single
  maintainer, 0.0.x versioning) parses `IronFlowConfig` YAML and backs the
  YAML node; IF-037 already hardened nesting depth against it.

Boundary: no current vulnerability or misbehavior was observed. These are
supply-chain posture gaps relative to the repository's own stated policy.

## Required outcome and acceptance

- Pin actions to commit SHAs and enable Renovate's
  `helpers:pinGitHubActionDigests`; add `permissions: contents: read` to
  `ci.yml`.
- Enable `#![warn(clippy::unwrap_used, clippy::expect_used)]` at the crate root
  with scoped `#[allow]` and a rationale where a call is infallible, then
  promote to deny in the required lint command.
- Replace `num_cpus` with the standard library; drop the redundant
  dev-dependency; re-check duplicate versions after the next Renovate cohort
  and record which remain upstream-blocked.
- Record `noyalib` as a watched dependency in `docs/SECURITY.md` with an exit
  criterion (for example migrate on a 0.1 API break or after six months
  without a release).
- Resolution evidence: `cargo tree --duplicates` output, Clippy green under the
  new lints, actionlint green, and Renovate producing digest updates.

## Outcome and validation

Resolved on 2026-10-28 on branch `fix/if-171-supply-chain` at 1.20.1-dev.8.

Outcome:

- All 40 third-party action references across `ci.yml`, `release.yml`,
  `container.yml` and `container-release.yml` are pinned to commit SHAs with
  the version tag in a trailing comment. `renovate.json` extends
  `helpers:pinGitHubActionDigests` so Renovate keeps the digests current, and
  a package rule keeps `dtolnay/rust-toolchain` version-pinned because its tag
  is the Rust version that the toolchain group, `rust-toolchain.toml` and the
  Docker builder image move together. `ci.yml` declares `permissions:
  contents: read` at the top level; the publishing workflows already declared
  their grants. `repository_policy.test.ts` asserts the SHA format, the version
  comment, the permission block and the Renovate preset and exception, and the
  policy tests that named actions by tag now match them by name.
- `src/lib.rs` and `src/main.rs` enable `clippy::unwrap_used` and
  `clippy::expect_used` for production code (test modules are exempt through
  `cfg_attr(test, allow(...))`). Under the required lint command
  (`-D warnings`) they are therefore denied. The eight `unwrap` sites are gone:
  the date node uses `NaiveDate::and_time(NaiveTime::MIN)` and `Utc.fix()`,
  the delay node turns a non-finite `seconds` into a node error instead of a
  panic, and the recovery graph uses map entries instead of indexed
  `expect`s. Every remaining `expect` carries a scoped `#[allow]` on its
  enclosing function or static with the invariant that makes it infallible,
  taken from the call site's own message (for example "UUID error IDs are
  valid HTTP header values", "fixed u32", "a lease lock path has a parent").
  Converting those documented invariants into recoverable errors is a
  follow-up per module, not part of this change.
- `num_cpus` is removed; `runtime_config::host_parallelism()` wraps
  `std::thread::available_parallelism` (one when the platform cannot report
  it) and serves both the task limit default and `parallel_subworkflows`. The
  duplicate `futures-util` dev-dependency is removed; the normal dependency
  stays.
- `docs/SECURITY.md` gains a "Watched dependencies" section recording
  `noyalib` with its exit criterion (an incompatible API change, six months
  without a release, or an advisory) and the action-pinning policy.
- Duplicate crate versions in the resolved default graph on 2026-10-28
  (`cargo tree --duplicates`): base64 0.22/0.23, block-buffer 0.10/0.12,
  core-foundation 0.9/0.10, cpufeatures 0.2/0.3, crypto-common 0.1/0.2,
  digest 0.10/0.11, font-types 0.11/0.12, getrandom 0.2/0.3/0.4, hashbrown
  0.16/0.17, html5ever 0.38/0.40, markup5ever 0.38/0.40, miniz_oxide 0.8/0.9,
  phf 0.11/0.12/0.13/0.14 (with phf_generator, phf_macros, phf_shared), rand
  0.8/0.10, rand_core 0.6/0.10, read-fonts 0.39/0.41, sha1 0.10/0.11, sha2
  0.10/0.11, skrifa 0.42/0.44, spin 0.9/0.10, string_cache 0.9/0.11, syn
  2/3, tower-http 0.6/0.7, web_atoms 0.2/0.3, weezl 0.1/0.2. All are
  transitive and follow upstream release cadence (the RustCrypto 0.11 line,
  the html5ever and fontique stacks, phf through several parsers); none is
  selectable from `Cargo.toml` today, so they are recorded here and re-checked
  after the next Renovate cohort rather than pinned.

Contract boundary: no runtime behaviour changes except that the `delay` node
now reports a non-finite `seconds` value as an error instead of panicking,
which its input validation already prevented. Workflow behaviour is unchanged;
only the action revisions are fixed. Renovate opens digest updates from its
next run.

Validation on 2026-10-28:

- `cargo clippy --all-targets -- -D warnings` passes with default features,
  with `postgres,redis,cjk-fonts` and with `--no-default-features` after the
  lint change: 49 scoped allowances remain across 41 files, each on the
  enclosing function or static and each stating its invariant; the eight
  `unwrap` sites and the recovery-graph and Redis-listing `expect`s were
  rewritten instead. The listing that drove the pass came from Clippy itself
  under both feature sets (53 sites before the rewrites).
- `src/engine/recovery.rs` and `src/storage/redis_store/listing.rs` shrank by
  the rewrites, and the module-size policy demanded that their reviewed
  ceilings be lowered to 316 lines each before it would pass; this is the
  shrink-is-violation behaviour that [IF-165](IF-165.md) records.
- `cargo test --lib` (572 passed) and the full default suite through
  `scripts/test_rust_targets.ts` (20 targets, 1,838 tests, 0 failed) passed
  with the lints enabled and the hand-written fixes in place; the `engine`,
  `api`, `storage` and `nodes` binaries passed again after the recovery and
  listing rewrites. Python script tests (16) pass with the lowered ceilings.
- `actionlint .github/workflows/*.yml` passes with every action pinned, and
  `bun test scripts/tests/*.test.ts` (91 pass) includes the new pinning,
  permission and Renovate assertions.
- Not run here: Renovate itself; its first run after this change is expected to
  open digest updates rather than tag bumps, which confirms the preset.
