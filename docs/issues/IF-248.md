# IF-248 — Azure Responses can name different deployments in the request URL and body

## Evidence and boundary

Reviewed 2026-11-19 on local `develop` at `ae1f686`.

`src/nodes/ai/llm.rs:112` prefers the chat deployment when choosing the default model, whereas `src/nodes/ai/llm_providers/provider.rs` prefers the deployment for the selected mode when building the URL. In Responses mode with distinct deployments and no explicit model override, the body and reported model name chat while the URL names Responses. Source inspection; no live Azure call.

## Required outcome and acceptance

Select the default deployment once per mode. Using a local recording endpoint, assert that URL, body and reported model agree for both modes with distinct deployments; preserve the documented explicit model override.

## Outcome and validation

Chat and Responses now use the selected deployment for the URL, default request model and reported model. If only one deployment is configured, both modes use it. An explicit `model` takes precedence over `chat_model` or `responses_model`; none changes the route.

Recording-endpoint tests check the URL, JSON body and reported model for both modes, with and without overrides.
