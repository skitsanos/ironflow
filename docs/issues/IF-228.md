# IF-228 — Decide whether slide footer placeholder text belongs in extract_pptx slide text

## Evidence and boundary

Recorded on 2026-11-16 from the IF-222 sample run. A maintainer decision,
not a defect: the behaviour then was consistent and was left unchanged.

Observed on a deck saved by PowerPoint 16: 70 of 86 slides have a footer
placeholder (`p:ph type="ftr"`) with a plain run, and `extract_pptx`
returns that text as part of each slide. In JSON it is a `text_block` with
`"placeholder": "ftr"`, so a caller can filter it. In text and Markdown it
is an ordinary line repeated on every slide, which adds the same sentence
70 times to a summary or an embedding.

By reading: slide number and date placeholders that hold only a field
(`a:fld`) contribute nothing, because field text is not read on slides. A
date or slide number typed as a plain run would be returned like the
footer.

Speaker notes were decided the other way under IF-193: notes return the
body placeholder only and drop footer, header, date and slide number.

## Outcome and validation

Decided by the maintainer on 2026-11-16: drop them. Slide text omits the
`ftr`, `dt`, `sldNum` and `hdr` placeholders in every format, as speaker
notes do. No `text_block` is returned for them, whether they hold a field
or typed text.

Contract boundary:

- Only the slide's own placeholder type decides. A text box placed in the
  footer area, or a placeholder of any other type, is still slide text.
- There is no parameter to get the footer back.
- Output changes for every deck with a footer: stored extractions and
  embeddings differ, and `"placeholder": "ftr"` no longer occurs.

Regression, failing first: `tests/test_pptx_slide_furniture.rs` on a
hand-built slide with typed text in all four placeholders, a body, a
subtitle and a text box, in JSON, text and Markdown. One assertion of
`tests/test_pptx_inherited_bullets.rs` that expected a footer paragraph was
removed.

Checked on the private deck of the IF-222 run, read in place: the 70
footer text blocks are gone (1,665 text-block paragraphs before, 1,595
after) and no `ftr`, `dt`, `sldNum` or `hdr` block remains.

Validation, default features: `documents` 224 passed (3 ignored),
`examples` 11, the 38 extraction tests of `serial`, 115 extraction unit
tests, formatting, the module-size check and
`cargo clippy --all-targets -- -D warnings`. Not run: the integration gate
and feature-enabled suites.
