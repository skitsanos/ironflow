# IF-228 — Decide whether slide footer placeholder text belongs in extract_pptx slide text

## Evidence and boundary

Recorded on 2026-11-16 from the IF-222 sample run. A maintainer decision,
not a defect: the current behaviour is consistent and was left unchanged.

Observed on a deck saved by PowerPoint 16: 70 of 86 slides have a footer
placeholder (`p:ph type="ftr"`) with a plain run, and `extract_pptx`
returns that text as part of each slide. In JSON it is a `text_block` with
`"placeholder": "ftr"`, so a caller can filter it. In text and Markdown it
is an ordinary line repeated on every slide, which adds the same sentence
70 times to a summary or an embedding.

By reading: slide number and date placeholders that hold only a field
(`a:fld`) contribute nothing, because field text is not read on slides. A
date or slide number typed as a plain run would be returned like the
footer.

Speaker notes were decided the other way under IF-193: notes return the
body placeholder only and drop footer, header, date and slide number.

## Required outcome and acceptance

Decide one of:

- keep it (JSON callers filter on `placeholder`), and say so on the node
  page;
- drop `ftr`, `dt`, `sldNum` and `hdr` placeholders from slide text in
  every format, as notes do;
- add a parameter, with the default chosen by the maintainer.

Any change is an output change for stored extractions and needs a
hand-built regression, the node page and an upgrade note.
