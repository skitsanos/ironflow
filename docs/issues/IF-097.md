# IF-097 — Default CI contains two timing-dependent test failures

## Outcome and validation

**Historical status:** Resolved on 2026-08-05.

Two consecutive green-product `develop` runs failed different default-suite
tests. Run `30989914250` removed one rather than two cache entries because the
test combined second-resolution TTLs, sequential inserts, implicit insert-time
sweeps, and a 1.5-second sleep. Run `30990412844` timed out a deliberately slow
flow-load request after two seconds under the fully parallel Ubuntu suite even
though the same regression passed in the single-threaded full-feature job.

Required outcome:

- give `BoundedCache` private fixed-time seams and make TTL/get/sweep unit tests
  deterministic without sleeping;
- remove the duplicate integration test that reaches into the utility type and
  relies on wall-clock alignment;
- retain refusal as the flow-admission synchronization signal while replacing
  its two-second completion deadline with a generous deadlock watchdog;
- stress both focused regressions and run the required Rust quality gates; and
- keep production cache behavior, public contracts, Lua examples, and node
  documentation unchanged.

Resolution: `BoundedCache` now routes its public insert, get, and expiry-sweep
operations through private fixed-time helpers. Production callers still use
the same second-resolution system clock, while unit tests can establish exact
creation and observation times without sleeps or scheduler assumptions. The
duplicate wall-clock integration test was removed, and the memory-node TTL-zero
regression no longer waits 1.1 seconds for an entry whose contract says it is
already expired.

The flow-load admission regression still uses the observed refusal as its
synchronization signal. Its completion timeout is now a ten-second deadlock
watchdog, leaving enough headroom for the deliberately slow parser under a
fully parallel hosted runner without weakening the admission assertion.

The final focused runs passed 7 bounded-cache unit tests, 13 cache-node tests,
and the flow-load admission regression. Stress validation passed 100 iterations
of each deterministic cache regression (200 total) and 20 iterations of the
admission regression. `cargo fmt --all -- --check`, the 453-module size policy,
exact all-target Clippy with warnings denied, 14 issue/repository policy tests,
the generated issue-registry check, and `git diff --check` passed. No full
integration gate, live storage service, Lua example validation, or deployment
test was run because the change only stabilizes internal tests and does not
alter public behavior, documentation, or examples.
