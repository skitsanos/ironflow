# IF-188 — Child workflows have no nesting limit and outlive a timed-out parent step

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12, reproduced with a local
optimized build.

1. No nesting limit. A flow `self.lua` whose only step is
   `nodes.subworkflow({ flow = "self.lua" })` started about 67,000 nested
   child executions in 12 seconds and was still descending when stopped. No
   depth error is raised, `ironflow validate` does not load child flows, and
   `IRONFLOW_MAX_RUN_SECONDS` is unset by default. Every composition node
   re-registers the others in its child registry
   (`src/nodes/composition/registry.rs:20-24`), and none carries a depth
   (`subworkflow.rs:146-154`, `parallel_runner.rs:73-90`,
   `repeat_subworkflow.rs:115-124`, `tool_dispatch/runner.rs:57-63`).
2. Parent does not wait for child work. A parent step
   `subworkflow(...):timeout(2):on_error("handler")` whose child was inside
   an uninterruptible tracked blocking node timed out at 2 s; the handler
   started at once and the parent run was finalized `success` while the
   child's worker was still running. The same node placed directly in the
   parent keeps the run open until the worker stops (still open at 25 s).
   Tracked workers register with the task that spawns them, which is the
   child coordinator's own task, so the parent's wait sees an empty set
   (`src/engine/executor/handle.rs:53-99`, `src/util/execution.rs:75-84,
   217-236`).
3. Eager child contexts, by reading. `parallel_subworkflows` builds every
   child context before `max_concurrent` applies
   (`parallel_subworkflows.rs:89-146`) and has no item ceiling, unlike
   `tool_dispatch` and `repeat_subworkflow`. It also calls
   `Path::canonicalize` on the async thread once per entry.

Boundary: `docs/ARCHITECTURE.md` states that run and task admission is held
until physical work stops (IF-064, IF-065). Item 2 means a handler or
dependent step can run, and admission can be released, while the child is
still writing. Memory growth in item 3 was not measured.

## Required outcome and acceptance

- Carry a nesting depth through child execution and fail above a small
  documented ceiling.
- Make the parent step's completion, timeout and cancellation wait for the
  child's tracked workers before releasing permits or starting handlers.
- Build each child context after its concurrency permit is acquired, add an
  item ceiling to `parallel_subworkflows`, and resolve paths off the async
  thread.
- Regressions: self- and mutually-recursive flows fail fast; a timed-out
  parent does not finalize before a child worker stops; fan-out memory stays
  proportional to `max_concurrent`.
- Document the limits in the four composition node pages.
