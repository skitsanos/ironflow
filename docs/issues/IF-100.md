# IF-100 — Production deployments lack a bounded metrics contract

## Required outcome and acceptance

IronFlow exposes liveness/readiness probes, structured tracing, persisted task
timings, and run-event SSE, but it has no scrapeable metrics surface. Operators
cannot alert on admission saturation, scheduler skips, lease loss, storage
failures, or run/task outcome and latency trends without parsing logs or
polling individual runs.

Required outcome:

- define a Prometheus-compatible metrics endpoint and its authentication or
  network-exposure boundary;
- instrument run and task outcomes/durations, active work, admission pressure,
  scheduler decisions, lease loss, and state/event-store failures;
- keep labels on bounded vocabularies and prohibit run IDs, arbitrary flow or
  schedule names, URLs, errors, context values, and secrets;
- avoid making metrics publication part of a correctness-critical state
  transition or blocking the async runtime;
- document metric stability, reset semantics, Kubernetes scraping, and alerting
  examples; and
- add focused endpoint, label-cardinality, redaction, concurrency, and disabled
  or inaccessible-surface regressions.

The first delivery is an operator metrics contract, not a bundled dashboard,
distributed tracing backend, billing system, or hosted telemetry service.
