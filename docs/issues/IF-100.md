# IF-100 — Production deployments lack a bounded metrics contract

## Outcome and validation

**Resolved on 2026-08-18.** IronFlow now exposes an opt-in, process-local
OpenMetrics contract at `GET /metrics`. The route is absent by default, uses the
same API authentication middleware when enabled, and returns OpenMetrics 1.0
text without caching.

Resolution:

- A per-server registry records terminal run and task-attempt outcomes and
  durations, current run/task/flow-load work, admission decisions, scheduler
  outcomes, lease renewal/loss behavior, and typed state/event-store failures.
- Every label value comes from an enumerated vocabulary. Run IDs, flow,
  schedule, task and node names, URLs, diagnostics, context, and secrets never
  enter labels. All valid series are initialized, making cardinality fixed and
  auditable.
- Recording performs only bounded in-memory work, returns no errors, and is
  outside workflow, scheduler, lease, and storage correctness decisions.
- `IRONFLOW_METRICS_ENABLED` and `metrics_enabled` are strict opt-in controls.
  The API-key, explicit unauthenticated mode, and loopback rules are shared with
  other protected API routes and documented as the exposure boundary.
- `docs/METRICS.md` defines metric stability, process-restart resets,
  replica-aware aggregation, authentication, and every name/label. Prometheus
  Operator `ServiceMonitor` and `PrometheusRule` templates provide authenticated
  pod scraping and four starting alerts.

Focused Rust validation passed 7 metrics tests, 24 API tests, 3 lease tests, 13
configuration tests, and the invalid-metrics-precedence regression. This covers
the enabled endpoint, disabled `404`, authenticated `401`/`200`, OpenMetrics
content type, fixed cardinality, secret redaction, concurrent updates, registry
reset, real workflow and scheduler recording, admission drain, lease timeout
and error paths, and both store wrappers. `cargo check --all-targets`, exact
warning-denying Clippy, formatting, the module-size policy, and
`cargo audit --deny warnings` passed.

A real `ironflow serve` probe independently observed disabled `404`, an enabled
request without credentials returning `401`, an authenticated request returning
`200`, a successful flow changing both run and task counters, an OpenMetrics EOF
marker, and absence of request sentinels from the scrape. Bun parsed both
Kubernetes manifests, and Prometheus 3.13.1 `promtool` accepted all four alert
rules. The full integration gate then passed the default and `postgres,redis`
test suites, warning-denying Clippy in both configurations, all 137 Lua examples,
a release build, and live tests against disposable Redis and PostgreSQL
instances. Kubernetes, Railway, and OpenShift were not deployed; the manifests
remain operator templates rather than deployed evidence.

This delivery intentionally does not bundle a dashboard, distributed tracing
backend, billing system, or hosted telemetry service.
