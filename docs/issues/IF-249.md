# IF-249 — db_query silently drops columns with duplicate labels

## Evidence and boundary

The row converter read columns by ordinal but inserted them into a JSON object by label. For example, `SELECT 11 AS id, 22 AS id` returned `{"id":22}` without an error. Joins selecting two `id` columns had the same problem.

## Required outcome and acceptance

Test `SELECT 11 AS id, 22 AS id` and require an actionable duplicate-label error or a documented lossless representation. Distinct aliases must preserve both values and the ordinary object shape.

## Outcome and validation

`db_query` now rejects duplicate labels in a returned row instead of overwriting a value. The error identifies the duplicate column by position and recommends distinct `AS` aliases. SQLite and PostgreSQL regression tests cover the rejection and the aliased result.
