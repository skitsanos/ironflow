# IF-249 — db_query silently drops columns with duplicate labels

## Evidence and boundary

Reviewed 2026-11-19 on local `develop` at `ae1f686`.

`src/nodes/database/row.rs:26` reads columns by ordinal, then inserts each into a JSON object by label. A later column with the same label replaces an earlier value. A join selecting two `id` columns can therefore return success with incomplete data. Source inspection.

CLI confirmation using in-memory SQLite: `SELECT 11 AS id, 22 AS id, 33 AS other` reported success and returned only `id=22` and `other=33`. PostgreSQL was not exercised.

## Required outcome and acceptance

Test `SELECT 11 AS id, 22 AS id` and require an actionable duplicate-label error or a documented lossless representation. Distinct aliases must preserve both values and the ordinary object shape.
