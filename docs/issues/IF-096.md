# IF-096 — String-backed code silently resolves undefined globals to nil

## Outcome and validation

**Historical status:** Resolved on 2026-08-05.

IF-095 added undefined-global diagnostics for serialized function handlers but
left string-valued `nodes.code.source` outside the lexical pass. A direct
reproduction showed that `ironflow validate --strict` accepted a stale global
read, execution succeeded, and `string.format` emitted `"hello nil"`.

Resolution: validation now compiles every executed string-valued `code` source
without calling it. Both statement chunks and the expression form supported by
`mlua::Chunk::eval` are accepted; invalid syntax identifies the owning step and
fails validation in both ordinary and strict modes. A regression whose source
calls `error()` proves that compilation does not execute workflow code.

The shared tree-sitter scope analyzer now checks string source using the same
runtime-global allowlist as function handlers. Undefined reads remain warnings
by default and strict mode rejects them. CLI locations use
`step[NAME].source:LINE:COLUMN`; API diagnostics include an optional `step`
field. Lines and columns are relative to the decoded source string, including
correct remapping when expression analysis adds an internal `return ` prefix.

Validation mirrors runtime precedence by ignoring `source` when authenticated
`bytecode_b64` is present. Aggregate embedded-source bytes are checked against
`IRONFLOW_MAX_FLOW_SOURCE_BYTES` before compilation or parsing, including
sources constructed dynamically while loading the flow. The current README,
CLI reference, Lua guide, `code` node reference, and a runnable parallel-flow
example document the contract.

Focused validation passed seven analyzer tests, two embedded-source validation
unit tests, nine CLI/API/runtime diagnostic tests, and the existing function
handler load regression. Formatting, Rust doctests, the 453-module size policy
with 11/11 reviewed exceptions, exact all-target Clippy, dependency audit with
warnings denied, 14 Bun registry/repository-policy tests, issue registry checks,
and strict validation of all 132 Lua examples passed. Validation did not execute
handler or embedded code; only the initial explicit workflow-run reproduction
demonstrated the wrong `"hello nil"` output. No live storage, deployment, or
full integration gate was required for this validation-only change.
