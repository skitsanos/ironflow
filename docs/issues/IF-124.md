# IF-124 — MCP stdio drops partially consumed frames on select cancellation

## Required outcome and acceptance

- Keep partially read framing bytes outside cancellable futures, or isolate reading in a dedicated owned task.
- A simultaneous outgoing server-request reply must not discard any valid response prefix.
- Add deterministic fragmented-frame/ping interleaving coverage and retain EOF, malformed-frame, cancellation, timeout, and process cleanup behavior.

## Evidence and cause

Fresh review on 2026-09-12, finding R19. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: mcp/stdio.rs:149](../../src/nodes/mcp/stdio.rs), [buffer: stdio.rs:285](../../src/nodes/mcp/stdio.rs).

An outgoing ping reply can cancel `read_frame` after it consumed a response prefix into future-local storage. The next read sees only the suffix and closes the transport. A valid fragmented local response reproduced this twice after successful initialization. Retain incomplete bytes outside the cancellable future or use a dedicated reader task. Evidence case: `mcp-partial`.

## Outcome and validation

Resolved on 2026-09-14. `mcp/stdio/framing.rs` now owns the read buffer in a
`FrameReader`, outside the future selected by the stdio worker. An outgoing
message can interrupt a pending `read_until` without discarding bytes already
consumed. Each retry admits only the remaining frame budget plus one sentinel
byte; cancellation cannot reset the accumulated size limit. EOF after a
cancelled prefix is an unterminated-frame error rather than clean EOF.

The incoming limit still includes LF or CRLF delimiters. Complete frames have
their delimiter removed before the existing JSON-RPC parser validates them.
Outgoing serialization and its pre-newline size check are unchanged. No new
task, dependency, session API, timeout, or process-lifecycle policy was added.
Actual operation failure, timeout, or cancellation still invalidates the session
and cleans up its owned process; internal read interruption for an outgoing
reply does not. Streamable HTTP transport behavior is unchanged.

The framing extraction reduced `stdio.rs` from 335 to 285 lines. Its obsolete
module-size exception was removed, reducing the exception budget from 10 to 9.
Node, CLI-limit, and architecture docs describe the cumulative input budget and
cancellation boundary. The existing `mcp_stdio.lua` example now uses a mock
that withholds each response suffix until IronFlow replies to a server ping.

Validation used current stable Rust 1.98.1 and the local Python MCP mock:

- Before the fix, the public node fragmented-response test failed with
  `tools/list failed: Transport closed`. After mechanically extracting the old
  reader algorithm, four of seven deterministic reader tests failed: split
  response preservation, outgoing ping interleaving, cumulative frame limits,
  and EOF after a cancelled prefix. The three framing controls passed. An
  initial partial-EOF fixture error was corrected separately; the corrected
  public EOF control passed before the production fix and is not defect evidence.
- After the fix, all seven tests selected by
  `cargo test --lib nodes::mcp::stdio::framing:: -- --nocapture` passed. They
  force cancellation after bytes have been consumed, including every split of
  a UTF-8/CRLF response, a biased-select outgoing ping reply, repeated one-byte
  reads, cumulative overflow without further consumption, EOF, input I/O errors,
  complete-line boundaries, and outgoing limits.
- `cargo test --test test_mcp_nodes --test test_process_cancellation
  --test test_mcp_streamable_http --test test_mcp_streamable_http_sse
  -- --nocapture` passed all 23 tests. Coverage includes malformed envelopes,
  correlation, session reuse and isolation, partial EOF, timeout and cancellation
  during partial responses, explicit close, Unix parent/descendant termination,
  and Streamable HTTP JSON/SSE regressions against local fixtures. The repeated
  fragment test verifies 16 ping-prefix-suffix exchanges on one session; five
  additional runs passed.
- The CLI regression strictly validated both MCP Lua examples and executed the
  five-step stdio example. It verified a successful terminal run, the two listed
  tools, complete expected tool text, the same opaque handle across operations,
  and explicit close. The child CLI ran with a cleared environment plus an
  explicit PATH/TMPDIR in a temporary working directory, without project dotenv
  or external credentials. The HTTP example was validated, not executed against
  an external MCP server.
- `cargo fmt --all -- --check`, `python3 -B scripts/check_module_size.py`,
  `cargo clippy --all-targets -- -D warnings`, and
  `cargo audit --deny warnings` passed. All 16 module-size checker tests passed.

This is 30 distinct focused Rust tests plus the checker tests, not a full-suite,
Windows process-tree, hosted-provider, or release validation. The full
integration gate remains deferred to the next authorized push or release.
