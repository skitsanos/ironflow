# IF-151 — eMudhra distrust updates missing from bundled TLS dependencies

## Evidence and boundary

On 2026-10-24, develop `22f867c` resolved `rustls-webpki 0.103.15`,
`webpki-roots 1.0.9`, and `webpki-root-certs 1.0.9`. Cargo audit reports
RUSTSEC-2026-0381, RUSTSEC-2026-0382, and RUSTSEC-2026-0383. These versions
precede the eMudhra intermediate-key compromise fixes. This establishes an
affected dependency graph, not evidence that a connection was intercepted.

The published `latest` image was also tested by immutable OCI index digest
`sha256:c9010f50ef6ab7710a52125d603c3ff6bdf8ca37b24fda3a61500407ea2d34b6`.
Its installed CA package is `20250419~deb12u1`. Its curl accepted valid HTTPS
and then accepted `https://dv-g3b-emudhra.we-have-a-problem.com/` (exit 0).
The published image's IronFlow CLI was then tested with a single `http_get`
step using direct HTTPS to the same host. It exited 0 with `Status: success`.
This reproduces the trust failure in an actual workflow node as well as curl;
it is not a historical exploitation claim or a test of every client. The
containers and temporary flow were removed. A patched development image does
not move the stable `latest` alias; published artifacts still need a release.

Primary references:
- [Incident and test hosts](https://emudhra.we-have-a-problem.com/)
- [webpki verifier fix](https://github.com/rustls/webpki/releases/tag/v%2F0.103.16)
- [root-bundle fix](https://github.com/rustls/webpki-roots/releases/tag/v%2F1.0.10)
- [Bun 1.4.4](https://bun.com/blog/bun-v1.4.4)

## Required outcome and acceptance

- Resolve the patched verifier and both root bundles without advisory ignores.
- Require patched Debian CA packages in builder and runtime stages; an old
  cached image or binary is not repaired by updating its host.
- Keep CI's pinned Bun runtime at or above 1.4.4.
- Verify a valid HTTPS endpoint still works and compromised direct, cross-signed,
  and no-CT chains fail with certificate errors, not merely network errors.
- Record the exact tested candidate and distinguish source, local, hosted,
  published-image, and deployed evidence.

## Implementation and operator boundary

The candidate updates the verifier and root bundles, adds lockfile regression
checks, and makes both Debian stages reject CA packages older than
`20250419~deb12u2`. The opt-in command
`bun --no-env-file scripts/test_public_tls.ts target/release/ironflow` uses
isolated temporary storage, no inherited credentials/proxies, and a valid TLS
control before four compromised-chain probes. Enable it during the full gate
with `IRONFLOW_TEST_PUBLIC_TLS=1`.

HTTP and provider requests use reqwest/rustls platform verification. AWS,
SMTP, PostgreSQL and Redis also resolve rustls/webpki; some paths load native
roots, others bundled roots or operator-supplied CAs. Bundled updates do not
replace an administrator's custom CA file. Do not disable TLS verification or
silently edit custom trust anchors. Update host trust stores, rebuild and
redeploy images, and replace existing binaries. Audit proxy and endpoint logs
separately for historic exposure; this repository check cannot establish that
previously deployed instances were never attacked.

The separate website runs on Bun; an existing deployment needs Bun >=1.4.4
and a fresh image pull/rebuild. A floating `oven/bun:latest` tag does not update
already-running containers. Production rollout is not implied by local tests.

## Outcome and validation

The 2026-10-24 candidate resolves `rustls-webpki 0.103.16`, both webpki root
bundles at 1.0.11, and rustls 0.23.46. Cargo audit passes without ignores.
The built debug and release CLIs accept valid HTTPS and reject all four
documented compromised-chain probes with certificate errors. A fresh Debian
bookworm container installs `20250419~deb12u2`; its curl also accepts the valid
control and rejects all four compromised chains (exit 60). Local Bun and the
rebuilt website image use Bun 1.4.4 and reject all four with `CERT_REVOKED`.

`IRONFLOW_TEST_PUBLIC_TLS=1 scripts/integration_gate.sh` passed with Rust
1.99.1: 1,770 default tests, 1,897 full-feature tests (four manual tests ignored
in each), default/full-feature Clippy, formatting, policies, audit, release
build, 153 Lua examples, and real PostgreSQL 18.6/Redis 8.10.2 acceptance.
TLS acceptance covers verified CLI/serve persistence, restarts, `db_query`,
wrong-CA/hostname rejection, plaintext rejection and the insecure Redis bypass.
Gate-owned containers, certificates, keys, volumes and linked artifacts were
removed. An additional focused default S3 signing target passed two tests.

Hosted CI also passed on implementation commit `9d771f9`
([run 40067599158](https://github.com/skitsanos/ironflow/actions/runs/40067599158)).
The final documentation and signing-test follow-up is separately subject to
PR #217's CI before merge. Website PR #2 passed 329 tests, audit, lint,
types, a complete Docker build, and page/static-asset HTTP checks; an isolated
unpublished preview verified the optional security page and signing links.
These are source/local/hosted results, not proof that stable binaries, the
stable `latest` image, or every deployment have been replaced. The published
image reproduction above remains the pre-fix baseline until a patched release
and rollout; no absence-of-historical-exploitation claim is made.
