# IF-151 — eMudhra distrust updates missing from bundled TLS dependencies

## Evidence and boundary

On 2026-10-24, develop `22f867c` resolved `rustls-webpki 0.103.15`,
`webpki-roots 1.0.9`, and `webpki-root-certs 1.0.9`. Cargo audit reports
RUSTSEC-2026-0381, RUSTSEC-2026-0382, and RUSTSEC-2026-0383. These versions
precede the eMudhra intermediate-key compromise fixes. This establishes an
affected dependency graph, not evidence that a connection was intercepted.

Primary references:
- [Incident and test hosts](https://emudhra.we-have-a-problem.com/)
- [webpki verifier fix](https://github.com/rustls/webpki/releases/tag/v%2F0.103.16)
- [root-bundle fix](https://github.com/rustls/webpki-roots/releases/tag/v%2F1.0.10)
- [Bun 1.4.4](https://bun.com/blog/bun-v1.4.4)

## Required outcome and acceptance

- Resolve the patched verifier and both root bundles without advisory ignores.
- Require patched Debian CA packages in builder and runtime stages; an old
  cached image or binary is not repaired by updating its host.
- Keep CI's pinned Bun runtime at or above 1.4.4.
- Verify a valid HTTPS endpoint still works and compromised direct, cross-signed,
  and no-CT chains fail with certificate errors, not merely network errors.
- Record the exact tested candidate and distinguish source, local, hosted,
  published-image, and deployed evidence.

## Implementation and operator boundary

The candidate updates the verifier and root bundles, adds lockfile regression
checks, and makes both Debian stages reject CA packages older than
`20250419~deb12u2`. The opt-in command
`bun --no-env-file scripts/test_public_tls.ts target/release/ironflow` uses
isolated temporary storage, no inherited credentials/proxies, and a valid TLS
control before four compromised-chain probes. Enable it during the full gate
with `IRONFLOW_TEST_PUBLIC_TLS=1`.

HTTP and provider requests use reqwest/rustls platform verification. AWS,
SMTP, PostgreSQL and Redis also resolve rustls/webpki; some paths load native
roots, others bundled roots or operator-supplied CAs. Bundled updates do not
replace an administrator's custom CA file. Do not disable TLS verification or
silently edit custom trust anchors. Update host trust stores, rebuild and
redeploy images, and replace existing binaries. Audit proxy and endpoint logs
separately for historic exposure; this repository check cannot establish that
previously deployed instances were never attacked.

The separate website runs on Bun; an existing deployment needs Bun >=1.4.4
and a fresh image pull/rebuild. A floating `oven/bun:latest` tag does not update
already-running containers. Production rollout is not implied by local tests.
