# IF-252 — MCP action timeout excludes time waiting for the session lock

## Evidence and boundary

Reviewed 2026-11-19 on local `develop` at `ae1f686`.

`src/nodes/mcp/client.rs:64` and `:78` await the session mutex before starting list or call timeouts. `src/nodes/mcp/session.rs` does the same for close. Concurrent actions sharing a session can exceed their configured timeout before even sending a request. Source inspection.

## Required outcome and acceptance

Apply one deadline across queueing and execution. With one operation holding the session, a second short-budget action must time out without sending a late request. Cover close as well and verify cleanup and remaining session state.

## Outcome and validation

`list_tools`, `call_tool` and `close` share one deadline for queueing and execution. A waiter that expires before admission sends nothing and preserves the handle; an in-flight failure still invalidates it. The contention regression checks all three actions, the server request trace, subsequent reuse and explicit shutdown.
