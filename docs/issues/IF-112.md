# IF-112 — A one-page PDF split retains unselected pages' objects

## Required outcome and acceptance

- Collect only selected-page dependencies, without following Parent/Kids into unselected page graphs.
- Materialize inherited page attributes before reparenting; coordinate with IF-114 so page isolation does not break rendering.
- Assert unselected content and unique resources are absent from serialized output, not merely hidden from page count; retain valid selected text/resources.

## Evidence and cause

Fresh review on 2026-09-12, finding R07. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: pdf_merge_split/split.rs:137](../../src/nodes/image/pdf_merge_split/split.rs).

Recursive collection follows the selected page's Parent and the parent's Kids before replacing the parent link. Splitting only page 1 of a two-page synthetic document produced a nominal one-page PDF whose bytes still contained the page-2 sentinel and its object graph. Sending the resulting file can therefore disclose material outside the selected pages; it also amplifies output size.

Fix and coverage: collect only selected-page dependencies, materialize inherited attributes, and assert that unselected content is absent from output objects, not just absent from the visible page count. Evidence: extraction probe `split`; direct-split output contains `PRIVATE_PAGE_TWO`.

## Outcome and validation

Resolved locally on 2026-09-12, after published baseline `7c5c803`.
Split and merge now share an iterative, cancellation-aware page graph collector.
It materializes inherited page attributes before dropping the old Parent link,
excludes unselected Page objects and source Pages/Catalog objects, and remaps
references to omitted objects to PDF nulls. Annotation backlinks to a retained
page remain valid; cross-page destinations cannot reimport an omitted page or
accidentally resolve to a reused output object ID.

The five tests in `test_pdf_page_graph` failed before the repair and now pass.
They check serialized page-content/resource sentinels, exact Page/Pages object
counts, inherited attributes and null fallback, source order and overrides,
annotation backlinks/cross-page destinations, and malformed parent chains.
The link case also verifies that merge preserves destinations between pages
that are both retained. Fixtures now include fonts and image XObjects.

Post-fix validation passed seven merge unit tests and 24 tests across
`test_pdf_page_graph`, `test_pdf_merge_split_nodes`, `test_pdf_merge_safety`,
`test_pdf_image_nodes`, and `test_example_fixtures`. The merge unit suite checks
that inherited resources remain shared and count toward the object ceiling,
including refusal before staging when one object over budget. Existing
atomic-output and input/page/byte-limit tests pass.

The separate CLI/Poppler regression failed before the repair and now passes
with pixel-identical source/split/merged pages; see [IF-114](./IF-114.md).
Formatting, module-size policy, `cargo clippy --all-targets -- -D warnings`,
`cargo audit --deny warnings`, issue-registry validation, and validation of both
affected Lua examples passed. Both PDF examples also executed successfully in
isolated temporary workspaces. Native rendering evidence comes from explicitly running Poppler,
not the optional Pdfium paths in the existing image tests.

Node documents and examples explain the boundary: selected-page extraction is
not general content redaction. Retained shared resources or streams may contain
unused/hidden data. This does not resolve [IF-111](./IF-111.md)'s initial PDF
decompression admission finding. These changes are uncommitted; the full
integration gate for `7c5c803` is not claimed as post-fix validation.
