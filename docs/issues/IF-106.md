# IF-106 — Static compressed sidecars can escape the public root

## Required outcome and acceptance

- Inspect all precompressed candidates before serving, including missing originals, missing ancestors, and directory/SPA indexes.
- Reject escaping or dangling sidecar symlinks for GET and HEAD; preserve confined precompression, caching, ranges, and the existing SPA/missing-asset contract.
- Add deterministic routing regressions for .gz and .br and document the deployment immutability boundary.

## Evidence and cause

Fresh review on 2026-09-12, finding R01. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: static_files/path.rs:147](../../src/api/static_files/path.rs).

When the original file does not exist, `inspect` returns `Missing` before validating its compressed sidecars. The handler still calls ServeDir, which can serve an existing `.gz` or `.br` first. With precompression enabled, a scratch `public/orphan.txt.gz` symlink to a synthetic file outside the root returned HTTP 200 and the outside sentinel. The equivalent sidecar with an existing original was correctly rejected with 404. GET and HEAD were checked. This is a pre-existing integration gap, also supported by tower-http 0.6.11's lookup order, not a new 0.7-only feature.

Fix and coverage: validate every candidate that ServeDir might open, including sidecars for missing originals and missing ancestors; add orphan-sidecar containment tests. Evidence: `/tmp/ironflow-api-review-probe.log` and `/tmp/ironflow-api-probe-v38bgO`.

## Outcome and validation

Resolved locally on 2026-09-12. Missing originals now undergo sidecar confinement
checks and never reach ServeDir's compressed-file lookup. This enforces the
existing documented requirement for an original file. Every SPA fallback also
rechecks its index and compressed representations before calling ServeFile.
The CLI reference records these rules and the remaining concurrent-writer
boundary: the public tree must remain operator-controlled and read-only.

Three new negative regressions failed on the original implementation and now
pass: orphan sidecar links, escaping ancestor links, and replacement of the SPA
index or its sidecars after startup. A fourth test checks the original-file
requirement for confined orphans. Existing positive negotiation, HEAD, ranges,
validators, directory indexes, SPA, and API-route precedence coverage passes.

Validation: `cargo test --lib api::static_files` (15 passed),
`cargo test --lib api::server::tests` (7 passed),
`cargo fmt --all -- --check`, `python3 -B scripts/check_module_size.py`, and
`cargo clippy --all-targets -- -D warnings` passed. The regression matrix covers
GET/HEAD with Brotli, Gzip, and identity encoding. Symlink regressions are Unix
tests; the original-file test is portable. No live deployment is claimed.
