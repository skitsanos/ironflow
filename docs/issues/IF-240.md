# IF-240 — Container publication ignores changes to shipped third-party notices

## Evidence and boundary

At `ae1f686`, the Dockerfile copied `THIRD_PARTY_LICENSES.md` into the runtime image, but the Container workflow omitted it from the push paths. A notices-only commit on a publishing branch did not trigger a new build.

## Required outcome and acceptance

Include the notices file in the trigger (and the project license once packaged). Add a policy test that checks the runtime image inputs against the publishing trigger so a change to a shipped notice schedules a build.

## Outcome and validation

The Container workflow includes `THIRD_PARTY_LICENSES.md` in its push paths for `main` and `develop`. A policy test checks repository files copied directly into the runtime stage against the publishing filter. The font license is covered by `assets/**`; packaging IronFlow's own license is tracked in [IF-241](IF-241.md).
