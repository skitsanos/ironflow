# IF-119 — Dynamic fan-out reinterprets literal string items as context keys

## Required outcome and acceptance

- Transport fan-out item values as literals, separately from user-authored input mappings.
- Preserve strings, objects, arrays, booleans, nulls, and numeric item identity regardless of matching parent context keys.
- Test a string equal to an existing context key and an ordinary explicit mapping in the same workflow.

## Evidence and cause

Fresh review on 2026-09-12, finding R14. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: parallel_subworkflows.rs:185](../../src/nodes/composition/parallel_subworkflows.rs).

An item string `customer` became `ctx.customer`'s unrelated value because injected items go through input-mapping resolution. A string without a matching context key remained unchanged. Preserve literal item identity separately from mapping expressions. Evidence: engine dynamic fan-out probe.

## Progress

Open. Implementation and regression validation are pending.
