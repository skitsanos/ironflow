# IF-119 — Dynamic fan-out reinterprets literal string items as context keys

## Required outcome and acceptance

- Transport fan-out item values as literals, separately from user-authored input mappings.
- Preserve strings, objects, arrays, booleans, nulls, and numeric item identity regardless of matching parent context keys.
- Test a string equal to an existing context key and an ordinary explicit mapping in the same workflow.

## Evidence and cause

Fresh review on 2026-09-12, finding R14. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: parallel_subworkflows.rs:185](../../src/nodes/composition/parallel_subworkflows.rs).

An item string `customer` became `ctx.customer`'s unrelated value because injected items go through input-mapping resolution. A string without a matching context key remained unchanged. Preserve literal item identity separately from mapping expressions. Evidence: engine dynamic fan-out probe.

## Outcome and validation

Resolved on 2026-09-14. Internal typed flow entries now carry literal item and
index values separately from JSON flow configurations. Only user-authored
input mappings perform a single top-level parent-key lookup; runtime values
are then moved into the child context without reference resolution. No new
public configuration field or escaping convention is required.

Dynamic children still inherit only explicitly mapped inputs and their item
and index. Static children retain parent inheritance when `input` is omitted
and input isolation when it is an empty object. Runtime item and index values
override colliding authored fields; if both use the same key, the existing
index-last precedence is preserved. Engine-owned context handling, private
output filtering, redaction, IF-118 result metadata, and IF-116 result fidelity
and cancellation contracts remain unchanged.

Validation:

- Before the fix, the new five-test literal-input suite had three failures:
  matching-key strings became unrelated parent values, including the entire
  source array. The two existing static-mapping and index-precedence behaviors
  already passed.
- After the fix, 49 focused tests passed: two input-helper unit tests and 47
  integration tests covering literal JSON types, custom/private keys, serial
  and concurrent execution, ordinary mappings, CLI execution, conversion
  budgets, result metadata, live child values, nested cancellation, and the
  example catalog.
- The helper tests also verify that a large literal string moves into the
  child context without another allocation and that authored JSON cannot
  populate the internal literal-input field.
- Added and exercised `parallel_literal_inputs.lua` and its child example.
  Catalog validation loaded all 145 Lua examples.
- `cargo fmt --all -- --check`, `python3 -B scripts/check_module_size.py`,
  `cargo clippy --all-targets -- -D warnings`, and
  `cargo audit --deny warnings` passed on stable Rust 1.98.1. Existing module
  size exceptions are unchanged.

The runtime probes used isolated local workflows without external services.
Existing conversion limits still apply. This was a focused issue gate, not a
full release or deployed-server validation, and no changes were pushed.
