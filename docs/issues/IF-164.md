# IF-164 — Release binary carries 36 MB of embedded fonts and no release profile

## Evidence and boundary

Audit of `develop` at 1.20.1-dev.6 on 2026-10-28.

- A release build of `ironflow` for the `aarch64-apple-darwin` target on
  2026-10-28 is 106.5 MB.
- `Cargo.toml` has no `[profile.release]`: no `strip`, no LTO, default
  codegen units.
- `src/nodes/utility/markdown_document/pdf/fonts.rs` embeds six fonts with
  `include_bytes!`: NotoSansCJK.otf 29.3 MB, NotoSerif-Italic 2.3 MB,
  NotoSerif 1.8 MB, NotoSansMono 1.6 MB, NotoSansArabic 0.8 MB,
  NotoSansHebrew 0.1 MB; 36 MB in total, about a third of the binary, serving
  `markdown_to_pdf` only.
- `pdf-render = []` is a default feature with no dependency behind it and zero
  `cfg(feature = "pdf-render")` uses in `src/`; `pdfium-render` is
  unconditional. The feature name appears only in `Cargo.toml` and
  `scripts/tests/rust_targets.test.ts`.
- Only `postgres` and `redis` are optional. Document generation (parley,
  krilla, unicode-bidi, unicode-script), extraction (lopdf, pdfium-render,
  calamine, zip, quick-xml, html2md, ammonia), cloud (aws-sdk-s3,
  aws-sdk-s3vectors, aws-config), MCP (rmcp), email (lettre), image codecs and
  JSON Schema validation are always built: 73 direct dependencies, 571
  reachable crates.
- `tree-sitter` and `tree-sitter-lua` (a C grammar compiled at build time) are
  used only by `src/lua/analysis` to emit the `undefined_global` warning
  during validation.
- `README.md` and `docs/ARCHITECTURE.md` describe a "lightweight single
  binary".

Boundary: none of this is a correctness defect. It is size, build time and
positioning.

## Required outcome and acceptance

- Add `[profile.release]` with `strip = true`, `lto` (thin or fat) and
  `codegen-units = 1`. Keep `panic = "unwind"`: `src/engine/executor/coordinator.rs`
  relies on `catch_unwind`. Record before/after size for Linux musl and macOS.
- Move at least NotoSansCJK behind a Cargo feature or a runtime font directory
  (for example `IRONFLOW_FONT_DIR`) with a documented fallback and a clear
  error when CJK text is rendered without it. Update
  `docs/MARKDOWN_DOCUMENTS.md`, release packaging (`assets/fonts/OFL.txt`) and
  the Dockerfile.
- Make `pdf-render` real (gate `pdfium-render` and the `pdf_to_image` and
  `pdf_thumbnail` nodes) or delete it; update `rust_targets.test.ts`, the docs
  and `ironflow nodes` expectations.
- Evaluate optional features for document generation, extraction, cloud, MCP
  and email, with the release workflow's `-full` variant covering everything;
  evaluate making tree-sitter optional.
- Resolution evidence: measured binary sizes per target, `cargo tree -e features`
  showing the gated stacks, and example validation across feature sets.

## Outcome and validation

Resolved on 2026-10-28 on branch `fix/if-164-release-size` at 1.20.1-dev.8.

Outcome:

- `[profile.release]` sets `strip = true`, `lto = "fat"` and
  `codegen-units = 1`; `panic` stays at the default `unwind` because
  `src/engine/executor/coordinator.rs` relies on `catch_unwind`.
  `scripts/tests/cargo_features.test.ts` pins the profile and
  `ci_resources.test.ts` keeps dev and test profiles out of the manifest.
- `cjk-fonts` is a new Cargo feature, off by default. Only builds with it
  embed `NotoSansCJK.otf` (about 29 MiB); the `-full` release variants
  (`postgres,redis,cjk-fonts`), the container image (`ARG FEATURES`) and the
  CI feature job and local gate enable it. Every build loads additional fonts
  from `IRONFLOW_FONT_DIR`: each `.ttf`, `.otf` or `.ttc` file there (at most
  64 files of at most 64 MiB each, enforced before reading) is registered once
  per process after the bundled fonts and its families are appended to the
  fallback lists for the Han, Hiragana, Katakana and Hangul scripts, so a font
  under any family name serves CJK runs. Coverage is probed through the font's
  character map. An unreadable directory or an unusable file fails the first
  document with an error naming `IRONFLOW_FONT_DIR` and the path.
- `markdown_to_pdf` checks each paragraph before layout: CJK text with no
  CJK font registered fails with "the document contains CJK text but no CJK
  font is available; build IronFlow with the `cjk-fonts` feature or set
  IRONFLOW_FONT_DIR to a directory containing a CJK font", instead of the
  generic missing-glyph error, which now says "available fonts".
- `pdf-render` is real: `pdfium-render` is optional behind it, `pdf_to_image`
  and `pdf_thumbnail` (module, re-export and registration) and the two helpers
  only they use are `cfg`-gated, and the artifact streaming writer carries a
  scoped `allow(dead_code)` for builds without the feature. The feature stays
  in `default`, so default builds keep 105 nodes; `--no-default-features`
  drops the two nodes and the binding crate and compiles clean under Clippy.
- Documentation: `docs/MARKDOWN_DOCUMENTS.md`, `assets/fonts/README.md`,
  `docs/nodes/markdown_to_pdf.md`, `docs/nodes/pdf_to_image.md`,
  `docs/nodes/pdf_thumbnail.md` and `docs/CLI_REFERENCE.md` (feature list,
  release variants, `IRONFLOW_FONT_DIR` row) describe the feature set and the
  font directory.
- Feature evaluation (`cargo tree -e normal --prefix none --locked`, crates
  reachable from each root on 2026-10-28, out of 625 in the default graph;
  subtrees overlap heavily through tokio, hyper and serde): `aws-sdk-s3` 254,
  `jsonschema` 206, `aws-sdk-s3vectors` 203, `rmcp` 169, `lettre` 102,
  `calamine` 91, `lopdf` 79, `krilla` 75, `parley` 71, `pdfium-render` 62,
  `tree-sitter` 9 plus `tree-sitter-lua` 2. Without `pdf-render` the graph
  holds 617 crates. The cloud (S3 and S3 Vectors), MCP, email and JSON Schema
  stacks are the candidates with a unique-dependency payoff; document
  generation and extraction share most of their graph with the rest of the
  engine. Gating them changes the node set per build and therefore the
  documented 105-node contract, examples and `ironflow nodes` expectations; that
  is a follow-up decision, not part of this change. `tree-sitter` is small
  (11 crates, one C grammar at build time) and only feeds the
  `undefined_global` warning; making it optional saves little.

Contract boundary: default release binaries no longer render Chinese,
Japanese or Korean text in `markdown_to_pdf` unless `IRONFLOW_FONT_DIR`
supplies a CJK font; DOCX output is unaffected because it references family
names only. The `-full` binaries and the container image keep the bundled
font. Tests that render the multilingual fixture to PDF in-process are gated
on `cjk-fonts` and run in the feature job; the serve-backed CLI test passes
`IRONFLOW_FONT_DIR` to its child processes and runs everywhere. Node count,
Lua examples and the extraction round trip are unchanged.

Validation on 2026-10-28:

- Release size for the `aarch64-apple-darwin` target (`cargo build --release
  --locked`): 50,806,544 bytes (48.5 MiB) with default features, built in
  4 m 49 s including dependencies, and 81,783,088 bytes (78.0 MiB) with
  `cjk-fonts`, against 106.5 MB before this change. The stripped, link-time
  optimized profile accounts for roughly 28 MB of the reduction and the font
  feature for the remaining 29 MiB. The default binary lists 105 nodes. The
  Linux musl and Windows sizes come from the next release workflow run.
- Failing first: `scripts/tests/cargo_features.test.ts` (profile, optional
  `pdfium-render`, opt-in `cjk-fonts`, `-full` and container feature sets)
  failed on the old manifest and workflows; `tests/test_markdown_fonts.rs`
  showed CJK text rendering silently through the bundled font and an
  unreadable `IRONFLOW_FONT_DIR` going unreported; all pass after the change,
  with the feature-gated bundled-font case passing under `cjk-fonts`.
- `documents` binary: 114 tests under default features (the two in-process
  multilingual PDF renders are gated), 116 under `cjk-fonts`; the serve-backed
  CLI case renders the multilingual fixture through `IRONFLOW_FONT_DIR` in
  both. `serial`: 184 passed under default features with the gated render-node
  tests included.
- `cargo clippy --all-targets -- -D warnings` with default features, with
  `postgres,redis,cjk-fonts`, and with `--no-default-features` (the gated
  render nodes and the scoped artifact-writer allowance compile clean).
  `cargo fmt --all -- --check`, module-size policy and
  `bun test scripts/tests/*.test.ts` (90 pass) are green; `actionlint` covers
  the workflow edits.
- Not run here: the full suite under every feature combination beyond the
  binaries that changed, and the release workflow itself.
