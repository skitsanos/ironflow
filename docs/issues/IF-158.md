# IF-158 — Full integration tests retain every linked executable until the phase ends

## Evidence and boundary

On 2026-10-26, IF-156 integration qualification reached `cargo test --all-targets`
after passing policy checks, Cargo check and exact Clippy. The linker failed
building `test_zip_security` with errno 28, no space left on device. At the
observed near-full point, this checkout's debug target occupied about 26 GiB and
the volume had about 1.1 GiB free. The cleanup trap package-cleaned IronFlow's
generated artifacts and recovered about 20 GiB free, preserving dependency
caches and unrelated project data.

Cargo builds all selected test executables before running them. The unreleased
document-generation batch embeds fonts in registry-linked binaries, making the
aggregate retained executable set larger. Phase-boundary cleanup was therefore
insufficient on this machine even with debug info and incremental output off.
This is a confirmed local qualification failure, not evidence that a test failed
or that hosted CI lacks sufficient disk. No test was waived or treated as green.

## Required outcome and acceptance

- Run the full Cargo target set in bounded batches, including library, binary,
  integration, example and benchmark targets; preserve feature selection and
  test harness arguments. Fail rather than silently ignore unknown target kinds.
- Preserve default-feature closure and required-feature selection, and keep
  Cargo responsible for compiling/running tests and configuring their runtime.
- Reclaim only current-package, test-profile executables reported in Cargo build
  events, after success or failure. Keep normal CLI binaries and libraries for
  runtime/TLS probes. Reject paths outside the target tree and symlinked parents
  escaping it. Never trust test-harness stdout as build-artifact evidence.
- Keep source, dependencies, unrelated data and the existing outer cleanup trap.
- Prove cleanup and failure propagation with policy tests and a real full gate.

## Outcome and validation

`scripts/test_rust_targets.ts` discovers the single-package target set through
structured Cargo metadata and selects batches of eight. Each batch runs Cargo
test with the original feature/harness flags and structured build messages.
Only current-package test executables are removed, after the child exits; errors
stop the gate. The script forwards interruption signals to Cargo. The local
integration gate uses this runner for both default and PostgreSQL/Redis phases.
CI's Linux default/full-feature and macOS test jobs use the same runner with
pinned Bun setup before execution. Static policy and actionlint checks qualify
the wiring; it is not evidence that unpublished changes have run on hosted CI.

Six Bun regressions cover target-kind coverage, feature closure/arguments,
cleanup admission, symlink escape refusal, success/failure cleanup and rejection
of forged harness build events. These and the repository policy checks pass.
Full native integration requalification passed: all 178 Cargo targets in both
default and full-feature modes, doc tests, exact Clippy, audit, release build,
155 Lua examples and live PostgreSQL/Redis TLS checks. Roughly 20 GiB remained
free near the end of full-feature tests, and the outer cleanup trap reclaimed
its remaining package artifacts and removed the disposable containers. The final
67 Bun policy tests and workflow actionlint checks pass. Hosted execution of
the new CI wiring must be qualified separately against its exact commit. The
runner bounds retained linked test executables, not total compiler peak memory,
disk consumption by dependencies, or auxiliary platform debugging artifacts.
