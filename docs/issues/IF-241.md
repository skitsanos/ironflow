# IF-241 — Release archives and runtime image omit IronFlow’s own license

## Evidence and boundary

Reviewed 2026-11-19 on local `develop` at `ae1f686`.

The Unix and Windows packaging steps in `.github/workflows/release.yml:77` and `:82` include third-party notices and the font license but not the repository `LICENSE`. The runtime stage of `Dockerfile` likewise ships the notices but not the project license they reference. This finding concerns the packaging definitions, not an inspection of previously published assets or a legal assessment.

## Required outcome and acceptance

Package an unchanged copy of `LICENSE` in both archive formats and the image alongside the notices. Verify its presence and contents against the source in each output format; keep the existing third-party files.

## Outcome and validation

Both archive formats include `LICENSE` at the root. The runtime image installs it at `/usr/local/share/licenses/ironflow/LICENSE`, and license-only changes trigger a rebuild. The release and container workflows compare the packaged bytes with the repository file before upload or publication.

The tar.gz, PowerShell ZIP, and runtime-stage image each retained byte-identical copies of the project license, third-party notices, and font license.
