# IF-195 — date_format ignores input offsets; date_format and html_sanitize panics stall the run

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12, reproduced with a local
optimized build.

1. Wrong instant. `date_format({ input = "2024-06-15 10:30:00 +0200",
   input_format = "%Y-%m-%d %H:%M:%S %z" })` returns `10:30:00Z` and unix
   `1718447400`. The same instant given as RFC 3339
   (`2024-06-15T10:30:00+02:00`) returns `08:30:00Z` and `1718440200`. With
   an explicit `input_format`, the node parses through
   `NaiveDateTime::parse_from_str`, which accepts `%z` and discards it
   (`src/nodes/utility/date.rs:109-124`).
2. Panic on `output_format`. `output_format = "%Y-%m-%d %H:%i"` panics in
   chrono's formatter (`date.rs:136-143`). The run ends `stalled: execution
   failed: workflow execution panicked`, and the step's `on_error` handler
   does not run. Unknown specifiers and a trailing `%` behave the same.
3. Panic in `html_sanitize`. `allowed_tags = { "p", "style" }` panics inside
   ammonia (`` `style` appears in `clean_content_tags` and in `tags` ``),
   with the same stalled run (`src/nodes/utility/html_sanitize.rs:40-58`).
   `script` behaves the same by reading.

By reading: `allowed_tags = {}` converts to a JSON object, fails
`as_array()`, and falls back to ammonia's default allow-list instead of
stripping all tags. `docs/nodes/date_format.md` says `timezone` defaults to
UTC, but without it an RFC 3339 input keeps its own offset.

Boundary: items 2 and 3 are contained by the coordinator's panic handling,
so the process survives, but a bad node parameter becomes a run-level
infrastructure failure that bypasses retries and `on_error`. Format strings
and tag lists can come from interpolated context.

## Required outcome and acceptance

- When the input format carries an offset or zone specifier, parse with an
  offset-aware parser and convert; reject formats whose offset would be
  ignored.
- Validate `output_format` items before formatting and return a node error.
- Remove or reject `script` and `style` in `allowed_tags`; treat a present
  non-array value as an error and an empty list as "no tags".
- Regressions for each case, asserting a step failure that `on_error` can
  handle.
- Correct the `timezone` default wording.
