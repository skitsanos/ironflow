# IF-257 — Invalid timezone components are silently normalized to another offset

## Evidence and boundary

Reviewed 2026-11-19 on local `develop` at `ae1f686`.

`src/nodes/utility/date_input.rs:143` parses hours and minutes as independently signed integers, then checks only the combined offset. For example `+01:75` is accepted as 8100 seconds (`+02:15`), rather than rejected; `+01:-30` also passes. The `timezone` configuration contract in `docs/nodes/date_format.md` requires `+HH:MM` or `-HH:MM`. This concerns the output timezone parameter, independently of IF-238 input field reconciliation. Source inspection.

CLI confirmation: with UTC input `2026-01-01T00:00:00Z`, `timezone="+01:75"` returned success and formatted `2026-01-01 02:15:00 +02:15`.

## Required outcome and acceptance

Validate digits, component widths and minute range before converting. Test malformed minute values, embedded signs and invalid widths; keep UTC, Z, positive and negative half-hour offsets, and the documented less-than-a-day boundary.
