# IF-179 — Image nodes and transcribe write outputs through symlinks without the staged writer

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12.

- Reproduced with a local optimized build: `image_resize` with `output_path`
  pointing at a symlink succeeds, and the link's target (a text file) now
  holds PNG data. The same destination given to `write_file` fails with
  `destination leaf is a symlink and will not be followed` and leaves the
  target unchanged.
- By reading, the same plain write is shared by the other image writers:
  - `save_dynamic_image` (`src/nodes/image/common.rs:63-71`), used by resize,
    crop, rotate, flip, grayscale and watermark;
  - `image_convert` (`src/nodes/image/image_advanced/convert.rs:64, 78-79`);
  - `image_to_pdf` (`src/nodes/image/image_conversion/worker.rs:52`).
- `transcribe` writes `output_file` with `tokio::fs::write`
  (`src/nodes/ai/transcribe.rs:122-128`) after the provider call, outside the
  tracked worker. Its documented example derives the path from context.
- Consequences beyond symlinks, by reading: the destination is truncated in
  place, so an encoder failure (for example a float-pixel source saved as
  PNG) or a cancellation leaves a zero-length or partial file where the
  previous one was; a FIFO destination blocks the worker while it holds
  admission.

Boundary: `write_file`, `copy_file`, `base64_decode`, the archive nodes,
`pdf_merge`, grouped `pdf_split` and the Markdown document nodes already go
through `RootedDir::stage_file`. These are sibling paths that IF-139 and
IF-140 (both P1) did not cover. Only `image_resize` was executed.

## Required outcome and acceptance

- Route every listed output through the shared rooted, no-follow, atomic
  writer inside the tracked blocking step: encode into the staged file, then
  commit.
- Decide and document the output mode with IF-185.
- Regressions per node family: symlinked destination refused and target
  unchanged; encoder failure and cancellation leave an existing destination
  intact and no staging file; normal output unchanged.
- Update the affected node documents with the destination contract.
- Evidence: focused image, PDF-image and transcribe tests, plus the existing
  write-safety suites.

## Outcome and validation

Resolved on 2026-11-12 at 1.21.1-dev.2.

Outcome:

- `src/nodes/file/staged_output.rs` adds `publish`: it pins the existing
  destination directory with the new `RootedDir::existing`, stages a sibling
  file, hands the encoder a buffered writer that checkpoints on every write of
  at most 64 KiB, flushes, synchronizes, checkpoints once more and commits.
- Every listed output goes through it inside the tracked blocking step:
  `save_dynamic_image` (resize, crop, rotate, flip, grayscale, watermark),
  both branches of `image_convert`, `image_to_pdf`, and the `transcribe`
  `output_file`, which moved from `tokio::fs::write` into a tracked step after
  the provider call.
- The nodes no longer checkpoint after the commit, so a step cannot report a
  deadline failure for an output it already replaced.
- Docs: a destination contract in the eight image node documents and in
  `docs/nodes/transcribe.md`, one bullet in `docs/ARCHITECTURE.md`, a release
  note, and a comment in the nine affected Lua examples.

Behaviour measured on `develop` at 8d33145 before the change, unoptimized
build, macOS, umask 022, all eight image nodes and `transcribe`:

| Case | Before | After |
|---|---|---|
| Symlinked destination | followed, target overwritten | refused, target unchanged |
| Missing parent directory | error, nothing created | error, nothing created |
| Existing regular file | truncated and rewritten in place | replaced by rename |
| Encoder failure (float source to PNG) | destination left at 0 bytes | destination unchanged |
| FIFO destination (`image_resize`) | blocked until killed | refused at once |
| New file mode | `0644` | `0600` |
| Replaced `0640` file | stays `0640` | `0600` |
| Output bytes, 12 files | reference | identical |

Contract boundary:

- The output mode is the one kept behaviour that changed with this fix: it
  became the staged writer's `0600`. [IF-185](IF-185.md) restored it for the
  staged writer as a whole, so these nodes again publish the umask default
  for a new file and keep a replaced file's bits.
- Parent directories are not created, unlike `write_file`: these nodes never
  created them. The error text changed to `<node>: destination directory
  '<dir>' does not exist`.
- Replacement is a rename: the output is a new inode, other hard links keep
  the old content, and the destination directory must be writable.
- A cancellation that arrives after the final checkpoint still publishes.
- `image_watermark` and `image_to_pdf` have no encoder failure that can be
  constructed after the write began, and `transcribe` writes bytes verbatim;
  their failure coverage is cancellation or deadline only.
- Unix was built and run. The portable `RootedDir::existing` was written by
  reading and not compiled.
- Not covered, by reading only: single-page `pdf_split` still saves each page
  with a plain create (documented as its legacy mode), and the `cache` file
  backend writes with `std::fs::write`. Both are tracked in
  [IF-207](IF-207.md).

Validation on 2026-11-12:

- Failing first, on the unchanged code: 6 of 10 cases in
  `test_image_output_safety` and 3 of 5 in `test_transcribe_output_safety`
  failed. The symlink was followed, a failed encode and a cancelled step left
  an empty or replaced destination, the FIFO write waited, and `transcribe`
  wrote past its deadline. The other 6 cases describe kept behaviour (bytes,
  missing parent, replacement) and passed before and after.
- After: both suites pass (10 and 5). Cancellation is exercised by dropping
  the step once its staged file appears; 120 consecutive runs of the three
  cancellation cases, half under CPU load, passed without a retry.
- `staged_output` has 6 unit tests. Removing the pre-commit checkpoint, the
  per-write checkpoint or the error return each fails exactly one of them.
  `staged_save_writes_the_bytes_of_a_plain_lopdf_save` compares the PDF path
  with `Document::save`.
- The twelve outputs of a flow using every affected node have the same
  SHA-256 before and after. The eight image examples ran and all nine affected
  examples pass `validate --strict`.
- Focused targets: library 609, `documents` 136, `nodes` 247, `nodes_network`
  133, `examples` 11, `serial` 186 single-threaded.
- `cargo fmt --all -- --check`, the module-size gate and `cargo clippy
  --all-targets -- -D warnings` pass. The full integration gate was not run.
