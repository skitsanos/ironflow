# IF-179 — Image nodes and transcribe write outputs through symlinks without the staged writer

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12.

- Reproduced with a local optimized build: `image_resize` with `output_path`
  pointing at a symlink succeeds, and the link's target (a text file) now
  holds PNG data. The same destination given to `write_file` fails with
  `destination leaf is a symlink and will not be followed` and leaves the
  target unchanged.
- By reading, the same plain write is shared by the other image writers:
  - `save_dynamic_image` (`src/nodes/image/common.rs:63-71`), used by resize,
    crop, rotate, flip, grayscale and watermark;
  - `image_convert` (`src/nodes/image/image_advanced/convert.rs:64, 78-79`);
  - `image_to_pdf` (`src/nodes/image/image_conversion/worker.rs:52`).
- `transcribe` writes `output_file` with `tokio::fs::write`
  (`src/nodes/ai/transcribe.rs:122-128`) after the provider call, outside the
  tracked worker. Its documented example derives the path from context.
- Consequences beyond symlinks, by reading: the destination is truncated in
  place, so an encoder failure (for example a float-pixel source saved as
  PNG) or a cancellation leaves a zero-length or partial file where the
  previous one was; a FIFO destination blocks the worker while it holds
  admission.

Boundary: `write_file`, `copy_file`, `base64_decode`, the archive nodes,
`pdf_merge`, grouped `pdf_split` and the Markdown document nodes already go
through `RootedDir::stage_file`. These are sibling paths that IF-139 and
IF-140 (both P1) did not cover. Only `image_resize` was executed.

## Required outcome and acceptance

- Route every listed output through the shared rooted, no-follow, atomic
  writer inside the tracked blocking step: encode into the staged file, then
  commit.
- Decide and document the output mode with IF-185.
- Regressions per node family: symlinked destination refused and target
  unchanged; encoder failure and cancellation leave an existing destination
  intact and no staging file; normal output unchanged.
- Update the affected node documents with the destination contract.
- Evidence: focused image, PDF-image and transcribe tests, plus the existing
  write-safety suites.
