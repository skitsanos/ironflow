# IF-129 — Notification response bodies bypass HTTP body admission limits

## Required outcome and acceptance

- Read Slack and Resend response bodies through bounded streaming admission, including chunked responses and oversized Content-Length.
- Apply the documented HTTP byte ceiling without returning a successful partial body or masking cancellation.
- Compare notification nodes with the generic HTTP control under a small cap and cover within-limit success and provider failures.

## Evidence and cause

Fresh review on 2026-09-12, finding R24. See
[AUDIT_2026-09-12.md](./AUDIT_2026-09-12.md) for the reviewed candidate,
evidence boundaries, and complete finding-to-issue mapping.

[Source: notify/slack.rs:100](../../src/nodes/notify/slack.rs), [Resend: resend.rs:52](../../src/nodes/notify/email/resend.rs).

These nodes collect `response.text()` without a byte bound. Under a 1024-byte configured HTTP body ceiling, the generic HTTP control correctly failed but both notification nodes retained a 4096-byte response. A timeout alone does not bound a fast response's memory consumption. Apply bounded streaming reads and test declared and chunked bodies. Evidence: API probe log.

## Progress

Open. Implementation and regression validation are pending.
