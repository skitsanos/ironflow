# IF-229 — extract_pptx approximates bullets inherited from the layout and master

## Evidence and boundary

Recorded on 2026-11-16 from the IF-222 sample run. The limitation is
documented on the node page; this page tracks removing it.

IF-222 made list detection follow the declared bullet: `a:buChar`,
`a:buAutoNum` or `a:buBlip` in the paragraph's `a:pPr` or in the shape's
own `a:lstStyle`. Slide layouts, slide masters and the presentation's
default text style are not read. A placeholder paragraph that declares
nothing is therefore guessed from `lvl`: a list item when the attribute is
present and plain when it is absent.

By reading, both directions can be wrong:

- a body placeholder whose first-level paragraphs carry no `lvl` and are
  bulleted by the layout or master is returned as plain text;
- a placeholder whose layout sets `a:buNone` for a level is returned as a
  list item when the paragraph carries `lvl`.

On the sample deck the output agreed with the slide XML for all 569 list
items, but that comparison used the same rule, so it does not measure the
error for placeholders.

## Required outcome and acceptance

Resolve a placeholder paragraph's bullet through the chain PowerPoint uses:
paragraph, shape list style, the matching placeholder on the slide layout,
the matching placeholder on the slide master, the master's `p:txStyles`
(title, body, other), then the presentation default. Follow the layout and
master through relationships, parse each part once per call, and charge the
work to the existing budgets.

Acceptance: hand-built regressions, failing first, for a bullet inherited
from the layout, one from the master text styles, and `a:buNone` on a
layout level; text boxes and drawn shapes unchanged; the node page and an
upgrade note updated, since `list_level` and Markdown markers change for
existing decks.
