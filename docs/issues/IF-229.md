# IF-229 — extract_pptx approximated bullets inherited from the layout and master

## Evidence and boundary

Recorded on 2026-11-16 from the IF-222 sample run. The limitation was
documented on the node page; this page tracked removing it.

IF-222 made list detection follow the declared bullet: `a:buChar`,
`a:buAutoNum` or `a:buBlip` in the paragraph's `a:pPr` or in the shape's
own `a:lstStyle`. Slide layouts, slide masters and the presentation's
default text style are not read. A placeholder paragraph that declares
nothing is therefore guessed from `lvl`: a list item when the attribute is
present and plain when it is absent.

By reading, both directions can be wrong:

- a body placeholder whose first-level paragraphs carry no `lvl` and are
  bulleted by the layout or master is returned as plain text;
- a placeholder whose layout sets `a:buNone` for a level is returned as a
  list item when the paragraph carries `lvl`.

On the sample deck the output agreed with the slide XML for all 569 list
items, but that comparison used the same rule, so it does not measure the
error for placeholders.

## Outcome and validation

A placeholder paragraph that declares nothing now takes the first
declaration for its level from the layout placeholder (same `idx`, else the
first of the same type), the master placeholder of the same role, and the
master's `p:txStyles` (title, body, other). A level nothing declares is
plain. The parts are followed through the `slideLayout` and `slideMaster`
relationships, read once per call and charged to the existing budgets.

Contract boundary:

- Text boxes and drawn shapes inherit nothing, as before. The
  presentation's `p:defaultTextStyle` is not read.
- A slide without a single internal layout relationship, or whose layout or
  master part is absent, keeps the `lvl` approximation and does not fail.
- Malformed XML in a layout or master now fails the step.
- Numbering, bullet characters and theme-level styles are not resolved.

Regressions, failing first: `tests/test_pptx_inherited_bullets.rs`, five
tests on hand-built decks (master text styles; `a:buNone` on a layout
level; nearest declaration wins; matching by `idx` then type; text boxes
and decks without layout or master unchanged). Four failed before the
change and the fifth pins the unchanged cases.

Checked against real files with an independent script that resolves the
same chain from the package XML:

- The committed pandoc deck: its two bullets resolve through its layout
  and master, and the expected Markdown of `test_tool_authored_documents`
  is unchanged.
- The private PowerPoint 16 deck of the IF-222 run, read in place: 86
  slides, 569 list items before and after, no slide differing. Its 60
  placeholder paragraphs that reach the chain all resolve to plain, so this
  deck confirms no regression but does not show an inherited bullet from
  PowerPoint itself.

Validation, default features: `documents` 223 passed (3 ignored),
`examples` 11, the 38 extraction tests of `serial`, 115 extraction unit
tests, formatting, the module-size check and
`cargo clippy --all-targets -- -D warnings`. Not run: the integration gate
and feature-enabled suites.
