# IF-239 — Integration gate receipt can identify a different tree from the one tested

## Evidence and boundary

Reviewed 2026-11-19 on local `develop` at `ae1f686`.

`scripts/integration_gate.sh:148` calls the receipt writer only after validation. `scripts/gate_receipt.ts` checks cleanliness and resolves the tree at write time, without an initial tree to compare. If a parallel development task commits a change after the relevant check has finished, the ending tree is clean but the receipt may certify code that check never ran on. Static finding; distinct from IF-172 receipt expiry and IF-205 hook environment handling.

## Required outcome and acceptance

Bind validation to a clean, known input tree. Prefer validating an isolated snapshot; at minimum capture the starting tree and refuse a receipt if the end tree differs or is dirty. Cover a commit during validation, an unchanged tree, and the intended message-only amend behavior.
