# IF-174 — HTML-to-Markdown conversion overflows the stack on nested markup and aborts the process

## Evidence and boundary

Review of `develop` at 1.21.1-dev.1 on 2026-11-12, reproduced with a local
optimized build.

- `extract_html` with `format = "markdown"` on a file of 2,500 nested `<div>`
  elements (27.5 KB) ends with `thread 'tokio-rt-worker' has overflowed its
  stack` and exit status 134. 1,000 levels succeed; 5,000 to 100,000 abort.
- `html_to_markdown` aborts the same way on `string.rep("<div>", 5000)` (the
  smallest size tried).
- Both call `htmd` 0.5.6 (`src/nodes/extract/html/content.rs:35`,
  `src/nodes/utility/markdown.rs:74-82`). Its `dom_walker` recurses
  `walk_node` to `walk_children` once per nesting level with no depth limit,
  and html5ever does not cap nesting. The only structural bound is
  `IRONFLOW_MAX_EXTRACT_ITEMS` (250,000 markup items), which counts elements,
  not depth, and `html_to_markdown` has no item budget at all.
- A stack overflow is an abort, not a panic. The coordinator's panic handling
  cannot contain it, so `ironflow serve` exits and every in-flight run is
  left for lease reconciliation.
- `extract_html` text mode is unaffected: its traversal is iterative.

Boundary: same class as IF-037 (XML/YAML depth), which did not cover the HTML
path introduced with `htmd` in IF-161. The exact threshold depends on build
and stack size; only the sizes above were measured.

## Required outcome and acceptance

- Measure DOM depth iteratively after parsing and reject documents above a
  fixed cap (IF-037 uses 128) before `tree_to_markdown`, in both nodes, as an
  ordinary node error.
- Give `html_to_markdown` the same input and item admission as
  `extract_html`, and run its conversion on the tracked blocking bridge.
- Regressions: nesting at the cap succeeds, one level above fails with a node
  error, and a 100,000-level document fails without terminating the test
  process, for both nodes.
- Update `docs/nodes/extract_html.md`, `docs/nodes/html_to_markdown.md` and
  the limits table in `docs/CLI_REFERENCE.md`.

## Outcome and validation

Resolved on 2026-11-12 at 1.21.1-dev.1.

Outcome:

- `src/nodes/extract/html/tree.rs` now parses for both nodes. It feeds
  html5ever in 4 KiB pieces with a cancellation check between them, stops
  once an open element is more than 256 levels deep, then measures the
  finished tree iteratively and rejects element depth above 128 with
  `<node>: HTML element nesting exceeds 128 levels`.
- Found while fixing: parse time is quadratic in nesting depth. An optimized
  build spent about 16 s parsing 100,000 nested `<div>` (1.1 MB) with no
  cancellation point, so a check only after parsing was not enough.
  `html5ever` 0.38, already present through `htmd`, became a direct
  dependency; the lockfile gained no package.
- `html_to_markdown` runs on the tracked blocking bridge, rejects input above
  `IRONFLOW_MAX_FILE_BYTES`, and charges `<` markers against
  `IRONFLOW_MAX_EXTRACT_ITEMS`. Its converter configuration is unchanged.
- Docs: both node pages and the `IRONFLOW_MAX_FILE_BYTES` and
  `IRONFLOW_MAX_EXTRACT_ITEMS` rows of `docs/CLI_REFERENCE.md`.

Contract boundary:

- The cap is fixed and counts the implied `<html>` and `<body>`, so a
  fragment may nest 126 elements. An unoptimized build overflowed a 2 MiB
  stack between 482 (tables) and 628 (`div`) levels.
- Only Markdown conversion is capped. `extract_html` text output accepts
  deeper markup as before; its parse is still quadratic, but now observes
  cancellation and the deadline. Tracked in [IF-207](IF-207.md).
- `html_to_markdown` output is not charged against the extract output limit.
  At the cap, wide content grew 63 times in one measurement (323 KB in, 20 MB
  out).
- `html5ever` must stay on `htmd`'s release line, as `markup5ever_rcdom`
  already must.

Validation on 2026-11-12:

- Failing first, unoptimized test build: both cap tests failed with `127
  nested levels must be rejected`; the 2,500-level `extract_html` and
  5,000-level `html_to_markdown` cases aborted the test binary with `has
  overflowed its stack`; the 100,000-level case ran for over a minute and
  aborted the same way; the deadline test and both admission tests failed.
- After: `test_html_depth_limit` 8 passed in 0.06 s,
  `test_html_to_markdown_admission` 2 passed, and the six
  `nodes::extract::html` unit tests passed, including chunked against
  one-shot parsing across chunk boundaries.
- Focused targets: library 577, `documents` 122, `serial` 186
  (single-threaded), `extract_execution` 2, `examples` 11.
- `cargo fmt --all -- --check`, the module-size gate and `cargo clippy
  --all-targets -- -D warnings` pass. The license gate passes with 577
  packages. `cargo audit` fails only on the three IF-173 advisories, as it
  does on the unmodified tree.
